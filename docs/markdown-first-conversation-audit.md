# Markdown-first 对话交互审计

> 2026-08-30 口径更新：所有用户任务共用本协议；资产 AI 中需要连续修改的推荐报告也复用同一 Markdown 对话和文件预览组件，但不进入任务列表。

## 一、目标

业务主线、新建工作和独立支线任务的普通 Agent 输出统一使用真正的动态 Markdown 渲染，避免为不同业务结果持续新增专用前端组件。正式业务动作继续使用 Hunter 受控组件，不能让 Markdown 承担写入、授权或批量操作。

## 二、统一渲染边界

| 内容                                       | 渲染方式                     | 原因                                              |
| ------------------------------------------ | ---------------------------- | ------------------------------------------------- |
| 分析、解释、证据摘要、风险、建议、阶段总结 | 动态 Markdown                | 内容长度和结构不固定，缺少某一段时不影响其他内容  |
| 少量结果、比较结果和统计                   | Markdown 列表或表格          | 不需要为每种业务结果建立专用卡片                  |
| 大量候选人、联系人、人物关系和岗位匹配结果 | Markdown 摘要 + 通用审核入口 | 需要分页、选择、详情和正式写入，不能只用 Markdown |
| 授权、确认和互斥选择                       | `DecisionRequest`            | 需要稳定对象、动作、权限、禁用和防重复提交        |
| 执行计划和相关任务                         | `RuntimeBar`                 | 状态由 Hunter 维护，不能由 Agent 文本自行声明     |
| 外部回复等待                               | `ExternalWaitState`          | 需要稳定的等待对象、时间和恢复入口                |
| 加载、错误、权限受限、暂停和恢复           | Hunter 状态组件              | 需要可操作状态和明确恢复行为                      |
| 正式业务资产列表与详情                     | 独立业务页面                 | 数据已经进入系统，不属于 Agent 对话输出           |

## 三、现有内容迁移结论

| 现有内容                                   | 调整                                              | 结果                             |
| ------------------------------------------ | ------------------------------------------------- | -------------------------------- |
| 岗位边界证据表、客户招聘信号证据表         | 表格正文改为 Markdown，保留统一“查看完整证据”入口 | 不再依赖场景专用表格组件         |
| 联系人、候选人、人物关系和岗位匹配数量摘要 | 改为 Markdown 表格                                | 字段缺失或分类变化时仍可完整展示 |
| 招聘机会摘要卡片                           | 改为 Markdown 标题、段落和表格                    | 不要求 Agent 生成固定卡片结构    |
| 人才摸排目标、公司组织、人物关系结果       | 改为 Markdown 表格、列表和引用                    | 支持分批结果和缺失区块           |
| 候选人新资料影响、岗位无结果原因           | 改为 Markdown 表格和引用                          | 变化数量不固定时不破坏布局       |
| 新建工作分类说明与支线任务判断             | 改为动态 Markdown                                 | 不因工作类型增加新的对话布局     |
| 审核入口                                   | 保留通用操作行                                    | 大型结果仍在当前工作区完成审核   |
| 授权、等待、计划、错误恢复                 | 保留受控组件                                      | 继续由 Hunter 管理真实状态和动作 |

## 四、数据不足和异常规则

1. Markdown 只渲染实际存在的段落和表格，不为缺失数据生成空字段。
2. 少量只读结果可以直接降级为 Markdown；未知内容不允许注入 HTML。
3. 需要正式写入、批量选择或对外操作的结果必须满足对应受控组件的数据契约；不满足时要求 Agent 修正或显示可理解的错误，不能改用 Markdown 放行。
4. 表格在移动端使用容器内滚动或业务对应的移动布局，不能造成页面横向溢出。
5. Markdown 链接只承担查看和导航，不承担写入、授权、删除或发送等有副作用的操作。

## 五、验收范围

1. 四类业务主线从首条回复到完成状态的普通输出均由动态 Markdown 渲染。
2. 新建工作和独立支线任务的普通输出均由同一组件渲染。
3. 授权、计划、外部等待、审核和错误恢复的既有流程没有回归。
4. 覆盖标题、段落、有序与无序列表、引用、表格、链接、强调、行内代码、代码块和分隔线。
5. 覆盖桌面与移动端、流式输出、缺失结果、错误和权限受限状态。
