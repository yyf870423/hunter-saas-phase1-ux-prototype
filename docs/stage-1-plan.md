> 2026-08-30 口径更新：导航和工作台统一使用“任务”，不再区分业务主线与支线任务。本文保留旧名称的 Review 记录仅用于追溯设计演进，当前产品边界以 `docs/unified-task-model.md` 为准。

## 一、阶段边界

本阶段只完成全局框架、工作台、基础公共组件和桌面/移动端响应式结构，不制作业务主线工作区、支线任务列表、信号中心完整页面、业务资产页面或运营端。

本阶段需要验证：

1. 用户能否从全局框架理解 Hunter 的模块结构。
2. 工作台能否按处理优先级查看任务类型、名称、进度和状态，并同时扫读洞察与资产变化；不再放大某一条任务。
3. 搜索、通知、账号、用量、主题、导航收起和移动导航是否具备稳定入口。
4. 公共组件和设计 Token 是否足以支撑后续页面，不使用浏览器默认控件。
5. 桌面、iPhone 和 iPad 是否能完成相同的工作台查看与轻量操作。

## 三、全局框架

### 3.1 桌面与 iPad

1. 左侧导航默认收起为 `64px`，只保留 Hunter 标识和 SVG 图标。
2. 展开后为 `224px`，常驻工作台、任务、洞察中心；2026-09-07 起资产区默认平铺公司、岗位、招聘机会、候选人和知识图谱，显隐可在设置中配置。
3. 未平铺资产进入“其他”，使用从侧栏右侧展开的公共浮层选择；不再先打开全资产侧向面板。“数据管理”入口增加同级“数据工具”分组标题。保持资产独立路由，联系人仅从公司进入。全部显示、全部隐藏与移动行为见 `asset-navigation-preferences.md`。
4. Agent 用量放入用户右拉菜单，仅显示已用百分比与到期日期；取消侧栏独立用量环。设置继续放入用户菜单，不占主导航。知识图谱子导航及密度规格见 `graph-types-navigation-prototype.md`。
5. 顶栏保留全局搜索、创建入口、主题、通知和账号；不重复显示大标题或营销信息。
6. 内容区不使用装饰性悬浮页面卡片，工作台各区域按业务层级组织。

### 3.2 iPhone

1. 顶部显示 Hunter 标识、搜索和通知。
2. 底部固定五个入口：工作台、任务、洞察、业务资产、更多。
3. 业务资产和更多沿用底部导航层；资产第一层显示配置的常用项和“其他”，其他中展示未平铺项，可返回第一层。两端共用一份配置。
4. 页面内容使用单列重组，不出现页面级横向滚动。

## 四、工作台信息布局

### 4.1 页面头部

保留日期与问候语，下方提供紧凑的自然语言新任务入口，不再显示描述产品能力的大块引导。

### 4.2 按处理优先级排列任务

上方全宽公共表格显示任务类型、名称、进度和状态，默认 5 条、最多 10 条。不保留焦点切换或放大的单任务摘要。按最新工作台反馈，进度显示“已完成 X / Y 步”与当前计划步骤，不再使用业务对象数量；计划未生成时明确显示待生成状态。点击名称直接进入对应任务，任务详情不重新设计。

任务按待你处理、待你验收、正在推进排序，等待外部放在末尾且保留状态。同优先级保持输入顺序，先排序再截取数量；状态列直接表达关注状态，任务置顶和完成比例不覆盖处理优先级。

### 4.3 洞察与资产变化

1. 桌面端下方双栏顶部对齐，内容区不足 900px 时按洞察、资产变化纵向排列；只使用全页滚动，不增加区域内部滚动。
2. 洞察使用连续摘要行，显示 8 条，保留类型、标题、状态、来源数、时间及下一步。
3. 资产变化显示 10 条，保留资产类型、名称、变化摘要和时间，并直接进入现有资产详情；联系人进入所属公司的子资产详情。
4. 两类区域均最多显示 10 条，不填充空白行。任务和洞察保留全量模块入口；资产变化没有独立全量页，不伪造“全部变化”入口。
5. 三个区域共享中性标题带、语义图标和上下边界；任务到动态区留白 40px，双栏留白 48px 并设置中线，窄屏单列间距 24px。动态名称优先于类型和时间，行内增加留白，不使用浮动卡片或内部滚动。

### 4.4 空状态与失败状态

全局空状态保留新任务输入和三个零数量区域，任务提供新建入口、资产提供导入入口，不渲染示例记录或行动队列。某一区域单独为空时，其余区域保留原数据。加载、洞察局部错误重试、来源受限及输入禁用使用公共组件。完整入口见 `dashboard-layout-prototype.md`。

### 4.5 行动队列

行动队列默认收起为一条摘要，说明待确认、待补充、外部新回复和异常数量。展开后只显示明确需要人工处理的事项；处理动作回到唯一来源，不在工作台建立第二套完成状态。

## 六、公共组件与设计 Token

### 6.1 Token

- 字体：`Inter`、`PingFang SC`、`Microsoft YaHei`。
- 正文默认 `14px`，辅助文字不低于 `12px`，紧凑标签保持单行。
- 主蓝：`#0070F7`，页面背景：`#FAFAFA`，深色背景：`#000000`。
- 圆角以 `6px`、`8px`、`12px` 为主；不使用大面积胶囊卡片。
- 阴影只用于浮层、下拉和当前焦点，不把页面区块全部做成悬浮卡片。

### 6.2 组件

本阶段沉淀：应用导航、平铺资产与其他导航、移动底部导航、顶栏、按钮、图标按钮、搜索输入、状态标签、业务摘要行、Modal、Drawer、Toast、Tabs、空状态、错误状态、骨架屏和用量摘要。

所有图标由原型 SVG 组件提供，不使用 Icon Font、Emoji 或浏览器默认图标。

## 七、关键交互

1. 导航收起、展开并记忆状态。
2. 桌面常用资产直接进入；其他浮层支持打开、选择后关闭、点击外部或 `Escape` 关闭，只展示未平铺项。显隐配置、恢复默认与持久化覆盖见 `asset-navigation-preferences.md`。
3. 全局搜索支持输入、分组结果、无结果、关闭后恢复工作台位置。
4. 通知支持全部/未读切换、单条已读和全部已读。
5. 顶栏将“导入数据”与“新建工作”作为两个独立四字入口；“新建工作”菜单只承载统一自然语言入口和手动新建资产提示，数据导入统一进入全局导入任务。
6. 主题切换在亮色与深色间即时变化并记忆。
7. 五项任务平等展示，直接进入对应详情；下方 8 条洞察和 10 条资产变化均有有效去向。
8. 行动队列可展开、收起；点击事项只进入其唯一来源入口。
9. 移动端业务资产和更多导航层可打开、关闭并保持返回位置。
10. Modal、Drawer 和菜单支持点击遮罩、关闭按钮和 `Escape`；提交中状态禁止重复操作。

## 八、审批门禁

1. 不突出单个任务；四个任务字段可对齐比较，下方洞察和资产变化双栏顶部对齐，移动端保留全部信息。
2. 任何标签、状态和操作文字均不换行或超出边界。
3. 1440×900、820×1180、390×844 三个视口没有页面级横向溢出。
4. 默认亮色、深色模式、正常、加载、空、错误和权限受限状态均可访问。
5. 所有可见按钮都有实际反馈，所有浮层可以正常关闭。
6. Playwright E2E、控制台错误检查、截图和原型自我 Review 全部通过。
7. 完成后只提交阶段一给人类审批，未通过前不进入自动化通用交互框架。
