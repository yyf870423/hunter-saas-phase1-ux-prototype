# 原型阶段一：全局框架与工作台实施计划

> 状态：已通过人类审批并冻结。
>
> 日期：2026-08-19。
>
> 设计语言：WorkBuddy × Vercel，默认亮色、冷色蓝系、紧凑但不压迫，警告和风险才使用暖色。

## 一、阶段边界

本阶段只完成全局框架、工作台、基础公共组件和桌面/移动端响应式结构，不制作业务主线工作区、支线任务列表、信号中心完整页面、业务资产页面或运营端。

本阶段需要验证：

1. 用户能否从全局框架理解 Hunter 的模块结构。
2. 工作台能否明确表达“业务主线最重要、支线任务其次、重点信号再次、行动队列最后”的优先关系。
3. 搜索、通知、账号、用量、主题、导航收起和移动导航是否具备稳定入口。
4. 公共组件和设计 Token 是否足以支撑后续页面，不使用浏览器默认控件。
5. 桌面、iPhone 和 iPad 是否能完成相同的工作台查看与轻量操作。

## 三、全局框架

### 3.1 桌面与 iPad

1. 左侧导航默认收起为 `64px`，只保留 Hunter 标识和 SVG 图标。
2. 展开后为 `224px`，常驻显示四个核心工作入口和一个“业务资产”入口；不在侧栏堆叠八类资产，也不要求用户滚动导航。
3. 点击“业务资产”后打开侧向资产面板，按招聘资产、人才资产和研究资产分组，并直接进入对应资产；该面板不是资产中心页面，也不改变资产的独立路由。
4. Agent 用量固定在侧栏底部并使用环形图，展开时补充文字说明；设置放入用户展开菜单，不再单独占用侧栏入口。
5. 顶栏保留全局搜索、创建入口、主题、通知和账号；不重复显示大标题或营销信息。
6. 内容区不使用装饰性悬浮页面卡片，工作台各区域按业务层级组织。

### 3.2 iPhone

1. 顶部显示 Hunter 标识、搜索和通知。
2. 底部固定五个入口：工作台、业务主线、支线任务、业务资产、更多。
3. 业务资产和更多使用全屏导航层，不把桌面长导航压缩到手机。
4. 页面内容使用单列重组，不出现页面级横向滚动。

## 四、工作台信息布局

### 4.1 页面头部

显示日期、问候语和“新建业务主线”主操作。文案不使用“首先处理、其次查看”等教学式表达。

### 4.2 业务主线焦点

首屏最醒目的区域只展示一条当前最需要用户继续的业务主线：

- `星澜机器人招聘合作`，类型为客户开发。
- 已核验 2 个招聘信号，形成 3 位联系人草稿，其中 2 位有可用联系方式。
- 当前等待用户选择优先联系对象，不复制联系人完整审核数据。
- 同一区域使用紧凑行展示另外 3 条活跃主线，不做第二个完整列表。

点击焦点或其他主线只验证导航意图和来源状态保留，完整主线工作区在原型阶段二制作。

### 4.3 支线任务与重点信号

桌面端左右并列，移动端按业务优先级纵向排列：

1. 支线任务使用紧凑任务行，展示任务目标、状态、关联对象、当前进度或阻塞原因，只显示 3 条需要关注的任务。
2. 重点信号使用连续信号流，展示对象、变化、强度、证据数量和发现时间，只显示 3 条值得处理的信号。
3. 两个区域均提供进入完整模块的入口，但不复制全量列表、筛选器和详情。

### 4.4 行动队列

行动队列默认收起为一条摘要，说明待确认、待补充、外部新回复和异常数量。展开后只显示明确需要人工处理的事项；处理动作回到唯一来源，不在工作台建立第二套完成状态。

## 六、公共组件与设计 Token

### 6.1 Token

- 字体：`Inter`、`PingFang SC`、`Microsoft YaHei`。
- 正文默认 `14px`，辅助文字不低于 `12px`，紧凑标签保持单行。
- 主蓝：`#0070F7`，页面背景：`#FAFAFA`，深色背景：`#000000`。
- 圆角以 `6px`、`8px`、`12px` 为主；不使用大面积胶囊卡片。
- 阴影只用于浮层、下拉和当前焦点，不把页面区块全部做成悬浮卡片。

### 6.2 组件

本阶段沉淀：应用导航、业务资产侧向导航、移动底部导航、顶栏、按钮、图标按钮、搜索输入、状态标签、业务摘要行、Modal、Drawer、Toast、Tabs、空状态、错误状态、骨架屏和用量环形图。

所有图标由原型 SVG 组件提供，不使用 Icon Font、Emoji 或浏览器默认图标。

## 七、关键交互

1. 导航收起、展开并记忆状态。
2. 桌面业务资产侧向面板支持打开、关闭、点击外部或 `Escape` 关闭，并可直接选择八类资产。
3. 全局搜索支持输入、分组结果、无结果、关闭后恢复工作台位置。
4. 通知支持全部/未读切换、单条已读和全部已读。
5. 创建菜单支持新建业务主线、导入数据和手动新建资产入口提示。
6. 主题切换在亮色与深色间即时变化并记忆。
7. 业务主线焦点和紧凑行可切换当前焦点，不跳动页面布局。
8. 行动队列可展开、收起；点击事项只进入其唯一来源入口。
9. 移动端业务资产和更多导航层可打开、关闭并保持返回位置。
10. Modal、Drawer 和菜单支持点击遮罩、关闭按钮和 `Escape`；提交中状态禁止重复操作。

## 八、审批门禁

1. 首屏不会同时出现四组等权列表，业务主线具有明确视觉优先级。
2. 任何标签、状态和操作文字均不换行或超出边界。
3. 1440×900、820×1180、390×844 三个视口没有页面级横向溢出。
4. 默认亮色、深色模式、正常、加载、空、错误和权限受限状态均可访问。
5. 所有可见按钮都有实际反馈，所有浮层可以正常关闭。
6. Playwright E2E、控制台错误检查、截图和原型自我 Review 全部通过。
7. 完成后只提交阶段一给人类审批，未通过前不进入自动化通用交互框架。
