# 资产内 AI 处理原型

## 目的

用岗位 AI 解析、候选人信息补全和已有公司调研更新验证三层对象关系：

1. **工作**承载独立业务目标，例如围绕岗位持续找人。
2. **AI 处理**承载单一资产上的明确操作，例如解析岗位、补全候选人、更新公司调研和重新计算匹配结果。
3. **运行记录**承载一次 AI 处理的执行、重试和失败诊断。

用户不需要选择类型。系统根据发起位置和目标范围自动归类。

## 归类边界

| 功能                                     | 产品归类       | 原因                                               |
| ---------------------------------------- | -------------- | -------------------------------------------------- |
| 岗位 AI 解析                             | 资产内 AI 处理 | 更新一个已有岗位，结果是字段建议                   |
| 候选人信息补全                           | 资产内 AI 处理 | 更新一个已有候选人，结果是字段建议和待确认身份关联 |
| 已有公司调研更新                         | 资产内 AI 处理 | 更新一个已有公司，不产生新的客户开发目标           |
| 候选人或岗位重新匹配                     | 资产内 AI 处理 | 更新资产之间的匹配结果，不产生独立业务目标         |
| 新建公司时的公开调研                     | 资产创建流程   | 结果是一个尚不存在的新资产，需要先确认草稿         |
| 生成推荐报告                             | 支线任务       | 会形成可持续修改、下载和交付的独立文件             |
| 岗位招聘、客户开发、人才摸排、候选人求职 | 工作           | 有持续目标、计划、分支任务和跨资产推进             |
| 学术搜索                                 | 工作           | 搜索范围、筛选、审核和导入构成完整目标             |

## 统一页面与交互

| 场景           | 页面表现                                                                             | 数据归属                   |
| -------------- | ------------------------------------------------------------------------------------ | -------------------------- |
| 从资产详情发起 | 在当前资产详情打开输入或范围配置，不离开资产                                         | 当前资产                   |
| 运行中         | 资产资料顶部显示运行状态；全局顶部只显示紧凑运行入口                                 | 当前资产的 AI 处理         |
| 查看处理详情   | 右侧抽屉显示处理对象、来源、可选所属工作、执行计划和运行记录                         | AI 处理与运行记录          |
| 结果待审核     | 打开全宽横向审核工作区；左侧选择字段，中间看 AI 建议，右侧看当前内容、修改依据和来源 | 当前资产待审核变更         |
| 处理失败       | 保留失败原因、已完成步骤与原输入，允许在原资产上重试                                 | 当前资产的 AI 处理         |
| 查看处理历史   | 在资产详情的关联信息或相关工作中查看，不与目标级工作混排                             | AI 处理与运行记录          |
| 查看工作列表   | 资产内 AI 处理不进入工作列表                                                         | 只展示有独立业务目标的工作 |

字段审核统一使用同一套组件和交互：

1. 字段目录只负责切换审核对象和选择需要写入的建议，不显示重复的“应用 / 保留”文字。
2. 桌面端同时显示 AI 建议和当前内容；平板与手机端通过“AI 建议 / 当前内容”切换。
3. 用户可以稍后处理；未选择的建议继续保留在 AI 处理记录中。
4. 只有用户确认的字段写入正式资产，并形成新的资料版本。

## 状态入口

### 岗位 AI 解析

- 启动配置：`/positions/position-vla?tab=profile&ai=setup`
- 运行中：`/positions/position-vla?tab=profile&ai=running`
- 字段审核：`/positions/position-vla?tab=profile&ai=review&panel=review`
- 失败：`/positions/position-vla?tab=profile&ai=failed`
- 处理记录：`/positions/position-vla?tab=work`

## 验收标准

1. 岗位解析、候选人信息补全和已有公司调研更新不会创建工作，也不进入工作列表。
2. 运行中、待审核和失败状态能从全局紧凑入口返回对应资产。
3. 用户能从资产详情查看执行计划和每次运行记录。
4. 用户确认前，AI 建议不改变正式资产；确认后形成新的资料版本。
5. 与资产有关的目标级工作仍能从“相关工作”进入，且不与 AI 处理记录混排。
6. 新建资产、推荐报告和目标级工作保持原有产品归类，不因本次统一而改变。
7. 桌面端和移动端均无横向溢出，Modal、Drawer 和字段审核使用公共组件。
