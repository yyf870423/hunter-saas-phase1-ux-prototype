# 资产 AI 处理原型：岗位 AI 解析

## 目的

用“岗位 AI 解析”验证三层对象关系：

1. **工作**承载独立业务目标，例如围绕岗位持续找人。
2. **AI 处理**承载单一资产上的明确操作，例如解析岗位、更新匹配结果。
3. **运行记录**承载一次 AI 处理的执行、重试和失败诊断。

用户不需要选择类型。系统根据发起位置和目标范围自动归类。

## 页面与交互

| 场景                    | 页面表现                                                 | 数据归属             |
| ----------------------- | -------------------------------------------------------- | -------------------- |
| 从岗位详情点击“AI 解析” | 打开当前岗位的解析配置，不离开岗位详情                   | 当前岗位             |
| 解析运行中              | 岗位资料顶部显示运行状态；全局顶部只显示紧凑运行入口     | 当前岗位的 AI 处理   |
| 查看处理详情            | 右侧抽屉显示处理对象、来源、所属工作、执行计划和运行记录 | AI 处理与运行记录    |
| 解析结果待审核          | 在岗位页打开字段级审核，用户选择应用哪些建议             | 当前岗位待审核变更   |
| 解析失败                | 保留失败原因、已完成步骤与原输入，允许重试               | 当前岗位的 AI 处理   |
| 查看相关工作            | 目标级工作和 AI 处理记录分区展示                         | 工作与 AI 处理不混排 |
| 查看工作列表            | 岗位解析不进入工作列表                                   | 只展示目标级工作     |

## 状态入口

- 默认：`/positions/position-vla?tab=profile`
- 启动配置：`/positions/position-vla?tab=profile&ai=setup`
- 运行中：`/positions/position-vla?tab=profile&ai=running`
- 待审核：`/positions/position-vla?tab=profile&ai=review`
- 失败：`/positions/position-vla?tab=profile&ai=failed`
- 处理记录：`/positions/position-vla?tab=work`
- 工作列表对照：`/works`

## 验收标准

1. 单一岗位解析不会创建工作，也不进入工作列表。
2. 运行中、待审核和失败状态能从全局紧凑入口返回对应岗位。
3. 用户能从岗位详情查看 AI 处理的执行计划和每次运行记录。
4. 用户确认前，解析建议不改变岗位正式资料。
5. 与岗位有关的目标级工作仍能从“相关工作”进入。
6. 桌面端和移动端均无横向溢出，Modal 与 Drawer 使用公共组件。
