# 云端与配套寻访 App 边界调整：原型变更计划

> 状态：云端原型已完成边界调整并通过自动化专项验证；Hunter 本地助手原型延期，后续单独设计。
>
> 日期：2026-08-21。

## 一、已确认边界

1. Hunter 产品主体是面向个人猎头的云端 SaaS。
2. 需要登录猎聘、脉脉等认证人才平台的自动寻访只在用户电脑上的配套寻访 App 中执行。
3. 云端不登录、调度、监控或恢复认证人才平台自动化。
4. 寻访 App 不是完整本地版 Hunter，只承载岗位任务包、平台寻访、本地候选人整理、匹配调用和候选人批次提交。
5. Hunter 第一阶段只保留邮件作为系统主动通信渠道。云端和寻访 App 均不发送平台私信、不申请好友、不发送短信，也不执行电话外呼。
6. 手机号继续作为候选人和联系人的资料字段保留，但不提供拨号、短信或其他基于手机号的通信操作。
7. 跨端传递以用户主动在线同步为主、文件导入导出为兜底。原型界面统一使用“本机处理”语义，不出现“发送到寻访 App”“自动寻访”或具体人才平台自动化描述。
8. 用户可以把系统外沟通结果写入普通跟进记录，但不选择或保存电话、微信等渠道类型。Hunter 发送的邮件保留独立发送、失败和回复状态。
9. 本机候选人批次默认由用户确认后提交，也允许用户预先授权符合门禁的候选人自动提交。自动提交只进入云端导入批次；是否写入正式候选人使用独立的云端审核设置，并始终经过强制门禁。
10. 候选人批次默认只提交文本和结构化字段。原始简历附件需要用户在提交批次时单独选择；自动提交不包含原始附件，未提交文件继续保留在本机。
11. 用户主动选择、粘贴或拖入文件后直接上传到当前工作，不再增加二次确认。输入区显示附件并允许在发送前移除；格式、大小或上传失败时保留输入并显示错误。
12. 云端候选人详情只显示来源平台和本地批次，不保存认证平台个人资料 URL；“在本机查看来源”由已连接的本地助手打开本机资料。设备离线、资料已清理和来源不可用必须有明确状态。
13. 一个 Hunter 云端账号可以连接多台电脑，但同一任务只能由一台设备接收。每个人才平台账号只能绑定一台设备中的一个浏览器环境；未开始任务允许更换设备，已接收任务在其他设备显示不可重复执行状态。
14. 本机清理规则与云端业务流程解耦。暂定成功任务保留 30 天、失败或取消任务保留 7 天、未提交结果保留 30 天、空间上限 10 GB；该默认值后续在本地助手详细设计中独立验证，不阻塞当前云端原型。
15. Hunter 本地助手必须与阶段一云端 SaaS 同期上线，属于岗位招聘闭环的 P0 组成。当前只设计云端的任务准备、在本机继续、结果接收、合并和审核；本地助手自身页面、设置和运行过程不进入本轮原型，后续单独设计与审批。
16. 云端和本机是并行的候选人来源，不互相等待。任意来源结果到达后立即进入统一身份判断、查重、合并、资料更新和匹配流程；原型使用“新一批结果”“新增候选人”“已有候选人资料更新”，不使用“最终结果”。
17. 明确同一人且资料不冲突时自动合并，并展示合并对象与变化摘要；疑似同一人进入身份确认；同一人存在字段冲突时进入合并审核；确认不同人后建立新候选人并保留判断。自动合并不能静默发生。
18. 岗位更新后，本机旧任务继续存在并标注旧版本，返回结果按最新版岗位重新匹配；岗位关闭后不再接收结果写入，本机下次同步时显示任务失效。云端原型不提供远程暂停、继续或平台执行控制。
19. 发件邮箱在用户设置中配置。第一阶段每封或每批邮件均由 Hunter 生成标题和正文草稿，用户确认或修改收件人、标题、正文和附件后才能发送，不提供自动发送授权。
20. 邮件等待不是持续运行任务。支持事件通知时优先使用通知；否则按邮箱级低频检查新增邮件，不为单封邮件单独轮询。原型必须覆盖等待回复、建议跟进、长期未回复、用户结束等待和晚到回复重新打开主线。
21. 邮件等待暂定为：无法推送时每 6 小时检查；3 个工作日未回复显示“可以跟进”；7 天未回复显示“长期未回复”。用户可以继续等待、让 Hunter 拟定跟进邮件或结束等待，任何发送仍需确认；晚到回复可以重新打开主线。

### 1.1 面向用户的统一文案

| 场景         | 使用文案        | 不使用文案             |
| ------------ | --------------- | ---------------------- |
| 云端入口     | 在本机继续      | 发送到寻访 App         |
| 准备数据     | 准备本地任务    | 生成平台寻访包         |
| 等待状态     | 等待本机结果    | 等待寻访 App 运行      |
| 结果到达     | 本地结果已返回  | 平台寻访结果已上传     |
| 设置入口     | 本机协作        | 人才平台、自动寻访设置 |
| 本地产品名称 | Hunter 本地助手 | 猎聘助手、脉脉助手     |

文案中性不等于隐瞒实际数据处理。首次使用、授权和隐私说明仍需明确说明岗位资料会发送到用户设备、候选人资料由用户确认后提交云端，以及云端不会查看本地平台账号和运行过程。

## 二、保留的原型基础

1. 云端 Shell、导航、工作台信息层级和业务主线统一工作区继续复用。
2. Markdown 对话、流式输出、执行计划、相关任务、外部等待和错误恢复继续复用。
3. Hunter 受控审核组件、候选人审核、身份合并、正式数据写入门禁继续复用。
4. 客户开发、人才摸排和候选人求职的主要业务目标不变，但通信动作统一收敛为邮件或用户在系统外完成后回填结果。

## 三、现有云端页面变更

| 页面         | 需要删除                                         | 需要增加或替换                                       |
| ------------ | ------------------------------------------------ | ---------------------------------------------------- |
| 工作台       | 猎聘、脉脉运行状态，平台登录失效和处理登录       | 本地任务待处理、候选人批次已返回、跨端交接失败       |
| 新建工作     | 云端直接编排人才平台任务的描述                   | 云端公开渠道任务与本地任务并行编排                   |
| 岗位招聘主线 | 人才平台子任务、平台日志、平台登录和平台错误恢复 | 任务准备、等待本机结果、批次到达、云端合并和增量审核 |
| 相关任务     | 猎聘、脉脉执行任务                               | 只保留云端 Agent 任务；本机状态作为跨端交接记录      |
| 候选人审核   | 把平台结果描述为云端直接召回                     | 统一显示云端公开来源和本机已确认提交的结果           |
| 信号中心     | 平台登录、验证码和页面错误                       | 不增加同类业务信号；跨端异常进入通知和待处理动作     |
| 组件页       | 处理平台登录、平台权限受限                       | 本机协作不可用和云端继续工作的状态                   |

## 四、岗位招聘主线的新流程

1. 理解岗位并确认找人边界。
2. 云端并行处理系统候选人、公开网络、论文、专利和人才摸排结果。
3. 生成版本化的本地任务，并允许用户选择已连接设备或下载任务。
4. 等待用户在本机完成处理；该阶段不显示云端 Agent 持续运行，也不持续消耗云端 Agent 用量，云端其他来源继续推进。
5. 接收用户确认提交的候选人批次。
6. 云端完成身份判断、查重、合并、补全、统一匹配和排序。
7. 用户审核候选人并加入岗位储备。
8. 需要由系统执行的对外沟通只允许邮件，并在发送前沿用统一授权和强制门禁。

## 五、需要新增的云端原型

1. 本机未连接、已连接和暂不可用状态。
2. 本地任务准备、选择设备、文件下载、岗位版本变化和失效状态。
3. 候选人批次接收、持续合并、身份合并冲突和增量审核。
4. 文件直接上传、发送前移除、格式与大小校验和失败反馈。
5. 邮件草稿编辑、逐次确认、发送和低频等待。

## 六、后续单独设计的 Hunter 本地助手原型

本节只记录后续范围，不属于本轮原型交付和验收。

1. 待处理岗位任务包。
2. 人才平台登录与设备侧状态。
3. 寻访配置和平台整体进度。
4. 候选人列表、详情、附件和本地匹配结果。
5. 用户选择候选人并提交到 Hunter。
6. 平台错误恢复、检查点、本地数据清理和 App 设置。
7. 寻访 App 不提供邮件、平台私信、好友申请、短信和电话等通信能力。

## 七、本轮实施与 Review 结果

1. 工作台、新建工作和岗位招聘主线已经移除云端直接执行认证人才平台自动化的表达。
2. 岗位主线在云端检索开始后停在“在本机继续”，支持选择已连接设备或下载本地任务；本机不可用不再暂停整条主线。
3. 云端与本机结果按批次持续汇入，每批立即执行身份判断、去重、合并、更新和最新岗位匹配，不使用“最终结果”。
4. 已覆盖等待本机结果、旧岗位版本、身份合并冲突和云端局部来源失败状态。
5. 候选人与客户沟通只保留邮件。邮件草稿可编辑，必须确认收件人、主题和正文后发送；自动执行模式不能绕过。
6. 公共对话附件在用户主动选择、粘贴或拖入后直接上传，不显示二次确认 Modal；发送前仍可从输入区移除。
7. Hunter 本地助手没有制作页面原型，后续必须单独完成需求、交互和审批。

## 八、后续独立处理且不阻塞当前原型的问题

1. 本机任务包与候选人批次的具体同步协议、加密和失败恢复。
2. 本机匹配接口采用实时调用还是批次调用。
3. 本机存储清理默认值、商业权益和设备数量上限。
4. 邮箱供应商接入方式、事件通知能力和凭据安全方案。
5. 认证人才平台自动化的专项法律意见和平台协议评估。
