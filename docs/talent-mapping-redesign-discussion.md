# 摸排能力重构讨论记录

> 状态：讨论中，不直接替代已审批的概要设计、详细设计或原型。
>
> 最近更新：2026-08-31。

### 讨论与设计推进原则

1. 当前 Hunter 的实现和试用数据用于理解真实使用方式、验证历史问题和识别可复用能力，但不作为 SaaS 新设计必须照搬的默认答案。
2. 缩放反馈、Tooltip、快捷键、拖动动效、控件位置等交互细节，由 UX 设计根据产品目标、数据规模、通用最佳实践和已确认设计语言先形成可交互原型，再通过原型验收调整，不在需求确认阶段逐项提问。
3. 需求确认阶段只继续讨论会改变产品边界、数据所有权、核心业务流程、关键异常处理或显著开发范围的重要问题。
4. 已确认的产品原则是原型设计边界，但具体交互不是一次性冻结；原型验证发现理解成本、工作空间或数据规模问题时，可以回到本文更新方案。

## 一、已确认的新认识

### 1.1 摸排的定义

“摸排”是一类持续获取、整理、核实和复用市场人才信息的业务过程，不等同于一份知识图谱，也不应被固化为单一展示形态。

摸排的核心目标是：围绕明确的行业、技术方向、公司、组织或岗位，把相关公司、组织架构、人物、任职、合作和其他关系逐步摸清，并保留来源、时间和可信状态。

### 1.2 共享关系事实与业务结果分开

公司、组织、人物、论文和专利等正式资产，以及能够独立核实的客观关系，应形成可复用的数据。候选人、岗位、公司、论文、专利等资产内部产生的阶段、匹配、归属和作者等关联继续由来源业务记录管理；前同事、共同作者、共同发明人和人才流动等关系根据来源记录形成可持续查询的派生关系。共享事实、来源业务关联和来源派生关系都可以被不同业务场景实时引用，但不因不同页面、图谱或任务而产生第二个可编辑的数据所有者。

基于正式资产、共享事实、来源业务关联及其派生关系，可以形成不同的业务结果：

1. **知识图谱**：以自由画布、组织架构图、人物关系图等受控视图展示某个专题范围内的公司、组织、方向、人物和关系。
2. **岗位人才梳理结果**：围绕特定岗位，结合系统候选人、人岗匹配、公开信息和知识图谱，整理适合继续了解的人选；结果绑定岗位，并随着候选人资料变化更新相关展示和判断。
3. **关系信息**：在候选人、公司、论文和专利等资产中展示学术合作、共同任职、上下游、合作、竞争等与当前业务有关的关系。
4. **联系路径**：当目标人物缺少直接联系方式时，从用户能够联系的人或已知关系出发，梳理一条或多条可能的引荐路径，并明确每段关系的证据和可信状态。

知识图谱、岗位人才梳理结果和联系路径是共享事实、来源业务关联及其派生关系的不同业务视图或阶段性成果，不是彼此独立、重复维护的关系数据库。来源内容发生变化后，当前视图需要自动同步或增量重算；历史版本只负责追溯，不能继续作为当前状态展示。

### 1.3 岗位人才梳理结果采用持续结果与历史版本并存

岗位人才梳理结果不是一次生成后永久不变的静态报告，也不能在底层资料变化后静默改写全部结论。阶段一采用以下产品规则：

1. 岗位详情保留一份持续可用的“当前结果”，供猎头日常查看和处理。
2. 候选人的姓名、当前职位、联系方式等基础资料引用候选人资产的最新资料，不为每次梳理复制一份独立档案。
3. 候选人资料、岗位资料、共享关系或其他输入变化可能影响入选范围、匹配结论、分数、排序、风险或建议动作时，系统自动识别受影响对象并启动增量重算，不等待用户积攒一批后手动更新。
4. 增量重算期间，当前结果明确显示正在更新及受影响范围；完成后自动更新当前结果并生成新版本。用户可以查看新旧版本的主要变化，也可以追溯此前版本。
5. 自动重算只更新匹配和梳理结果，不替用户执行招聘决定。已加入岗位推进的候选人不能因为新分数降低而自动退出流程，联系、推荐、移出流程等业务动作仍由用户决定。
6. 新公开信息、新增知识图谱关系或新的候选人进入系统时，系统可以自动加入“新发现、待查看”的结果范围并说明来源，但不能把尚未审核的人物伪装成已经审核通过，也不能自动联系或推荐。

### 1.4 全局关系事实与场景判断分开

关系层按“客观事实全局共享、来源业务关联由原资产管理、业务判断按场景保存”划分：

1. **全局共享事实**：上下级、师生、认识、引荐、顾问，以及公司投资、合作等能够独立核实且不由某一项业务记录天然拥有的关系。关系需要保留方向、时间、来源、证据和可信状态。
2. **来源业务关联**：人物任职、候选人与岗位的匹配、岗位推进阶段、岗位与公司、论文作者、专利发明人等关联由对应资产或业务记录管理。知识图谱、列表和 Agent 只实时引用，不复制成无范围的共享事实。
3. **来源派生关系**：前同事、共同作者、共同发明人和人才流动等关系可以根据任职经历、论文作者、专利发明人等来源业务关联计算。由来源记录推导出的结果需要长期可查询、持续显示并随来源更新，不能直接改写派生结果。用户拥有独立证据或明确知情时，仍可补充同类共享关系；系统合并展示来源证据和人工证据，不重复显示两条关系。
4. **场景内判断**：某公司是本次目标公司、某人是关键人选、某候选人适合某岗位、优先级、排除原因、所选联系路径和知识图谱中的展示位置等，只在对应岗位、任务或摸排范围内成立。
5. **带范围的客观关系**：竞争、上下游、技术路线相近等关系不能脱离范围保存。例如“两家公司在自动驾驶方向竞争”可以作为共享事实，但必须同时记录适用方向和时间，不能简化成永久、全公司的竞争关系。
6. 同一条共享事实或来源业务关联只维护一次；来源派生关系只保留可追溯的计算结果或查询索引，不形成第二个可编辑的数据所有者。同一语义关系同时存在来源推导和人工确认时，统一展示关系并合并证据，但每项证据仍回到各自来源纠正。不同场景可以引用并给出不同业务判断，不能复制后各自改写来源数据。
7. 场景判断不能反向污染共享关系或来源业务记录。只有出现新的可核实信息并通过对应写入规则后，才能更新来源数据；来源数据一旦合法变化，引用它的当前图谱和业务视图自动同步。

### 1.5 摸排、知识图谱和共享关系的产品入口

1. **摸排是任务，不是资产**：用户从统一任务入口用自然语言发起摸排，任务可以在用户已经创建的知识图谱中生成或更新图页，也可以产生岗位人才梳理结果、人物关系和联系路径等成果；任务不能创建新的顶层知识图谱。
2. **知识图谱是独立业务资产**：顶层图谱必须由用户先创建；已有图谱支持人工维护、文件导入图页，以及任务生成或增量更新图页。文件和任务不能静默创建新的顶层图谱。
3. **岗位人才梳理不依赖知识图谱才能运行**：无论是否已有相关知识图谱，用户都可以从岗位发起人才梳理。存在相关知识图谱时，图谱是重要输入；不存在时，系统使用候选人资产、论文专利、公开网络和用户输入完成梳理，但不默认创建知识图谱。
4. **联系路径按人物生成**：正式候选人和尚未进入候选人资产的人物线索都可以生成联系路径。正式候选人的联系路径在候选人详情中持续显示；人物线索的联系路径在对应人物详情、知识图谱节点或任务成果中显示。人物线索转为候选人后，已经确认的关系和联系路径随身份关系继续引用，不复制一份新数据。
5. **学术关系是持久关系**：已确认的共同作者、师生、同实验室和其他学术合作关系不只存在于一次任务结果中。它们持续显示在候选人或人物详情，并可以被知识图谱、岗位人才梳理和联系路径复用。新增论文或身份确认可以增量更新关系，但不能由一次场景判断静默覆盖。
6. **共享关系层没有独立导航**：关系事实通过公司、候选人、人物线索、知识图谱、岗位、论文、专利和任务上下文展示，用户不需要进入一个抽象的“关系数据库”页面。

### 1.6 公司关系与人才流动采用不同的数据口径

公司关系和人才流动都可以帮助找人和客户开发，但不能作为同一种关系保存：

1. **公司关系**是可以核实的公司间关系，包括竞争、合作、投资、上下游、客户、供应商、孵化或拆分等。它可以由用户维护或任务建议，确认后持久化，并记录方向、适用业务或技术范围、时间、来源和可信状态。
2. **单个人才流动**来源于人物的工作经历，例如某人从公司 A 加入公司 B。事实所有者仍是该人物的工作经历，不能再创建一条独立且可能冲突的公司关系。
3. **聚合人才流动**是对已知人物经历的统计投影，例如“过去两年已知有 8 人从公司 A 流向公司 B”。它应随底层人物经历变化自动重算，不能由用户直接修改统计数字。
4. 人才流动只反映 Hunter 当前已知样本，不能包装成整个市场的完整流动规模。界面需要显示统计范围、时间和样本口径。
5. 任务发现新的公司关系或人才流动变化时，可以形成信号或待确认变化；不会因为一次分析直接改写正式关系。

公司详情增加“关系网络”Tab，并在其中提供两个明确视图：

1. **公司关系**：展示竞争、合作、投资、上下游等关系图和关系清单，支持查看方向、适用范围、时间、来源和证据。
2. **人才流动**：根据已知人物经历展示人才流入与流出，支持按时间、方向和岗位类别查看，并可从流向继续查看具体人物。

知识图谱继续按当前专题范围展示相关公司关系；岗位人才梳理只引用与岗位有关的对标公司和人才来源，不在不同页面复制关系事实。

### 1.7 Agent 同时承担任务执行和工作空间数据分析

Agent 不只负责运行较长的摸排、找人和资料整理任务，还需要能够按照用户的自然语言要求，从当前工作空间读取已经授权的数据，完成查询、组合、统计、比较和解释。

Agent 在产品中只有一种统一的对话交互形态。用户不选择“查询”“分析”“简单任务”或“长任务”，也不需要理解系统采用了哪种执行方式。系统根据用户目标自行判断：可以直接完成时直接回复；需要多个步骤时在同一对话中生成并持续更新执行计划；需要等待外部信息或用户决定时仍在同一对话中暂停和恢复。

产品能力包括：

1. 用户可以随时询问“某家公司近两年主要从哪些公司流入人才”“与目标候选人有共同作者关系的人中，哪些适合当前岗位”“这个方向还缺哪些公司没有摸到”等问题。
2. 简单问题可以一步查询并直接回答，不强制生成执行计划；需要多次检索、身份识别或分析时，系统在同一交互中自动增加执行计划，不切换到另一种产品形态。
3. 少量结果优先在对话中使用 Markdown、表格、列表和摘要展示；大量结果使用可筛选列表、树图、关系图、时间线或文件预览等受控展示组件。
4. Agent 可以根据问题选择合适的展示形式，但不能生成任意 HTML、CSS 或临时页面。关系图、比较、审核和大量数据列表由 Hunter 提供固定的数据结构和渲染组件。
5. 资产页面提供稳定、经常使用的默认视图；Agent 提供按需查询和临时组合。两者读取同一数据，不要求为每一种提问预先设计独立页面。
6. Agent 的数据读取受工作空间、用户权限、敏感字段和查询范围限制。产品层需要保留查询依据、使用的数据范围和结果时间，避免把缺失数据解释为“市场中不存在”。
7. 查询和分析结果默认属于对话成果。只有用户明确要求保存、更新或绑定到岗位、知识图谱等资产时，才进入正式写入流程，并继续遵循用户授权和 Hunter 强制门禁。
8. Agent 可以引用资产、关系、证据和历史结果解释答案；用户从答案打开具体对象时，进入现有资产详情或对应的受控结果视图。

### 1.8 Agent 查询与正式写入的边界

1. 用户要求查看、分析、比较或统计时，Agent 默认只产生对话成果，不改变正式资产。
2. 用户明确要求保存、更新、关联、加入岗位结果或执行其他写入动作时，才进入正式写入流程。
3. 写入是否等待用户再次确认，由当前任务的统一授权模式决定：仅分析不能写入；执行前确认需要用户确认；自动执行可以按授权写入。
4. 无论采用哪种授权模式，Hunter 的身份、结构、权限、租户、敏感信息和数据完整性门禁都不能关闭。
5. Agent 在分析过程中自行发现有价值的信息，但用户没有要求保存时，只能说明发现和建议动作，不能擅自写入正式资产。
6. 直接回答、执行计划、等待用户、结果查看和继续补充都发生在同一个对话中，不为读写边界建立新的任务类型或交互模式。

### 1.9 阶段一关系类型采用固定类型与其他说明

阶段一不提供可配置的自定义关系类型，也不建设关系类型管理页面。原因是自定义类型会引入同义重复、方向不一致、筛选混乱、统计口径不稳定和 Agent 无法可靠理解等问题，收益不足以覆盖产品和用户操作复杂度。

阶段一采用以下规则：

1. 系统提供覆盖主要业务场景的固定核心关系类型，用于搜索、筛选、统计、图形展示、联系路径和 Agent 分析。
2. 人物关系主要覆盖上下级、同团队、前同事、师生、共同作者、共同发明人、开源协作、创始团队、投资、顾问、引荐和认识。
3. 人物与组织关系主要覆盖任职、曾任职、负责人、创始人、顾问、投资人和组织成员。
4. 公司关系主要覆盖母子公司、投资、合作、竞争、客户、供应商、上下游、孵化和拆分。
5. 人物与成果关系主要覆盖论文作者、专利发明人和开源贡献者。
6. 固定提供“其他关系”，允许用户填写一次性的关系说明，但该说明不会成为新的可复用关系类型，也不参与按关系类型统计。
7. “其他关系”可以展示、搜索并被 Agent 引用；只有用户明确确认该关系确实可以用于引荐时，才能进入联系路径，不能根据同校、同协会等共同经历推断双方认识。
8. 关系可以由人工新增、导入或 Agent 建议。修改和删除关系不删除两端资产；多条来源支持同一关系时合并证据，不重复生成多条关系。
9. 固定关系类型只是统一展示和查询词汇，不改变数据所有权。论文作者、专利发明人、岗位流程、人岗匹配等来源业务关联仍在论文、专利、岗位或匹配记录中维护；知识图谱不能把它们复制成一条可独立编辑的通用关系。
10. 前同事、共同作者、共同发明人等可以作为固定展示和查询类型长期使用，但关系名称不直接决定数据所有者。由任职、论文作者和专利发明人等来源记录推导的结果需要回到来源纠正；用户根据独立证据明确补充的同类关系可以保存为共享关系。两种来源命中同一语义关系时合并展示证据，不重复统计。

### 1.10 联系路径的起点和可联系性

1. 联系路径同时支持正式候选人和人物线索，不要求目标人物先转为候选人。
2. 目标人物已有手机号时，可以认为猎头具备直接联系入口，路径状态显示“可直接联系”。
3. 目标人物只有邮箱时，不视为已经可以直接联系。邮箱仍然显示为可尝试的补充方式，但系统继续寻找关系路径，因为邮件得到回复的概率较低。
4. 系统可以把有手机号、已有真实沟通记录，或用户明确说明“我认识他”的人物作为候选起点，但只能作为路径建议，不能认定其愿意帮助引荐。
5. 只有邮箱、没有历史沟通且用户未确认认识的人，不自动作为可联系起点。
6. 每条路径展示起点人物、逐段人物与关系、来源、时间、可信状态和当前缺口，并区分“可直接联系”“路径完整”“需要核实”和“路径不完整”。
7. 即使路径完整，系统也只能建议猎头先联系某人询问，不能把关系存在表述为对方愿意引荐。
8. 用户可以在统一 Agent 对话中补充“我认识某人”“某人可以帮我联系”等信息，系统据此重新计算路径，不要求用户预先维护一套引荐配置。
9. 联系路径依赖的关系、联系方式或人物身份变化后，当前路径自动更新受影响段的有效状态，并增量计算可替代路径；不能继续把失效路径显示为当前可靠路径，也不能等待用户以后集中处理才刷新。

### 1.11 底层资产关系的持久化与调用

Hunter 中具有长期业务价值的资产关系需要持续保存，并能被资产页面、任务、知识图谱、匹配、信号和 Agent 在权限范围内复用。这些可复用数据包括独立维护的共享关系事实，也包括由原业务资产持续维护的来源业务关联；不能把二者统一复制成一套脱离来源的关系记录。

需要持续保存和调用的内容包括：

1. 候选人与公司、岗位推进、论文、专利、文件和知识图谱节点之间的正式关联。
2. 公司与联系人、招聘机会、岗位、候选经历和其他公司的正式关联。
3. 论文作者、专利发明人经过身份确认后与人物或候选人的关联。
4. 已确认的人物关系、公司关系、任职关系、学术合作关系及其方向、时间、范围、来源和可信状态。
5. 知识图谱节点与正式资产的关联，以及图谱内部由用户保存的自由节点和自由连线。
6. 知识图谱对候选人匹配、岗位流程、岗位归属、论文作者等来源业务关联的引用及展示配置；来源关联本身仍由原资产或业务记录管理。

并非所有关系表现都要重复保存为一条新的全局关系：

1. 单个人才流动来自候选人的工作经历，聚合人才流动由工作经历计算，不再复制一套独立事实。
2. 岗位候选人数、公司推进统计、关系图布局和筛选结果属于派生展示，可以实时计算或缓存，不作为新的业务事实；知识图谱展示这些内容时必须随来源自动刷新。
3. 联系路径是基于当前关系计算的业务结果，需要保存历史版本以便追溯，但当前路径状态和可替代路径随底层关系自动增量更新，路径中的每一段仍引用原始关系事实。
4. 某人是否适合某个岗位、某公司是否是本次目标公司等场景判断按岗位、任务或图谱范围保存，不提升为无范围的全局事实。
5. Agent 未经确认的推断只保留为建议、证据或待确认变化，不能被其他任务当作已确认关系直接使用。

产品需要保证关系可查询、可解释、可纠正、可追溯并能自动传播到所有当前引用；具体关系来自资产字段、关联记录还是关系存储，由后续技术方案决定，产品详细设计不强制所有关系使用同一种数据库结构。

## 二、可进一步承载的业务用途

### 2.1 招聘与岗位交付

1. **岗位市场校准**：在正式找人前，判断目标职级、核心技能、常见背景、主要来源公司和地域分布，帮助猎头与客户校准岗位要求，避免用不现实的画像反复搜索。
2. **岗位人才池盘点**：把系统已有候选人、公开信息发现的人物线索和知识图谱中的相关人员放在同一范围内，区分已确认候选人、待补充线索、已在流程中和暂不适合的人。
3. **相邻人才发现**：从目标人物所在团队、前同事、共同作者、共同发明人、上下游团队和相似组织中扩展搜索，而不是只依赖关键词命中。
4. **替代人选与梯队**：对重点候选人整理同团队、相似角色、前任、继任者或能力邻近的人选，降低单一候选人失联或拒绝后的重新搜索成本。
5. **团队型招聘**：识别同一团队中的关键负责人、骨干和协作角色，支持一次岗位招聘继续发现多个相关岗位或成组人才，但不把关系推断直接当作候选人意愿。
6. **招聘漏斗缺口分析**：把市场中已经摸到的人才与岗位当前流程对照，判断缺的是目标公司覆盖、某类角色、联系方式、资料完整度，还是已联系后的转化。
7. **候选人反向匹配**：候选人资料、任职或技术方向发生变化后，系统自动增量重算其可能适合的有效岗位并同步相关图谱；新的匹配判断显示变化原因，但联系、推荐和流程调整仍由用户处理。
8. **推荐依据解释**：人岗匹配不仅返回分数，还能说明候选人来自哪家公司和团队、与哪些目标人物或成果有关、为什么被扩展发现，帮助猎头判断推荐是否可信。

### 2.2 客户开发与招聘机会

1. **目标公司发现**：从新公司成立、团队扩张、关键管理者加入、人才持续流入、论文专利活跃和公开招聘等变化中发现潜在客户。
2. **客户组织与决策关系**：梳理业务负责人、招聘负责人、HR、创始人、投资人、顾问和可能的引荐关系，帮助猎头判断应该先找谁了解需求。
3. **招聘需求预判**：结合组织变化、人才流动和技术方向扩张形成招聘信号；信号只提醒用户或建议创建任务，不直接认定为正式岗位。
4. **客户沟通材料**：用目标公司团队结构、竞品人才分布、可触达人才范围和主要招聘难点形成有依据的沟通材料，帮助猎头证明对市场的理解。
5. **岗位可交付性判断**：在承接需求前，评估市场中可识别人才、可联系路径和关键资料缺口，辅助判断搜索难度和后续投入，但不自动给出合同或报价结论。

### 2.3 人才经营与关系维护

1. **重点人物持续关注**：围绕关键候选人、行业专家和团队负责人，跟踪任职、成果、合作关系和公开动态的变化；变化进入信号中心，不静默覆盖已确认事实。
2. **学术与技术网络**：通过共同作者、师生、同实验室、共同发明、开源协作等关系发现技术圈层中的核心人物和新兴人才。
3. **人才流动观察**：识别同一公司或团队的人才流入、流出和集体迁移迹象，辅助理解行业变化、候选人来源和潜在招聘需求。
4. **关系维护优先级**：结合岗位相关度、资料新鲜度、联系路径和历史沟通，提示哪些人物值得猎头优先人工跟进；系统不替代猎头通过认证人才平台或私人通信渠道联系。
5. **人物身份消歧**：共同机构、合作对象、任职时间和成果关系可以辅助判断同名作者、发明人或公开人物是否为系统中的同一人，最终仍遵循身份确认和合并规则。

### 2.4 市场与行业认知

1. **公司生态图**：展示竞争、合作、投资、供应链、客户和人才流动关系，为岗位对标公司和相邻人才来源提供依据。
2. **技术方向演进**：从公司组织、岗位、人才、论文和专利的变化中观察某个技术方向由谁在做、团队如何变化、关键能力向哪里迁移。
3. **角色与能力分布**：总结不同公司中相似职责使用的不同职位名称、组织归属和常见能力组合，辅助岗位解析和搜索词生成。
4. **区域人才分布**：按实际任职地点和团队所在地观察人才集聚与迁移，为岗位 Base、远程安排和候选人来源提供参考。
5. **专题市场报告**：把某次摸排范围内已经确认的公司、组织、人物、关系、缺口和证据整理为可复用报告；报告是由任务生成的成果文件，不是知识图谱数据导出，也不是新的事实副本。

### 2.5 Agent 的搜索与决策支撑

1. **搜索范围扩展**：Agent 可以沿已确认关系逐层探索目标人物、相邻团队和相关成果，减少只靠固定关键词造成的漏召回。
2. **搜索去重与停止判断**：系统知道哪些公司、组织、人物和来源已经查过，避免重复消耗；同时用目标清单和明确缺口判断下一步，而不是追求不可解释的“市场覆盖率”。
3. **增量影响分析**：新证据进入后，只重算受影响的人物身份、关系、岗位结果和联系路径，并向用户说明变化原因。
4. **结论可解释**：Agent 的推荐、信号和联系路径能够回溯到具体关系、来源和时间，用户可以纠正错误关系，纠正结果供后续任务复用。
5. **任务编排依据**：关系事实可以帮助 Agent 判断应该继续查组织、补人物资料、做身份确认、更新岗位匹配，还是等待用户补充信息。

## 三、建议的阶段优先级

### 3.1 阶段一必须支撑

1. 知识图谱中的公司、组织、人物和主要关系。
2. 面向岗位的人才梳理结果，以及与岗位流程、人岗匹配的清晰关系。
3. 相邻人才发现和替代人选扩展。
4. 学术合作、共同任职等对找人有直接价值的关系展示。
5. 缺少直接联系方式时的联系路径梳理。
6. 资料变化后的影响提示、增量更新和结果解释。
7. 关系来源、时间、可信状态、冲突和人工纠正。
8. 从组织变化、人物变化和公开招聘中形成信号。

### 3.2 可以在阶段一后续逐步增加

1. 客户目标公司发现和招聘需求预判。
2. 人才流动、团队迁移和角色能力分布。
3. 岗位市场校准和可交付性判断。
4. 专题市场报告与客户沟通材料。
5. 重点人物的长期变化关注。

### 3.3 暂不作为阶段一承诺

1. 用关系中心度自动判断“行业影响力”或“关键人物”。
2. 自动判断候选人的跳槽意愿、竞业限制或私人关系强弱。
3. 根据不完整关系自动代表猎头联系候选人。
4. 把所有行业知识都建设成需要用户维护的通用知识图谱。
5. 在没有明确范围和总体数量时输出虚假的市场覆盖率。

## 四、产品边界

1. 共享关系事实不等于所有关系都已确认。推断关系必须与已确认事实分开，并展示依据。
2. 摸排结果服务业务判断，不替代候选人意愿、客户需求和招聘决定。
3. 云端 Hunter 不登录或控制需要认证的人才平台，也不与外部简历摘取工具通信；用户可主动上传简历，Hunter 可使用公开网络信息。
4. 未经确认的 Agent 推断不能静默覆盖正式资料。涉及身份、组织归属或关键关系冲突的新写入，需要形成可审核变化；已经在各自数据所有者中合法生效的数据变化同步到图谱时，不属于再次写入，不应被重复审核阻塞。
5. 不为每一种用途复制一份关系数据。页面、任务和报告只保存业务范围、筛选条件、判断结果，以及对共享事实、来源业务关联和来源派生关系的引用。

## 五、知识图谱结构与操作结论

当前关于知识图谱基本形态的两个问题已经关闭：

1. 知识图谱不限定为一个完整摸排主题，也不限定为单家公司或团队组织结构图。它是一张由用户自行定义范围的受控自由关系画布。
2. 知识图谱不预先强制使用固定的“公司 / 组织 / 人物 / 生态”分类。用户可以在同一份图谱中按自己的理解组织多个根节点、子树和关系；系统通过受控视图、资产关联和 Agent 理解逐步结构化，而不是要求用户创建时先选严格类型。

后续仍需在信息架构和详细交互阶段继续确定，但不影响上述基本定义的问题包括：

1. 一份知识图谱内多个视图、根节点和专题区域的具体导航方式。
2. 大规模节点、交叉关系、冲突和未关联人物的查看与审核方式。

已确认视图组织原则：

1. **同一图页的画布与层级表格共用一份页面级节点实例、图谱本地连线和资产关联数据。** 两种展示方式不是两份可以分别编辑的业务内容。
2. **不同图页分别维护自己的节点实例、图谱本地连线、层级和布局。** 同一正式资产可以在多个图页或同一图页的多个位置出现，但每次出现都是独立节点实例。
3. 不同图页共同引用工作空间中的正式资产、共享关系、来源业务关联和来源派生关系，不复制这些来源数据。
4. 阶段一默认提供画布与层级表格两种展示方式。组织关系、人物关系和公司生态等内容由同一画布按图页范围和关系类型展示，不在阶段一预设为额外的固定视图类型。
5. 共享关系、来源业务关联、来源派生关系或同一图页中确认的底层内容发生变化后，会自动反映到引用该内容的当前展示；仅属于某个展示方式的布局调整不会改变另一个展示方式或其他图页。

已确认图页原则：

1. 一份知识图谱可以包含多个图页，避免不同专题区域全部挤在一张无限画布上。
2. 每个图页保存自己的名称、内容范围、当前展示方式，以及不同展示方式各自的布局配置，例如“公司分布”“阿里组织结构”“关键人物关系”。
3. 不同图页仍属于同一份知识图谱，并复用同一套正式资产、共享关系、来源业务关联及其派生关系；同一公司、人物或其他资产可以出现在多个图页中。
4. 图页不是独立知识图谱，删除图页不应误删其他图页仍在引用的正式资产或共享关系。
5. 图页的导航方式和大量图页时的管理交互留到原型阶段确认。

已确认展示方式原则：

1. 同一个图页必须支持切换展示方式，不能要求用户为了换一种展示方式而新建图页。
2. 阶段一至少支持画布视图和层级表格视图。
3. 画布视图用于直观查看和维护节点、层级、分组、人物及交叉关系。
4. 层级表格视图采用类似 Excel 的结构化展示，通过层级列和合并单元格清晰表达父子结构，便于扫描、批量阅读和编辑；当前阶段暂不据此承诺文件导出。
5. 两种视图读取同一份节点、图谱本地关系、共享关系、来源业务关联和资产关联数据。任何来源变化或任一视图对底层内容的修改都应自动反映到另一方，不能复制两套内容。
6. 画布坐标、缩放和折叠状态与表格列宽、排序和展开状态分别保存，切换视图不要求共享完全相同的布局。
7. 后续是否增加组织架构、关系网络等专用视图，在画布与层级表格完成后再评估，不作为当前讨论的前置条件。

已确认层级表格合并规则：

1. 合并单元格由系统根据节点父子层级自动生成，不提供类似 Excel 的任意区域合并操作。
2. 每一级节点对应一个层级列；父节点单元格自动纵向覆盖其全部可见子节点行。
3. 用户通过新增节点、调整父子层级、拖动顺序和删除节点改变表格结构，系统随结构变化重新计算合并范围。
4. 折叠节点、筛选内容或切换图页时，只改变当前显示范围，不改变底层层级结构。
5. 自动合并规则必须保证同一份内容可以在画布和层级表格之间无损切换，不能产生画布无法表达的任意单元格结构。

已确认交叉关系展示规则：

1. 父子层级由层级列和自动合并单元格表达。
2. 合作、竞争、前同事、共同作者等不属于父子层级的交叉关系，不强制改造成树结构，也不为此复制节点。
3. 层级表格提供“关联关系”摘要列，使用关系类型和数量说明当前范围内的交叉关系，例如“前同事 3”“共同作者 5”。
4. 用户点击关系摘要后，可以查看关联对象、关系类型、方向、证据、时间和可信状态。
5. 画布视图直接使用受控连线表达交叉关系；表格和画布引用同一份关系数据。

已确认节点层级规则：

1. 同一图页中的一个节点最多只有一个主要父节点，主要父节点决定画布中的树形层级和层级表格中的自动合并结构。
2. 一个节点可以同时拥有任意数量的交叉关系；交叉关系不改变主要父子层级。
3. 同一正式资产需要出现在两个层级分支时，使用两个节点实例引用同一资产，不让一个节点实例拥有多个主要父节点。
4. 删除或移动节点时，需要分别说明对主要父子结构和交叉关系的影响，不能因为调整层级而静默删除仍然有效的交叉关系。
5. 没有主要父节点的节点是当前图页的根节点；一个图页可以包含多个根节点。

已确认节点实例原则：

1. 同一个正式资产可以同时出现在同一知识图谱的多个图页，也可以在同一图页的不同位置出现。
2. 每一次出现都是独立的图谱节点实例，可以使用符合当前上下文的显示名称、补充备注、层级位置和布局。
3. 节点实例引用的正式资产资料保持共享。资产名称、当前职位、公司、联系方式等正式资料更新后，各节点自动刷新引用信息，但不会覆盖节点实例自己的显示名称和备注。
4. 删除某个节点实例只移除它在当前图页中的展示，不删除正式资产、共享关系或其他图页中的节点实例。
5. 用户从节点打开正式资产时进入同一份资产详情；节点上下文不能复制成另一份候选人、公司或其他正式资产。

已确认节点点击与详情原则：

1. 点击知识图谱节点统一打开节点详情面板，不因节点关联资产数量不同而直接跳转到不同页面。
2. 节点详情显示当前节点的文字、备注、所在层级、关联资产、交叉关系、来源和最近变化。
3. 节点关联多个资产时按资产类型分组展示；数量较多时支持搜索和渐进展开。
4. 用户点击面板中的具体资产后，再进入候选人、公司、岗位、论文、专利等正式资产详情。
5. 编辑节点本地内容、管理资产关联和查看关系证据都从节点详情面板进入，避免在画布和表格中堆叠大量操作按钮。
6. 画布和层级表格使用同一套节点详情面板，保持操作一致。

已确认 Agent 更新与授权原则：

1. Agent 更新知识图谱继续使用全产品统一的三档授权模式，不为知识图谱建立另一套授权交互。
2. “仅分析”只返回建议和预览，不修改知识图谱。
3. “执行前确认”先展示新增、修改、移动、删除、资产关联和关系变化，用户确认后再写入。
4. “自动执行”可以在通过门禁后直接更新图谱，但仍必须生成可查看的变更批次，并明确说明修改内容。
5. 每次应用 Agent 变更后形成可追溯版本，支持查看差异和恢复；自动执行不等于静默覆盖。
6. 涉及正式资产、人物身份或共享关系的变化，继续经过对应的数据结构、身份、证据、重复和权限门禁，不能因为图谱允许自动执行而绕过。
7. 一个变更批次可以同时包含图谱本地变化和共享数据建议，但审核与结果说明必须明确区分两者的影响范围。
8. Agent 提出新的图谱内容、正式资产或共享关系变更时继续受上述授权约束；已经在各自数据所有者中合法生效的共享事实、来源业务关联及其派生关系同步到图谱，不是 Agent 变更，不生成新的授权确认。

### 5.1 人工编辑保存与版本规则（阶段一暂定）

1. 节点输入、拖动、调整层级和连线后自动保存。
2. 当前编辑过程中支持逐步撤销和重做。
3. 连续进行的一组人工操作合并为一次编辑记录，不为每次拖动或每个字符创建独立历史版本。
4. 用户离开知识图谱、较长时间停止编辑或完成一批操作后，系统自动形成历史版本。
5. Agent 更新和文件导入始终各自形成独立版本，不与人工编辑版本混合。
6. 阶段一不要求用户手动命名版本。
7. 具体合并时间和自动保存技术实现由后续技术方案确定，产品验收关注不丢修改、可以撤销、历史可追溯。
8. 历史版本保存当时的资产摘要、共享关系、来源业务关联和来源派生关系状态，用于解释当时看到的图谱；历史状态只读，不能继续作为当前事实参与新的分析或业务操作。
9. 恢复历史版本只恢复知识图谱自己的节点、文字、层级、布局、图页和显示配置，不回滚或覆盖正式资产、共享关系和来源业务记录。恢复后的新版本重新解析当前来源状态；已经删除或失效的来源只显示为失效引用，不会被图谱恢复操作重新创建。

### 5.2 知识图谱操作清单（讨论草案）

以下清单用于明确知识图谱需要承载的完整用户操作。标记为“待确认”的操作需要继续讨论，其他操作仍需在原型阶段验证具体交互。

#### 图谱级操作

1. 新建知识图谱：由用户创建空白图谱，先确定名称和必要的基础信息；文件导入和 Agent 不能直接创建新的顶层图谱。
2. 查看、搜索和筛选知识图谱。
3. 编辑图谱名称、简介、备注和关联业务。
4. 导入文件到当前知识图谱。
5. 知识图谱导出暂不纳入当前阶段操作清单；现有格式是否保留、导出当前图页还是整份图谱，后续单独确认。
6. 删除知识图谱、进入统一回收站、恢复或到期清理。
7. 查看图谱历史版本、版本差异和恢复结果。

#### 顶层图谱创建后的空状态

1. **已确认：用户创建知识图谱时只创建顶层资产，不自动生成第一个“未命名图页”。**
2. 顶层图谱最低只要求填写名称；简介、备注和关联业务可以在创建时填写，也可以创建后补充。
3. 创建完成后进入知识图谱详情空状态，提供三条明确路径：新建空白图页、导入图页、让 Agent 生成图页。
4. 新建空白图页后直接进入可编辑画布；导入图页复用已经确认的格式校验、结构预览和后台智能分析流程。
5. 用户没有选择任何路径时，知识图谱保持合法的空资产，不因缺少图页报错，也不自动创建占位内容。
6. 空状态只负责选择下一步，不把三条路径设计成三种知识图谱类型；后续同一图谱仍可混合使用人工、导入和 Agent 维护。

#### 图页级操作

1. 新建、重命名、删除和调整图页顺序。
2. 在多个图页之间切换，并记住用户上次打开的位置。
3. 在画布和层级表格之间切换，同一图页复用同一份内容。
4. 分别保存画布布局和层级表格的列宽、展开、筛选等展示偏好。
5. 将节点移动到其他图页，或在其他图页创建引用同一正式资产的新节点实例。
6. 图页删除前说明节点实例、图谱本地连线和共享资产引用的影响。

#### 文件导入落点

1. **已确认：文件导入只能从一份已有知识图谱内发起，用于向该图谱增加图页；知识图谱列表和全局数据导入不提供“通过文件创建知识图谱”。**
2. 用户必须先自行创建知识图谱，再选择要导入的文件和目标图谱。
3. 导入不能静默创建另一份知识图谱，也不能静默合并到用户当前正在编辑的图页。
4. 文件解析前先完成格式校验，解析后显示结构预览、预计生成的图页、节点和关系数量，用户确认后才写入。
5. 图页名称重复时，用户选择替换原图页或保留两者；保留两者时系统添加可理解的名称后缀。
6. 文件导入形成独立历史版本。解析或写入失败时保留原知识图谱和原图页，不产生半成品内容。

#### 文件内容与图页的对应规则

1. **已确认：FreeMind 等单一结构文件，一个文件生成一个图页。**
2. Excel 文件包含多个通过格式校验的有效数据 Sheet 时，每个有效 Sheet 生成一个图页。
3. 同一个文件结构或 Sheet 中存在多个根节点时，多个根节点保留在同一个图页，不按根节点拆分图页。
4. 导入预览列出文件内所有可导入的结构或 Sheet，用户可以取消勾选不需要导入的部分。
5. 说明、模板示例、隐藏辅助数据和不符合图谱格式的数据 Sheet 不生成图页，并在校验结果中说明排除原因。
6. 多个图页在一次确认后作为同一个导入批次写入，并形成一个可整体查看和恢复的导入版本。

#### 导入格式兼容门禁与导出待讨论项

1. **已确认：SaaS 阶段一的知识图谱导入格式不能相对当前 Hunter 缩水。** 实现方式、解析流程和中间数据结构可以变化。
2. 当前 Hunter 代码确认支持以下 7 类导入格式，SaaS 阶段一继续全部支持：
   - EdrawMind / WPS 思维导图：`.emmx`。
   - XMind：`.xmind`。
   - OPML：`.opml`。
   - Markdown：`.md`、`.markdown`。
   - FreeMind / Freeplane：`.mm`、`.freemind`。
   - Hunter 结构化备份：`.json`。
   - Excel：`.xlsx`。
3. 所有格式都必须在写入前完成格式和结构校验。文件损坏、不符合格式或超过限制时停止导入并给出可理解的错误，不产生半成品图页。
4. 各格式承载能力不同。导入预览需要说明哪些内容可以保留、哪些内容会退化，不能静默丢失交叉关系、资产关联、备注或布局。
5. Hunter JSON 和 Excel 在导入时优先保留结构化信息；第三方思维导图和大纲格式优先保留其可识别的原生结构，并在能力允许范围内读取 Hunter 扩展信息。
6. 当前 Hunter 的实现依据为 `hunter/mapping/io/importers`、`hunter/mapping/io/exporters` 及人才地图详情页的格式入口；后续详细设计和技术评估需要逐格式建立兼容测试样本。
7. **最新决定：当前阶段先不设计知识图谱导出范围和交互。** 类似 Excel 的层级表格属于站内展示方式，不等同于生成 `.xlsx` 文件；是否保留当前 Hunter 的多格式导出、提供整图备份或只支持部分导出，留到后续单独讨论。
8. 暂缓的是知识图谱详情中的业务导出能力，不取消产品级数据可携带、账号数据导出或灾备恢复要求。后者属于全产品数据治理范围，不能被理解为用户数据无需导出，但不在本轮设计具体格式和入口。

#### 外部文件中的资产识别与关联

1. **已确认：知识图谱导入文件按外部资料处理，不假设文件包含 Hunter 资产 ID，也不围绕 Hunter ID 设计导入主流程。**
2. 系统先完整保留文件中的节点、层级、顺序、备注和可识别关系。资产识别或关联失败不能阻塞图页导入，也不能删除原始节点内容。
3. AI 结合节点自身、父子节点、相邻关系和文件上下文，识别其中可能存在的人物、公司、岗位、论文、专利或其他正式资产。
4. 资产候选匹配优先使用文件内容中可识别的手机号、邮箱、个人资料链接等稳定信息，其次综合姓名、公司、职位、教育经历和其他上下文信息。
5. **已确认：高可信唯一匹配由 AI 做语义判断。** 代码负责限制候选范围、校验输出结构、执行最低证据门槛和拦截明显不安全结果，不能用“数据库中只有一个同名对象”替代 AI 的上下文判断。
6. 只有姓名时绝不自动关联。AI 判断存在充分组合证据且只对应一个资产时，可以自动关联；系统保存关联依据、使用的上下文和变更记录，并允许用户撤销。
7. 多个候选对象、证据不足或信息矛盾时标记“待确认”。用户可以查看节点上下文与候选资产的完整对比，再选择关联对象。
8. 没有匹配对象时保留自由节点，不自动创建人物线索、候选人、公司或其他资产。用户后续可以关联已有资产或从节点创建新资产。
9. 导入结果区分“已自动关联”“待确认”“未找到资产”和“解析异常”，但用户不需要处理完所有问题才能查看和使用图页。
10. AI 判断失败、输出不符合结构或达到重试上限时，降级为不关联并说明原因，不能为了完成导入写入低可信关联。

#### 导入后的后台智能分析

1. **已确认：文件通过格式校验和结构预览后，用户确认导入，图页先完整写入并立即可以查看。** AI 分析不阻塞图页落地。
2. 导入确认页提供“智能分析节点与连线关系”选项，默认开启，用户可以关闭。界面说明该操作会使用 AI 并产生相应用量。
3. 选项开启后，AI 结合图页上下文识别节点可能对应的业务资产，并尝试理解无标签连线可能表达的组织、任职、合作、竞争、上下游或其他业务关系。
4. 选项关闭后，只导入原始节点、层级和连线，不进行资产或关系识别；用户后续仍可从知识图谱中启动相同分析。
5. 智能分析作为本次导入的后台处理继续运行，归属于“导入处理记录”，不创建独立任务，避免任务列表被资产内部处理占满。
6. 知识图谱页面显示简洁的分析进度、当前阶段和已处理数量。用户离开页面后处理继续运行，返回时可以查看最新状态。
7. 用户可以暂停、继续或重新分析。失败只影响尚未分析或未可靠关联的节点和连线，不回滚已经导入的图页结构和通过门禁的可信关联。
8. 导入处理记录保存每批自动关联、关系建议、待确认、无法判断和失败原因，用户可以按状态查看并定位到对应节点或连线。
9. 后台处理达到重试上限后停止并给出可继续操作的结果，不能无限重试或长期占用 Agent 用量。

#### 无标签连线的语义边界

1. 导入文件中没有关系名称的连线，默认只作为当前图页的“结构连接”保留，表示原文件中的节点连接关系。
2. 无标签连线不会因为两端节点关联了正式资产就自动成为共享关系，也不会全部生成待确认项。
3. 开启“智能分析节点与连线关系”后，AI 可以结合节点上下文尝试解释连线，但只依据图形位置和连接方式形成的结论只能作为建议。
4. AI 找到文件中的明确文字或可核实外部证据后，再按照当前授权模式、关系去重规则和共享写入门禁处理。
5. 无法可靠解释的连线继续保持结构连接，不强制填写关系类型，也不把“无法判断”当作导入失败。

#### 智能分析结果的发现与审核交互

1. **已确认：智能分析结果同时使用节点或连线上的就地标记，以及知识图谱内的集中分析审核模式，两种入口必须联动。**
2. 节点或连线标记用于让用户在当前图谱中直接发现待确认、冲突或分析异常。点击标记后进入分析审核模式，并自动选中对应结果。
3. 分析审核模式与知识图谱处于同一页面，不使用普通 Modal。页面以图谱为主要工作区，提供较窄的待处理列表和用于完整上下文、资产对比、AI 判断依据及证据的详情区域。
4. 用户从待处理列表选择一项时，画布自动定位并高亮对应节点或连线；切换到层级表格时，表格滚动并选中对应行和关系摘要。
5. 用户在任一入口完成确认、修改、仅保留在当前图谱或忽略后，节点标记、连线状态、列表数量和详情内容立即同步更新。
6. 一个节点或连线包含多个待处理事项时，标记显示主要风险和 `+N`，点击后在审核列表中展开全部事项，不把多个徽标堆叠到图形上。
7. 用户可以关闭分析审核模式继续编辑图谱，未处理结果继续保留；审核不是使用图谱的强制前置步骤。
8. 复杂的人物身份或关系冲突对比可以在当前页面扩展详情工作区，不使用空间不足的 Modal，也不默认打开新的浏览器 Tab。
9. 画布和层级表格共用同一份审核状态。任何视图中的处理结果都不能只更新当前视图。

#### 分析状态标记的生命周期

1. **已确认：待确认、身份或关系冲突、处理失败等仍需用户介入的状态持续显示，直到用户处理、忽略或问题因数据变化而失效。**
2. 高可信自动关联或自动写入在本次分析完成后显示“本次已更新”等短期标记，便于用户查看和撤销；用户查看后或经过产品规定的短期展示周期后，不再占用图谱主要视觉空间。
3. 已确认且没有异常的普通资产关联和共享关系不长期显示 AI 标记，只显示正常的资产类型、关联状态或关系样式。
4. 标记消失不删除历史。AI 判断依据、证据、处理人、处理时间和撤销所需版本信息继续保存在分析记录和历史版本中。
5. 用户可以从分析记录重新定位历史自动变更，但历史记录不能重新把整张图永久标成“已处理”。

#### 正式资产与共享关系的实时同步

1. **已确认：知识图谱中已经关联的正式资产和已经引用的共享关系不是静态快照，而是底层正式数据的实时视图。**
2. 正式资产的名称、职位、公司、有效状态等展示字段发生变化后，对应节点的资产摘要自动更新；用户维护的节点标题、备注、层级和布局保持不变。
3. 已被知识图谱引用的共享关系发生类型、方向、适用范围、时间、有效状态、合并或删除变化时，所有引用该关系的图谱和图页自动同步，不等待用户积攒一批后统一处理。
4. 共享关系失效或被删除后，正常关系视图立即反映最新状态。历史版本继续保存此前关系及当时证据，但不能让失效关系继续以当前有效关系的样式显示。
5. 自动同步属于正式数据引用更新，不需要再次请求图谱写入授权，也不生成待确认审核项；同步结果记录在图谱变化历史中，并使用短期“已更新”标记帮助用户理解变化。
6. 资产或关系来源本身存在错误时，用户需要修正正式资产或共享关系；知识图谱不能通过复制旧值长期覆盖底层事实。用户仍可以在当前图谱隐藏某条共享关系显示，但这只影响当前图页展示。
7. 图谱本地自由节点、本地结构连接、本地关系、用户文字和空间布局不因共享数据变化而被覆盖或删除。
8. 实时同步必须能定位所有受影响的知识图谱和图页，并在合理时间内完成；不能依赖用户下次手动启动 Agent 才刷新关系。
9. “受影响的知识图谱和图页”包括：已经引用该资产或关系的图页、与图中已有节点产生了允许展示的新关系的对象、保存的内容范围会命中该变化的图页，以及从该图谱上下文产生并绑定回图谱的业务结果。系统不能只按图谱名称或文字相似度猜测影响范围。
10. 新关系的一端尚未出现在图页时，只要该关系已经确定属于当前图页的内容范围，并且证据充分或已经由用户确认，系统就自动把新对象作为节点加入图页并建立关系，不能只在节点详情、变化提示或待处理列表中提醒用户手动添加。

#### 资产内派生或阶段性关联的实时同步

1. **已确认：知识图谱正在展示的关系不只包括共享关系事实，也包括候选人、岗位、公司、论文、专利等资产中生成的派生或阶段性关联；这些关联变化后也必须自动更新对应图谱。**
2. 典型关联包括但不限于：候选人与岗位的匹配结果、候选人所在岗位流程及当前阶段、岗位与公司、候选人与当前或历史公司、论文作者、专利发明人，以及其他由正式业务记录产生且允许在图谱中展示的关联。
3. 这类关联继续归属于原业务资产或业务记录，不因为显示在知识图谱中就升级为无范围的共享关系事实。图谱保存来源引用、显示配置和布局，不复制一份脱离来源的关系数据。
4. 来源记录的对象、状态、分数、阶段、有效性或删除状态变化后，对应图谱连线、标签和状态自动同步；关联结束或失效后不能继续显示为当前有效状态。
5. 历史图谱版本保留当时使用的派生关联快照和来源版本，当前图谱始终显示最新来源状态。
6. 用户可以在某个图页隐藏一类派生关联或单条关联，但隐藏只改变当前视图，不修改候选人、岗位或其他来源资产。
7. 图谱需要在视觉上区分共享关系、资产内派生关联和图谱本地关系，并在关系详情中明确显示来源，避免用户误以为三者具有相同的数据权威性。
8. 资产内派生关联的同步同样不形成需要集中积压处理的审核批次；如果来源变化导致身份冲突或业务规则冲突，则显示即时异常状态并进入对应资产的处理流程。
9. 新产生的来源业务关联只要属于当前图页，并且已经在来源资产中合法生效，就自动增加或更新节点、连线和状态。即使新关系的一端原本不在图页中，也需要直接增加对应节点，并对新增内容使用短期变化标记，让用户在图上看到实际变化。
10. 手工整理的图页同样遵循实时更新原则，不能因为没有保存动态范围就把新对象停留在节点详情或待处理提示中。系统根据已有节点、关系类型、图谱上下文和已保存内容判断是否属于当前图页；名称相似但没有正式关联的数据仍不能被加入。
11. **已确认：自动增加节点时保留用户现有布局。** 单个新节点放在触发关系的节点附近；一次新增多个节点时形成整齐的临时分组；附近空间不足时放到相邻的新内容区域。系统只整理新增节点和必要的局部空间，不能重新排列整张图。新增内容使用短期标记，用户可以继续移动节点、调整层级或隐藏当前图页中的关系显示。
12. **已确认：自动新增不做无限递归扩张。** 系统只加入本次变化直接涉及的节点和关系，以及当前图页已经明确关注的关系类型或内容范围；新加入节点自身的论文、共同作者、历史公司、岗位和其他外围关系，不会仅因为节点被加入就全部继续展开。
13. 新节点的其他关系以后如果分别命中当前图页的内容范围，仍按实时同步规则逐项加入。该限制只阻止无边界级联，不允许系统借此保留已经命中的旧数据或延迟更新。
14. **已确认：用户手动从当前图页删除自动加入的节点后，同一来源关系再次变化时不能把该节点自动加回来。** 删除节点实例同时形成当前图页的排除记录，只影响本图页展示，不删除底层资产、共享关系或来源业务关联。
15. 删除关系显示只排除当前关系；删除节点实例只排除该节点实例及其自动加入依据，不把同一正式资产在当前图页中的所有其他实例一并排除。从隐藏内容恢复原实例时取消对应排除记录，并恢复该实例的后续实时同步。
16. 图页级排除优先于自动同步，但不影响其他图页、资产详情、任务、匹配和 Agent 查询中的正式数据。系统需要提供可查看和恢复的隐藏内容入口，避免用户忘记曾经排除过对象。
17. 从当前图页删除节点后，节点实例进入隐藏状态并保留本地标题、备注、层级关系和原布局信息。底层资产与来源关系在隐藏期间继续更新，恢复后显示最新正式资料，而不是恢复一份过时副本。
18. 用户可以通过删除后立即撤销，或从“隐藏内容”中查找并恢复原节点实例。普通图谱搜索不显示隐藏节点。用户明确在其他层级或上下文再次添加同一正式资产时，允许创建新的独立节点实例；资产选择流程可以提示存在隐藏实例并提供恢复入口，但不能静默恢复、阻止合理的重复展示或把隐藏实例混入普通搜索结果。
19. 恢复时优先回到删除前的位置和层级；原位置已经被占用或父节点不存在时，在相关节点附近使用稳定规则放置，并说明位置发生了调整。
20. **已确认：自动加入节点的来源关系结束、失效或被删除后，关系连线、分数和状态立即退出当前有效展示。** 不能为了保留画布外观继续显示已经失效的关系。
21. 如果该节点完全由失效关系自动加入，用户没有编辑标题或备注、没有主动移动或调整层级，也没有其他有效关系，系统自动将节点移入当前图页的隐藏内容，并记录移除原因。
22. 如果用户已经编辑、移动、调整层级或添加备注，或者节点仍有其他有效关系，系统保留节点，只移除失效关系，并使用短期“原关联已失效”标记说明变化。用户可以继续保留或主动删除该节点。
23. 历史版本和变化记录继续保留节点当时的加入依据、关系状态及失效时间；自动隐藏不能抹去用户追溯来源的能力。
24. **已确认：同一正式资产或关系出现在一份知识图谱的多个图页时，所有符合各自内容范围的图页都需要同步更新，不只更新用户当前打开或最近访问的图页。**
25. 每个图页继续独立保存节点实例、布局、层级、隐藏和排除规则。同一来源变化可以在不同图页产生不同展示结果，但不能出现来源状态不一致。
26. 同一次变化影响多个图页时，通知在知识图谱层面聚合说明受影响图页和变化数量；用户从通知进入后可以逐页定位，不为每个图页重复发送一条通知。

#### 证据充分与待确认变化的处理

1. **已确认：自动更新的前提是变化已有足够证据，或者已经由用户明确确认，并且通过身份、结构、权限、重复和数据完整性门禁。** 用户在原业务入口完成的人工新增或修改可以作为明确确认，不要求所有关系都必须额外提供公开网络证据。
2. 证据充分且已合法写入来源资产或共享关系的数据，直接同步为当前图谱中的正式节点、关系和状态，不再要求用户重复确认。图上使用短期“已更新”标记说明变化来源。
3. Agent 推断、公开信息线索、身份疑似匹配或证据不足的变化不能直接成为正式图谱内容。系统在图谱中显示可区分的“待确认”节点或关系标记，并保留判断依据、证据、来源和受影响范围。
4. 待确认变化属于分析展示层，不参与正式统计、匹配、联系路径或其他 Agent 的已确认事实查询；用户确认后，先写入对应的数据所有者，再按实时同步规则转为正式图谱内容。用户拒绝后移除待确认展示并保留处理记录。
5. 待确认变化需要同时进入通知和待处理事项，通知负责让用户及时知道发生了什么，待处理事项负责后续处理和回到对应图谱位置。两者引用同一条事项，不能重复生成两份状态。
6. 同一资产、关系或同一分析批次产生多个相近问题时，通知和待处理事项需要聚合并去重，例如显示“具身智能知识图谱有 6 项关系待确认”，避免逐条通知造成信息泛滥。
7. 身份冲突、证据失效、来源被删除或自动同步失败等异常同样使用图上标记、通知和待处理事项联动；问题解决后，三个入口的状态和数量同步更新。
8. **已确认：普通字段刷新和低影响数值变化只更新图谱并写入变化历史，不发送用户通知。** 例如职位文字修正或不会改变排序、建议和业务判断的小幅匹配分数变化，不应打断用户。
9. 新增或移除节点、关键关系变化、来源失效，以及会改变排序、建议动作或业务判断的重要变化，需要发送聚合通知；疑似关系、身份冲突、同步失败等需要用户介入的问题，还要同时创建待处理事项。
10. 同一知识图谱在短时间内发生的同类变化合并为一条通知，并显示变化数量、影响图页和主要对象。具体聚合时间及重要变化阈值在详细设计和技术方案中结合业务场景确定，不在当前原则中写死。
11. 通知被合并后仍保留逐项变化记录和定位能力，用户可以从聚合通知进入对应图页、节点或关系，不能因为聚合而丢失可解释性。

#### 节点操作

1. 新增根节点、子节点和同级节点。
2. 编辑节点显示名称和本地备注。
3. 拖动排序、改变主要父节点、在图页之间移动。
4. 折叠、展开、聚焦和定位节点。
5. 删除节点实例，以及使用撤销恢复误操作。
6. 关联、取消关联或更换正式资产；一个节点允许零个或多个资产关联。
7. 从节点打开统一节点详情，再进入具体资产详情。
8. 从自由节点创建人物线索、候选人、公司或其他正式资产，并完成查重和门禁（已确认；创建交互见 5.4）。
9. 多选节点后执行有限批量操作，包括整体移动画布位置、移动到其他图页、批量挂到新的父节点、移动包含父节点的完整分支，以及删除节点实例（已确认）。
10. 查看当前图页已隐藏的节点和关系，并恢复需要重新参与自动同步的内容。

#### 关系操作

1. 通过调整层级建立或改变主要父子关系。
2. 新建、编辑和删除交叉关系。
3. 交叉关系可以填写固定关系类型、方向、适用范围、时间、说明和证据；“其他关系”只保存当前说明，不新增系统关系类型。
4. 查看关系详情和证据。
5. 将图谱本地关系提交为共享关系建议，或把已有共享关系引用到当前图谱。
6. 处理关系冲突、身份待确认、证据失效和共享关系变化。
7. 查看来源业务关联的来源资产、当前状态和变化历史；需要修改时进入对应候选人、岗位、公司、论文或专利的原业务入口，不能在知识图谱中改写一份复制数据。
8. 查看前同事、共同作者、共同发明人和人才流动等来源派生关系的计算依据；需要纠正时修改或核实任职、论文作者、专利发明人等来源记录，不能直接改写派生结果。

#### 画布视图操作

1. 平移、缩放、适应画布、回到当前节点和查看缩略导航。
2. 拖动节点、调整层级和建立受控连线。
3. 搜索并定位节点，按资产类型、关联状态或关系类型筛选。
4. 折叠和展开子树，对大图进行渐进加载或局部聚焦。
5. 使用自动布局整理当前分支或当前图页，同时保留撤销能力。

#### 层级表格视图操作

1. 根据最大可见层级动态生成层级列，并按父子结构自动合并单元格。
2. 在单元格中编辑节点名称、新增节点、调整层级和拖动排序。
3. 折叠或展开层级，搜索和筛选节点。
4. 调整列宽并记住偏好；不允许任意合并单元格。
5. 查看节点关联资产摘要、交叉关系摘要和节点详情。
6. 从表格执行与画布一致的节点移动、删除、关联和撤销操作。

#### Agent 操作

1. 从知识图谱内要求 Agent 生成或更新图页，或者从全局任务要求 Agent 分析和更新一份已有知识图谱；Agent 不能直接创建新的顶层图谱。
2. 指定整份图谱、某个图页、某个分支或选中节点作为处理范围。
3. Agent 读取图谱、正式资产、共享关系、来源业务关联、来源派生关系和允许使用的公开信息，返回分析或变更建议。
4. 按统一授权模式预览、确认或自动应用变更批次。
5. 查看 Agent 修改的节点、关系、资产关联、证据和未完成范围。
6. 对 Agent 结果继续用自然语言提出修正，并形成新的变更批次。

#### 图谱内 Agent 操作与全局任务的关系

1. **已确认：用户从知识图谱内启动 Agent 生成或更新图页时，该运行归属于图谱内 AI 操作，不进入全局任务列表。**
2. 图谱内 AI 操作复用全局任务相同的对话、执行计划、运行进度、授权、检查点、异常恢复和结果查看组件，不建设一套简化 Agent 交互。
3. 图谱内 AI 操作记录保存在知识图谱的“相关操作”中，用户可以查看历史、继续对话、恢复运行和定位该次生成的变更版本。
4. 用户从全局“新建任务”要求 Agent 分析或更新知识图谱时，该运行作为正式任务显示在任务列表，并关联对应知识图谱。
5. 两个入口使用同一套 Agent 能力、数据读取范围、授权模式和 Hunter 写入门禁；区别仅在用户发起位置和记录归属。
6. 图谱内 AI 操作和全局任务不能因为归属不同而重复执行同一变更。每次写入使用唯一变更批次，并在图谱历史中统一显示。

#### 图谱内 AI 协作工作区布局

1. **已确认：图谱内 Agent 操作使用与全局任务同构的全屏 AI 协作工作区，不使用普通 Modal，也不默认打开新的浏览器 Tab。**
2. 左侧承载对话、执行计划、运行状态、授权选择、用户输入和可读的过程记录；右侧以更大空间显示当前知识图谱的画布或层级表格。
3. Agent 的新增、移动、关联和关系建议先在右侧显示为变更预览，并明确区分尚未写入、已经确认和自动执行完成的内容。
4. 点击对话中的节点、关系、证据或变更引用时，右侧自动定位并高亮对应内容；点击图谱中的待处理变化时，左侧定位到对应说明和操作上下文。
5. 对话区域可以收起，使图谱恢复最大工作空间；再次展开时保留原会话位置、执行计划和当前选中对象。
6. 用户退出协作模式后返回普通知识图谱详情，本次会话保留在“相关操作”中，并关联对应变更批次和图谱版本。
7. Agent 过程展示面向业务用户，包括执行计划、正在处理的对象、已完成步骤、来源、阶段性产物、重试、错误和等待用户事项；不直接展示原始工具事件、内部命令或模型隐藏推理。

#### 统一资产内 AI 协作工作区（暂定，待原型验证）

1. **暂定：图谱内 AI 协作工作区的交互模式可以推广到候选人、岗位、公司、论文、专利等其他资产详情中的 AI 功能。**
2. 各资产复用同一套全屏协作外壳、对话、执行计划、进度、授权、异常恢复和历史记录；右侧工作区根据资产类型展示不同内容，不机械复用图谱画布。
3. 候选人右侧主要显示字段变化、资料版本和证据；岗位显示 JD 与岗位解析建议；公司显示调研草稿和证据；论文、专利显示解析结果与人物身份；生成文件类操作显示可在线预览和下载的最新产物。
4. 从资产详情启动时，该运行归属于资产内 AI 操作，不进入全局任务列表；从全局“新建任务”启动时才形成任务。两者使用同一执行与写入门禁。
5. 所有过程展示都使用业务可读状态，不展示模型隐藏推理、原始工具事件或内部命令。
6. 该规则必须先制作跨资产高保真原型，至少验证图谱生成或更新、候选人补全、岗位解析、公司调研和文件生成场景，再决定是否替换当前资产 AI 交互。
7. 如果原型验证发现工作区过重、资产内操作难以理解或影响现有高频流程，可以回滚到本节记录的改造前原型基线，不强制推广。

7. 从历史版本恢复图谱时，不恢复已经被修改、合并、删除或失效的来源数据。恢复动作只重建图谱本地结构和引用配置，当前视图继续遵循最新来源状态。

### 5.3 画布视图详细操作规范（讨论草案）

画布是知识图谱的主要关系编辑视图，但不是通用白板。它允许用户自由安排节点位置、查看层级和建立受控关系，不提供自由绘画、任意形状、旋转文字、装饰贴纸或无业务含义的图形组件。

> 当前状态：“位置自由、结构受控”的布局原则已确认；其余鼠标、键盘、触控、节点、连线和大图交互作为后续原型的设计基线，需通过可交互原型继续验收。

#### 视口与工作区

1. 画布占据知识图谱页面的主要工作区；图页导航、视图切换、搜索和缩放工具固定在工作区边缘，不随画布内容移动。
2. 画布使用可持续向四周平移的大范围工作区，不用固定页面尺寸截断节点。
3. 支持鼠标滚轮、触控板手势、工具栏按钮和键盘快捷键缩放。
4. 缩放以鼠标指针或触控中心为焦点，避免缩放后用户失去正在查看的节点。
5. 工具栏提供放大、缩小、恢复 100%、适应全部内容和聚焦选中内容。
6. 建议阶段一缩放范围为 25%—200%；具体边界在原型中验证，低于可读范围时进入语义缩放，不显示无法辨认的小字。
7. **已确认：每个图页分别保存上次的画布位置、缩放比例和展开状态。** 用户切换图页、离开知识图谱再返回或刷新页面时，恢复对应图页上次的视口，不自动重置为全图自适应。
8. 通过搜索结果进入节点时，搜索定位可以临时覆盖该图页的当前视口并将目标居中；用户后续平移或缩放形成的新视口继续作为该图页的最近状态保存。

#### 平移、框选与选择

1. 单击空白区域取消当前选择。
2. 默认选择模式下，按住左键拖动空白区域进行框选，不同时承担平移，避免框选和平移产生歧义。
3. 按住空格并拖动左键、使用鼠标中键拖动，或使用触控板双指移动来平移画布。
4. 工具栏提供“抓手”模式；启用后左键拖动空白区域用于平移，适合触控设备或不熟悉快捷键的用户。
5. 单击节点或连线选中单个对象；按住 `Shift` 或 `Command / Ctrl` 点击可以增加或移除多选对象。
6. 框选只选择完整或主要区域落入选择框的节点；跨越选择框的关系线不会因为经过选区而被误选。
7. `Esc` 取消选择或关闭当前轻量浮层，不丢失已经自动保存的修改。

#### 左键、双击与右键

1. 左键单击节点：选中节点并显示轻量操作入口；再次打开详情操作后显示统一节点详情面板。
2. 左键拖动节点：自由调整节点在当前图页中的位置，不改变主要父节点。
3. 拖动节点到明确显示的层级挂载区域，或使用“调整层级”操作时，才改变主要父节点。
4. 双击节点标题：进入标题行内编辑；按 `Enter` 保存，按 `Esc` 取消本次输入。
5. 双击画布空白区域：在该位置创建新的根节点，并立即进入标题编辑。
6. 右键节点：显示节点上下文菜单，包括新增子节点、增加同级节点、编辑、查看详情、关联资产、建立关系、调整层级、移动到其他图页和删除。
7. 右键空白区域：显示新建根节点、粘贴受支持内容、适应全部内容和自动布局等画布操作。
8. 右键连线：显示查看关系、编辑关系、查看证据和删除关系。
9. 任何只在右键菜单出现的重要操作，都必须同时在节点详情、工具栏或键盘路径中提供，避免右键成为唯一入口。
10. iPad 和移动 Web 使用长按打开对应上下文菜单，不要求外接鼠标。

#### 布局自由度

1. **已确认：节点的画布坐标允许自由拖动，用户可以按照自己的认知安排空间位置。**
2. **已确认：视觉位置和主要父子层级分开保存。移动节点位置不会自动改变层级，也不会删除交叉关系。**
3. 新增节点时由系统根据主要父节点和当前布局提供合理初始位置，用户可以继续自由调整。
4. **已确认：提供“自动整理当前分支”和“自动整理当前图页”，用于处理重叠、过密和导入后布局混乱。**
5. **已确认：自动整理只改变画布坐标和连线路径，不改变节点文字、父子层级、资产关联或关系事实。**
6. **已确认：自动整理完成后可以撤销；手工调整后的布局不会被后台静默重新排列。**
7. 工具栏提供明确的“一键整理”主入口，默认整理当前图页；用户在选中分支后使用节点或右键菜单时，只整理当前分支。操作不使用必须填写的配置表单。
8. 一次自动加入多个节点时，系统自动执行局部整理并保留现有主体布局；这与用户主动触发的整页“一键整理”是两种不同操作。
9. 节点允许在规定的最小和最大宽度内调整宽度，节点高度根据内容自动变化；不支持任意拉伸高度、旋转或改变为任意形状。

#### 节点显示内容

1. 节点必须显示本地标题；没有标题的节点不能完成创建。
2. 节点标题、备注摘要、关系说明和其他可变长度文字在任何缩放比例下都不能撑破节点或覆盖其他内容。超过当前可用宽度或规定行数后截断，并使用产品自定义 Tooltip 查看完整内容；不使用浏览器原生 Tooltip。
3. 关联正式资产时，节点显示资产类型、主要名称和必要状态；关联多个资产时显示主要部分和 `+N`，完整内容在节点详情中查看。
4. 节点显示可折叠子节点数量、交叉关系数量，以及身份冲突、关联资产已删除、证据失效或待审核变化等需要处理的状态。
5. 节点不直接堆叠手机、邮箱、完整经历、完整公司资料等大量敏感或长文本；这些内容在节点详情或正式资产详情中查看。
6. 根节点、普通节点、选中节点和需要处理的节点可以有清晰层级差异，但不通过大量不同形状制造新的节点类型。
7. **已确认：缩放较小时使用语义缩放。** 优先保留标题、资产类型和风险状态，逐步隐藏备注、关系数量和次要信息；恢复缩放后自动显示完整层级。语义缩放只改变信息层级，不改变文字截断和 Tooltip 规则。

#### 节点创建、编辑和删除

1. 支持通过空白区域双击、右键菜单、工具栏、节点菜单和键盘操作新增根节点、子节点或同级节点。
2. 新建节点默认只创建图谱本地内容，不要求立即选择节点类型或关联正式资产。
3. 节点标题支持行内快速编辑；备注、多个资产关联、来源和关系在节点详情面板中编辑。
4. 拖动排序、改变主要父节点和移动到其他图页时，界面必须显示明确插入位置和影响范围。
5. 删除有子节点的节点时，用户必须选择同时删除当前子树，或把直接子节点提升到被删节点的父级；不能静默处理。
6. 删除存在交叉关系的节点时说明受影响关系数量；只删除当前节点实例，不删除正式资产和共享关系事实。
7. 删除后可以立即撤销；图谱节点实例不单独进入全局资产回收站，知识图谱整体删除仍使用统一回收站。

#### 父子连线与交叉关系

1. 主要父子关系由系统生成层级连线，用户不能把父子连线改成没有含义的装饰线。
2. 父子连线随着节点移动自动重新寻路，避免穿过节点；用户不需要手工维护每段路径。
3. 节点提供受控的关系连接点。用户从连接点拖到目标节点后，选择关系类型、方向、适用范围、时间、说明和证据。
4. 用户可以先创建图谱本地交叉关系；提交为共享关系时再进入证据、身份和冲突门禁。
5. 交叉关系显示方向和简短标签；标签过长时截断，完整内容在关系详情中查看。
6. 父子关系、图谱本地交叉关系、已确认共享关系和待确认关系使用可区分但克制的线型和状态，不只依赖颜色。
7. 节点移动不会断开有效关系；关系端点始终跟随节点。
8. 用户可以选中关系后编辑说明、范围、时间和证据，或从当前图页移除该关系显示。
9. 从当前图页移除共享关系只取消本图页引用；删除共享关系事实需要进入关系影响说明和对应门禁。

#### 图谱本地关系与共享关系的写入规则

1. **已确认：用户手动创建关系时，如果两端都已关联正式资产，并且用户选择了允许从图谱维护的共享关系类型、方向和适用范围，保存后直接形成共享关系，同时由当前知识图谱引用。** 用户本次明确保存即视为对该关系的人工确认，不再增加一次重复审核。
2. 任一端仍是自由节点，或者关系使用“其他关系”，该关系只保存在当前知识图谱，不进入共享关系层。
3. Agent 生成或推断的关系继续遵守当前任务的授权模式、证据要求和 Hunter 强制门禁；不能因为两端已经关联正式资产就绕过确认或自动执行规则。
4. 自由节点后续关联为正式资产时，系统可以提示用户把满足条件的图谱本地关系升级为共享关系，但不能静默升级。
5. 共享关系需要保留方向、适用范围、时间、来源和有效状态，避免把只在特定业务或时间范围成立的关系解释成永久全局事实。
6. 当前知识图谱删除节点或移除关系显示时，只取消当前图谱引用；共享关系本身的删除使用独立影响说明和门禁。
7. 论文作者、专利发明人、岗位与公司、人岗匹配和岗位流程等来源业务关联不属于可从图谱直接创建的共享关系。用户在图谱中选择这类关系时，系统进入对应来源资产的新增或编辑流程；保存后再由实时同步返回图谱，避免产生两份所有者不同的数据。
8. 前同事、共同作者、共同发明人和人才流动等由来源记录推导出的结果在图谱中只读展示，用户需要纠正时进入对应来源记录。用户有独立证据或明确知情时，可以从关系创建器补充允许人工维护的同类共享关系；系统先做关系去重，命中已有派生结果时补充人工证据并合并展示，不能制造重复关系。

#### 关系重复、冲突与删除

1. **已确认：同一对正式资产之间，如果关系类型、方向相同，并且适用范围和时间重叠，系统复用已有共享关系，只补充新的来源和证据，不重复创建关系。**
2. 看似矛盾但适用范围或时间不同的关系可以同时保留。例如，两家公司可以在某个业务领域合作，同时在另一个领域竞争。
3. 如果两条关系真正冲突且无法通过适用范围或时间解释，系统不能直接覆盖已有关系，需要进入关系对比确认。
4. 冲突确认允许用户更新原关系、在补充范围或时间后保留两条，或者只把新关系保存在当前知识图谱。
5. 从当前知识图谱删除共享关系只取消当前图谱引用。用户要求删除共享关系事实时，需要显示受影响的资产、知识图谱和仍在引用该关系的业务结果。
6. 删除共享关系不删除两端资产，也不自动删除引用该关系形成的历史任务结果；历史结果保留当时使用的证据和版本说明。

#### 多选和批量操作

1. 支持框选、`Shift` 点击和 `Command / Ctrl` 点击选择多个节点。
2. 多选节点可以整体移动画布位置，并保持节点之间的相对位置。
3. **已确认：阶段一支持批量移动到其他图页、批量删除节点实例和批量挂到同一主要父节点。**
4. **已确认：批量移动允许包含父节点。** 选中父节点并移动完整分支时，其下级节点保持原有层级和相对结构；如果父节点和其子节点同时被选中，系统按一个分支处理，不能重复移动或产生循环层级。
5. 批量调整父级时显示新的挂载位置、涉及节点和受影响分支数量；不能把节点挂到自身或其后代节点下。
6. 阶段一不支持批量创建正式资产、批量确认人物身份或批量把本地关系写成共享关系，避免绕过逐项门禁。
7. 批量操作前显示对象数量和影响；存在不可操作对象时说明跳过项，不能让部分失败没有反馈。
8. 批量移动、调整层级和删除完成后均可整体撤销，不要求用户逐节点恢复。

#### 键盘操作

1. `Enter` 在当前节点后增加同级节点；`Tab` 增加或调整为子节点；`Shift + Tab` 提升一级。
2. 方向键在相邻可见节点之间移动选择；输入状态下方向键只移动光标，不触发节点跳转。
3. `Delete / Backspace` 触发删除确认；不会在文本编辑时误删节点。
4. `Command / Ctrl + Z` 撤销，`Command / Ctrl + Shift + Z` 或平台标准组合重做。
5. `Command / Ctrl + F` 打开当前知识图谱搜索并定位匹配节点。
6. `Command / Ctrl + +`、`Command / Ctrl + -` 和 `Command / Ctrl + 0` 控制缩放。
7. 快捷键是效率增强，不是唯一操作路径；所有核心能力都需要可见操作入口和自定义 Tooltip。

#### 搜索、筛选和大图处理

1. **已确认：知识图谱提供节点搜索，搜索到的目标会自动展开必要路径、移动到屏幕中心并高亮显示。** 搜索定位不能只给出文字结果而让用户自行在大图中寻找。
2. 搜索覆盖节点标题、备注、关联资产名称和允许搜索的关系说明。结果显示匹配文字、所在图页和完整层级路径，帮助用户区分同名节点。
3. **已确认：搜索默认覆盖整份知识图谱的全部图页。** 搜索结果以下拉列表展示全部匹配，当前图页的结果优先排列；用户不需要先切换图页或手动选择搜索范围。
4. 搜索结果的主要信息按照“图页名 + 节点名”显示，并补充完整层级路径和命中文字。多个图页存在同名节点时，用户能够根据图页和路径判断目标，不只看到一组无法区分的同名结果。
5. **已确认：普通搜索只返回当前实际存在于图页中的节点，不返回已经被用户删除并进入“隐藏内容”的节点。** 搜索遵循可见即所得，避免用户定位到画布中不存在的内容；隐藏节点只能从专门的“隐藏内容”入口查看和恢复。
6. 用户可以使用键盘上下键切换结果并按 `Enter` 定位，也可以点击结果定位；存在多个结果时支持查看上一个和下一个匹配项。交互沿用当前 Hunter 已验证的搜索结果选择方式。
7. 选择其他图页的结果后，系统自动切换到对应图页，只展开目标节点的必要祖先路径，并将目标移动到屏幕中心。目标使用清晰但短暂的高亮，不自动打开编辑面板，也不改变当前选中内容之外的数据。
8. 节点支持单独展开和收起；工具栏提供全部展开和全部收起。全部收起时保留根节点和必要的一级结构，不能把画布变成没有上下文的空白区域。
9. 展开和收起状态按图页保存。切换画布与层级表格时，两种视图读取同一节点可见范围，但可以分别保存适合各自展示方式的展开偏好。
10. 画布支持鼠标滚轮、触控板手势和工具栏进行放大、缩小，提供恢复 `100%`、自适应全部内容和聚焦选中内容。缩放以鼠标或触控中心为焦点，避免操作后丢失目标。
11. 不提供固定节点能力。一键整理当前图页或当前分支时，可以移动整理范围内的所有节点；整理结果支持撤销，用户可以在整理后继续手动调整。
12. 支持按图页、资产类型、关联状态、关系类型和待处理状态筛选。
13. 筛选只改变当前显示，不删除节点或改变图谱结构；页面明确显示当前筛选条件。
14. 大图默认折叠部分深层子树，并提供缩略导航、搜索定位和“只看当前分支”。
15. 节点和关系按可见范围渐进加载，但搜索数量、子节点数量和关系数量必须反映完整数据，不能只统计已渲染部分。
16. **已确认：任何缩放比例下，过长文字都需要截断并提供产品自定义 Tooltip。** 缩小画布时不能通过无限缩小字体塞入全部内容；放大后可以恢复更多信息，但仍遵循节点宽度、最大行数和防溢出规则。
17. 普通进入图页时恢复该图页最近保存的视口；搜索定位、聚焦选中和自适应全部内容属于用户主动触发的临时定位行为，不改变其他图页的视口状态。

#### 触控与响应式

1. iPad 使用单击选择、拖动节点、双指平移和缩放、长按打开上下文菜单。
2. 移动 Web 仍可查看、搜索、编辑节点、建立关系和处理审核；画布使用全屏工作区和底部操作面板，不能只提供只读缩略图。
3. 触控设备的连接点、拖动目标和操作按钮需要满足可点击尺寸，不能直接缩小桌面控件。
4. 拖动过程中自动滚动画布边缘，避免节点无法移动到当前视口之外。

#### 明确不支持

1. 自由画笔、荧光笔、便签、贴纸、任意图形和任意颜色装饰。
2. 节点旋转、任意高度拉伸和无语义的自由线条。
3. 在画布中直接编辑正式资产的全部资料。
4. 通过拖动或右键绕过身份、重复、关系证据和共享数据写入门禁。
5. 因自动布局、筛选或视图切换静默改变图谱底层内容。

### 5.4 从自由节点创建关联资产（阶段一暂定）

#### 产品规则

1. 用户可以从自由节点创建与该节点关联的正式资产，包括人物线索、候选人、公司及其他允许从图谱创建的资产。
2. 系统可以使用节点标题、备注、来源和已关联内容预填资产草稿，但不能因为来自图谱而绕过资产自身的必填、查重、身份确认和写入门禁。
3. 候选人资料不足以满足正式候选人创建条件时，只能创建人物线索；后续由用户确认或按已授权规则转为正式候选人。
4. 创建成功后保留原节点，只增加节点与正式资产的关联，不用正式资产替换或删除用户原有的节点文字、备注和布局。
5. 如果查重发现疑似已有资产，优先让用户关联已有资产或进入统一合并审核，不重复创建。

#### 阶段一暂定交互

1. 用户在节点详情或节点上下文菜单中选择“创建关联资产”，再选择要创建的资产类型。
2. 默认在当前应用内进入**全屏创建工作区**，并使用独立路由承载完整资产创建流程；不使用空间不足的普通 Modal，也不默认打开新的浏览器 Tab。
3. 创建页顶部保留“来自知识图谱 / 图页 / 节点”的来源上下文和返回入口。取消或完成后，返回原知识图谱、原图页、原画布视口和原选中节点。
4. 创建页复用对应资产已经确定的新建、查重和异常处理交互，不建设一套仅供知识图谱使用的简化表单。
5. 创建成功后自动刷新节点关联，并在原节点附近给出局部成功反馈；创建失败或取消时不改变节点和已有关系。
6. 桌面端允许用户通过浏览器标准操作主动在新 Tab 打开创建页，但这不是默认路径；移动 Web 始终使用应用内全屏创建页，避免多 Tab 导致上下文丢失。

采用这一交互的原因是：正式资产表单和查重流程通常较长，普通 Modal 工作空间不足；默认新开浏览器 Tab 又会割裂创建结果与原节点的状态同步，并在移动端造成明显负担。应用内全屏创建工作区同时保留完整创建能力和明确返回路径。

该交互将在高保真原型中验证。若完整资产创建流程仍造成明显上下文割裂，再调整全屏工作区的返回和状态保持方式；不因此退回空间不足的普通 Modal。

已确认命名规则：

1. 该类正式业务资产命名为“知识图谱”。
2. “人才摸排”继续表示用户发起的任务或业务过程，不作为资产名称。
3. 每份知识图谱使用用户定义的具体名称，例如“具身智能产业链”“阿里达摩院组织架构”或“VLA 核心人才”。
4. 历史文档和原型中的“人才地图”“人才版图”需要在后续正式更新阶段按语义替换，当前不做无上下文的机械批量替换。

## 六、当前 Hunter 真实使用与重构建议

### 6.1 代码和历史样本说明的问题

当前 Hunter 最初使用“部门 / 人物”强类型节点，但真实的 22 份地图、1857 个节点已经证明用户不会按该分类维护。样本同时包含组织架构、人才追踪、招聘需求、产品和业务图谱，约 45% 的节点不能可靠归为部门或人物。

Hunter 在 v0.10.0 已经据此改为“多根自由文本树 + 人物关联”：

1. 节点只要求自由文本或人物关联至少存在一项，不强制节点类型。
2. 同一份地图允许多个一级根节点，并通过 Tab 分别查看。
3. 人名可以关联正式候选人，也可以保留为待确认或未关联的人物文本。
4. 导入优先保留用户原始树结构和文字，而不是强制解释成统一业务类型；历史实现中的导出能力不自动成为 SaaS 阶段一范围。

这说明用户偏离原始设计并非偶然误操作，而是“树和思维导图”本身给用户提供了一个系统中缺失的通用关系整理空间。

### 6.2 不建议采用的两个极端

1. **重新限制为组织架构图**：会再次丢失上下游、产品方向、人物关系和用户自己的整理方式，重复当前 Hunter 已经验证失败的强类型设计。
2. **升级成完全自由的通用白板**：会引入任意图形、连线、排版、协作和文件兼容等巨大范围，同时自由文本无法直接支持 Agent 查询、岗位找人和关系复用。

### 6.3 已确认方向：知识图谱与结构化事实并存

知识图谱定义为：**猎头围绕一个自定范围，整理公司、组织、人物、方向和关系的正式业务资产；资产中可以包含多个图页，每个图页以受控自由画布或层级表格展示同一份页面级内容。**

该定义不要求一份知识图谱必须覆盖多个公司，也不要求只能表示组织架构。它可以用于单家公司组织、某个技术领域、上下游生态、人物关系或其他猎头认为有价值的专题。

产品采用三层内容：

1. **图谱本地内容**：自由文本节点、分组、层级、顺序、布局、备注和用户自己的解释，只属于当前图页或知识图谱。
2. **共享结构化内容**：节点可以不关联资产，也可以关联一个或多个与当前节点有关的公司、候选人、人物线索、联系人、招聘机会、岗位、论文或专利；连线可以关联已经确认的共享关系。关联后由共享资产和关系提供最新资料，但不会覆盖用户节点文字和布局。
3. **来源业务关联及其派生关系**：人岗匹配、岗位流程、岗位归属、论文作者等关系由候选人、岗位、公司、论文和专利等来源资产管理；前同事、共同作者、共同发明人和人才流动等关系由这些来源记录派生。知识图谱按当前范围实时引用和展示，不复制为独立关系事实。

因此：

1. 用户仍然可以导入和维护不规则的思维导图，不必先给每个节点分类。
2. Agent 可以建议识别公司、人物和关系，但未确认内容只作为建议，不直接成为共享事实。
3. 图谱中的“业务方向”“产品线”“关键岗位”“空缺”等内容可以继续作为自由节点，不需要全部升级成正式资产。
4. 已关联的公司、人物和关系可以被岗位人才梳理、联系路径、公司详情和 Agent 查询复用。
5. 同一共享事实可以出现在多份知识图谱中；每份图谱保留自己的范围、图页、布局、备注和业务判断。
6. 阶段一通过画布和层级表格承载组织、公司生态、人物关系和自由树等内容，不建设任意图形白板，也不预设额外固定视图类型。
7. 招聘机会、岗位推进、匹配结果和沟通记录继续由正式资产维护。知识图谱可以实时引用它们，但不复制完整业务状态；来源变化后对应图谱自动同步。

知识图谱在用户创建顶层图谱后，采用以下统一内容维护路径：

1. **文件导入图页**：用户先创建知识图谱，再从图谱内导入图页。导入优先保留原始层级、文字、顺序和可识别的关系，不要求导入前完成资产分类。
2. **人工维护**：用户可以创建节点、修改文字、拖动排序、调整层级、建立连线、添加备注和选择资产关联。
3. **Agent 生成或更新**：Agent 可以根据用户要求、公开资料和工作空间内已有资产整理或更新图页；图谱本地内容的变化、共享事实写入和来源业务关联的实时引用必须分别处理。

数据所有权采用以下规则：

1. 节点文字、层级、顺序、布局、备注和图谱内的解释属于对应图页或知识图谱，资产资料变化不能覆盖这些内容。
2. 节点关联的正式资产继续由对应资产管理。资产更新后，图谱中引用的姓名、职位、公司、状态等展示自动刷新，但图谱本地文字和布局保持不变。
3. 图谱内的自由连线可以只作为当前图页的表达；只有经过识别、确认并满足写入规则的关系，才进入可被其他页面和 Agent 复用的共享关系层。
4. Agent 可以读取整份知识图谱作为任务和查询输入，也可以提出节点识别、资产关联和关系确认建议；身份不明确、关系冲突或会影响共享数据时必须进入确认流程。
5. 用户和 Agent 都可以维护图页，但 Agent 的正式写入仍受统一授权模式和 Hunter 强制门禁约束。
6. 共享关系和来源业务关联一旦在各自的数据所有者中合法更新，来源派生关系随之重新计算，所有引用这些内容的当前图谱自动同步；同步不是 Agent 写入，不再次触发授权。只有新建或修改来源事实本身时才执行对应门禁。

### 6.4 产品判断

用户行为说明知识图谱的核心价值不只是“画组织架构”，而是**用空间和层级组织尚未完全结构化的猎头知识**。SaaS 版应保留这一价值，同时通过资产关联、关系确认和 Agent 提取，把有复用价值的内容逐步结构化。

阶段一不应要求用户在创建图谱时选择严格类型。用户先创建空白知识图谱，再直接人工整理、导入图页，或要求 Agent 在该图谱内生成初稿或增量更新；系统根据内容提供合适的初始视图，用户后续仍可增加其他受控视图。

最终产品原则可以概括为：**自由整理、按需关联、逐步结构化、可由 Agent 理解和维护。**

### 6.5 已确认：关系主题拆分为独立知识图谱

1. 公司关系、候选人关系、岗位重点人才、岗位上下游知识和行业上下游知识属于不同整理目标，默认分别创建为独立知识图谱资产，不能为了展示更多场景而全部塞入同一个图谱的多个图页。
2. 图页继续用于同一知识图谱范围内的内容分组、文件导入和人工整理，不用于容纳彼此无关的关系主题。
3. 一次人才摸排任务可以同时产出或更新多个独立知识图谱。用户完成审核后，系统按主题分别写入，并为每个图谱保留独立版本历史。
4. 资产详情中的候选人关系、岗位重点人才等入口，必须直接打开对应的独立知识图谱，不能再跳到一个总图谱中的隐藏图页。
5. 节点图标属于可配置的节点展示属性。新节点默认按节点类型选择图标，用户也可以明确指定公司、人物、岗位、组织或团队、产业或知识、分组或通用关系图标。
6. 画布、搜索结果、层级表格和版本预览统一读取同一节点图标配置，不能在不同页面按场景硬编码成不同图标。
