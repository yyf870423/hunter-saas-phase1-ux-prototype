# 原型阶段四：业务资产产品字段字典

> 2026-08-30 口径更新：用户侧只存在“任务”；历史字段说明中的业务主线、工作或支线任务均按关联任务处理。资产 AI 与运行记录是资产支撑对象，不作为正式任务资产。

> 状态：字段与关系交叉验证通过，已映射到阶段四完整原型；等待人类审批后冻结。
>
> 日期：2026-08-21。
>
> 用途：把已审批业务对象基线转换为阶段四原型可以直接使用的字段组、关系和操作范围。本文描述产品信息结构，不等同于数据库表结构。

## 一、字段分级

每类资产的字段按以下级别管理：

1. **创建必填**：未满足时不能形成正式资产。
2. **核心资料**：详情和编辑长期维护的主要内容。
3. **结构化子记录**：可以独立新增、编辑、排序、失效或追溯。
4. **派生摘要**：由关联关系或系统计算得到，不允许用户直接编辑。
5. **来源与历史**：用于解释和审核，默认不占用主信息区。

## 二、公司

| 字段组   | 内容                                                                                                                  | 规则                                              |
| -------- | --------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------- |
| 创建必填 | 公司名称                                                                                                              | 工作空间内不允许静默创建重复公司                  |
| 分类     | 行业标签                                                                                                              | 使用系统行业体系，多选，最多 5 个                 |
| 公司资料 | 公司简介、融资或上市及市值、公司优势与人才吸引点、一般薪资福利、一般面试流程、Base 地点与业务、其他招聘要求、用户备注 | 长文本支持自然段和列表；用户备注不能被 Agent 覆盖 |
| 名称识别 | 已确认名称变体、平台公司身份、官网或邮箱域名、已确认组织单元                                                          | 用于召回候选关系；不等同于外部原始文本            |
| 来源摘要 | 资料来源、最近更新时间、最近更新方式                                                                                  | Agent 和文件更新形成字段变化建议                  |
| 派生摘要 | 联系人数、招聘机会数、岗位数、任职人才数、推进人数、人才版图数                                                        | 从正式关系实时计算，不直接编辑                    |

**正式关系**：联系人公司关系、招聘机会所属公司、岗位招聘公司、候选人工作经历公司、人才版图公司引用。

**详情 Tab**：公司资料、招聘业务、联系人、任职人才、人才版图、关联任务。

**关键边界**：不设置统一客户状态；不把任意手动关联候选人解释成任职事实；删除公司不删除联系人、岗位、候选人或招聘机会。

## 三、联系人

| 字段组   | 内容                                                                                       | 规则                                                                     |
| -------- | ------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------ |
| 创建必填 | 姓名或明确称呼，加一种联系方式、公开身份依据、已确认公司关系或足以区分身份的来源和角色信息 | 只有姓名或“某公司 HR”不能创建正式联系人                                  |
| 基本资料 | 姓名、所在地区、用户备注                                                                   | 不重复维护候选人的学历、技能和完整经历                                   |
| 类别     | 客户 HR、招聘负责人、投资人、顾问、中间介绍人、行业关系人及自定义类别                      | 多选                                                                     |
| 联系方式 | 手机、邮箱                                                                                 | 阶段一结构化联系方式暂只支持手机和邮箱；保存主要项、状态、来源和核实时间 |
| 公司关系 | 正式公司、原始公司文本、关系类型、职位或角色、当前或历史、起止时间、主要归属               | 零到多条；主要归属只用于默认展示                                         |
| 身份关系 | 可选的同一自然人候选人档案                                                                 | 一对零或一；不代表推荐、认识或负责关系                                   |
| 时间线   | 人工备注、真实沟通                                                                         | 可选关联公司、招聘机会或任务                                             |

**详情 Tab**：联系人资料、跟进与沟通、相关业务。

**关键边界**：不单独维护公开资料链接集合；来源网页仍保留在来源记录；不维护“已联系”“已回复”等人工状态。

## 四、招聘机会

| 字段组   | 内容                                                                   | 规则                                       |
| -------- | ---------------------------------------------------------------------- | ------------------------------------------ |
| 创建必填 | 正式公司、招聘需求摘要、已确认存在需求的依据                           | 只有融资、扩张或招聘传闻时仍属于信号       |
| 核心资料 | 需求摘要、确认依据及来源、相关联系人、预计招聘方向、预计人数、预计时间 | 联系人、人数和时间可缺失                   |
| 状态     | 跟进中、已完成、已关闭                                                 | 关闭需要原因；已完成或已关闭可重新打开     |
| 岗位转换 | 已拆分方向、岗位草稿、已关联正式岗位、未处理方向                       | 一条机会可形成多个岗位；“已转岗位”不是状态 |
| 来源关系 | 来源信号、客户开发任务、创建方式                                       | 保留原始需求，不被岗位覆盖                 |

**详情 Tab**：机会资料、招聘方向、关联任务。

**关键边界**：不复制岗位 JD、岗位分析、匹配和招聘推进；允许关联已有岗位，避免重复创建。

## 五、岗位

| 字段组       | 内容                                                                                               | 规则                                                                                               |
| ------------ | -------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| 创建必填     | 岗位名称、招聘公司原始名称、基本招聘要求                                                           | 基本要求可以是完整 JD 或能够说明目标的几句话                                                       |
| 基础资料     | 正式公司关联、地点、薪资范围、最低工作年限、学历要求及弹性、关键技能、用户备注                     | 公司正式关联可空，原始公司文本必须保留                                                             |
| 招聘状态     | 招聘中、已暂停、已关闭                                                                             | 运行中任务会阻止暂停或关闭；重新开启不自动恢复旧任务                                               |
| JD 版本      | 当前 JD、原始文件或文本、来源、补充说明、确认人、创建时间、历史版本                                | 恢复旧版本形成新的变化记录                                                                         |
| 已确认要求   | 客户或猎头明确确认的事实与约束                                                                     | 只有本层可成为硬筛选和明确匹配约束                                                                 |
| 岗位分析     | 岗位定位、上下游、可迁移背景、对标企业、目标职级、文化偏好、软性和隐性要求、寻访关键词、待核实事项 | 用于理解、扩展和辅助判断，不自动成为硬要求；寻访关键词最多 5 组、每组最多 2 个词，用户可增删和修改 |
| 推进流程配置 | 岗位级阶段名称、顺序、稳定分类、终态含义                                                           | 默认流程为储备、推荐、面试、谈薪、已入职及失败出口；允许岗位级调整                                 |
| 派生摘要     | 匹配人数、储备、推进中、已入职、失败、最近推进、资料与匹配是否过期                                 | 从匹配和推进关系计算                                                                               |

**详情 Tab**：岗位资料、候选人流程、匹配结果、关联任务。

**关键边界**：岗位不保存目标招聘人数、岗位联系人、年龄或性别要求；候选人流程和匹配结果不是岗位字段。

## 六、候选人

| 字段组       | 内容                                                                                             | 规则                                                                                                               |
| ------------ | ------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------ |
| 创建必填     | 姓名，加至少一项可识别身份的信息                                                                 | 只有姓名不能创建正式候选人；资料不足时保留人物线索                                                                 |
| 身份资料     | 中文名、英文名、姓名变体、稳定外部身份                                                           | 工作空间内同一自然人只有一份正式档案                                                                               |
| 当前概览     | 当前公司原文及正式公司关联、当前职位、职级、地点、最高教育、工作年限、出生年份、性别             | 当前任职和最高教育概览不强制与详细经历一致；冲突时标记待核实而不是覆盖；年龄由出生年份动态计算                     |
| 联系方式     | 多个手机和邮箱                                                                                   | 阶段一结构化联系方式统一只支持手机和邮箱；每项含主要标记、状态、来源和核实时间，其他联系结果写入人工备注或沟通记录 |
| 工作经历     | 公司原文、正式公司关联、组织单元原文及可选关联、职位、部门、汇报、团队规模、起止时间、职责和亮点 | 每段独立保存来源和可信状态                                                                                         |
| 教育经历     | 学校、专业、学历、起止时间、补充信息                                                             | 概览与经历允许不一致                                                                                               |
| 项目经历     | 项目名称、角色、时间、说明、成果和相关技能                                                       | 保留原文与来源                                                                                                     |
| 技能与行业   | 标准关键技能、原始技能词、行业标签、软性或管理能力说明                                           | 关键技能暂定最多 12 个，行业最多 5 个                                                                              |
| 求职偏好     | 正在求职、愿意了解机会、暂不考虑、未知；目标方向、地点、薪资、入职时间和其他限制                 | 岗位特定意愿保存在候选人 × 岗位推进                                                                                |
| 候选人摘要   | AI 生成的职业轨迹、核心能力、代表经历和信息缺口                                                  | 标记生成时间和依据版本；资料变化后提示更新                                                                         |
| 收藏夹       | 零到多个多层收藏夹；支持按当前层级新建、重命名和删除                                             | 同层名称不能重复；删除收藏夹及子收藏夹只解除收藏关系，不删除候选人                                                 |
| 简历版本     | 多份简历、当前简历、来源、收到时间、解析状态、解析后的原始文本                                   | 新简历先比较和审核，不直接覆盖档案；原始文本参与搜索和匹配，页面没有对应字段时不强行高亮或伪造展示位置             |
| 其他文件     | 作品集、证明、沟通附件、推荐材料等                                                               | 与简历版本分开，可汇总查看                                                                                         |
| 公开资料链接 | LinkedIn、GitHub、OpenReview、Google Scholar、个人主页及其他                                     | 类型按 URL 自动识别，保存读取和验证状态                                                                            |
| 时间线       | 人工备注、真实沟通、岗位业务事件引用                                                             | 业务事件仍属于候选人 × 岗位推进                                                                                    |

**详情 Tab**：候选人资料、工作与教育、简历与文件、跟进与沟通、岗位匹配与推进、关联信息。

**关键边界**：候选人没有整体招聘状态；匹配分、推荐理由和岗位推进不写入基础档案；合并必须显示处理结果并可撤销。

## 七、候选人 × 岗位推进

该对象是稳定业务关系和过程记录，不是正式资产。

| 字段组   | 内容                                   | 规则                                           |
| -------- | -------------------------------------- | ---------------------------------------------- |
| 唯一关系 | 候选人、岗位                           | 同一候选人与同一岗位始终只有一条推进关系       |
| 当前状态 | 当前岗位级推进阶段、稳定分类、是否终态 | 稳定分类为储备、推进中、已入职、失败           |
| 推进内容 | 单一推进备注、相关文件                 | 阶段一不拆分推荐、面试、Offer 等复杂结构化对象 |
| 阶段历史 | 原阶段、目标阶段、时间、可选转换备注   | 终态可以移回其他阶段，保留全部历史             |
| 来源     | 手动、匹配结果、业务主线或其他正式入口 | 自动进入仍需符合岗位储备授权与门禁             |

## 八、人岗匹配结果

该对象是带版本的判断结果，不是候选人或岗位字段。

| 字段组   | 内容                                                         | 规则                                       |
| -------- | ------------------------------------------------------------ | ------------------------------------------ |
| 对象     | 候选人、岗位                                                 | 同一数据版本可有一次当前有效结果和历史版本 |
| 分数     | 原始分、调整项、最终分、分项解释                             | 代码执行结构校验和确定性调整               |
| 结论     | 推荐理由、优势、风险、建议动作                               | 必须可供猎头做业务判断                     |
| 角色适配 | 岗位角色概括、候选人角色概括、通过或有条件或拒绝、证据、扣分 | LLM 语义判断，代码执行硬门禁和条件折扣     |
| 版本     | 岗位资料版本、候选人资料版本、匹配策略版本                   | 任一相关资料变化后旧结果标记需要更新       |
| 使用状态 | 当前、需要更新、历史、用户从当前视图移除                     | 进入推进后不会因新分降低自动移出           |

## 九、人才版图

| 字段组       | 内容                                                                                       | 规则                                           |
| ------------ | ------------------------------------------------------------------------------------------ | ---------------------------------------------- |
| 创建必填     | 版图名称、摸排目标及已知范围                                                               | 用户可用自然语言、文件和链接输入               |
| 范围         | 使用目的、行业或方向、地区、目标公司、组织、角色、人才、纳入与排除边界、完成标准、范围版本 | 一份版图服务一个连贯业务目标                   |
| 目标清单     | 目标事项、类别、重要性、完成状态、缺失内容、建议动作、预期交付、完成条件                   | 不用未知市场总人数计算虚假覆盖率               |
| 公司与生态   | 正式公司、公司线索、版图分类、重要性、纳入原因、公司间关系                                 | 公司关系带方向、适用范围、时间、来源和可信状态 |
| 组织与方向   | 组织单元、原始组织名、上下级、方向、角色、排序                                             | 公司不维护全局唯一组织树；结构属于当前版图     |
| 人物与人才池 | 目标人才、关系人物、人物线索、候选人或联系人引用、公司组织方向角色、优先级和版图备注       | 敏感资料继续由候选人或联系人档案管理           |
| 人物关系     | 上下级、同事、师生、共同作者、共同发明人、投资、顾问、引荐、好友及自定义关系               | 同一对人物允许多种关系；关系分别保存           |
| 联系路径     | 路径节点、逐段关系、可信状态、来源、阻塞点                                                 | 不能把推断包装为确定关系                       |
| 变化批次     | 新增、修改、失效、删除、影响范围、确认状态和撤销                                           | 冲突更新即使自动授权也必须等待用户             |
| 业务复用     | 关联岗位、业务主线、任务和复用结果                                                         | 只保存引用与用途，不复制业务对象详情           |

**详情 Tab**：摸排概况、公司与生态、组织与方向、人物与关系、更新与审核、相关业务。

**关键边界**：人才版图只有正常和已删除两种普通资产状态；关系图、组织树和学术脉络是同一关系数据的不同投影。

## 十、论文

| 字段组     | 内容                                                                 | 规则                                         |
| ---------- | -------------------------------------------------------------------- | -------------------------------------------- |
| 主要内容   | 原始标题、中文标题、发表年份、发表场所、原始摘要、中文摘要、研究标签 | 翻译不覆盖原文                               |
| 作者署名   | 姓名、顺序、署名机构、稳定作者身份                                   | 原始署名始终保留                             |
| 成果身份   | DOI、OpenAlex Work ID、arXiv ID、OpenReview ID、原始 URL             | 稳定身份优先用于查重                         |
| 指标       | 被引数、指标更新时间                                                 | 不把时效数据描述为永久事实                   |
| 人物关联   | 人物线索或正式候选人、关联依据和状态                                 | 只同名不建立正式关联                         |
| 来源与文件 | 数据来源、导入时间、原始论文文件及附件                               | 每次导入反馈新建、补充、无变化、待确认或失败 |

**详情形态**：连续详情页，不使用业务状态 Tab；展示标题与发表信息、摘要、作者机构、人物关系、人才版图、文件和来源。

## 十一、专利

| 字段组     | 内容                                   | 规则                                                                                                 |
| ---------- | -------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| 主要内容   | 标题、摘要、专利类型、研究标签         | 专利类型使用产品统一中文枚举；导入端将 `invention`、`utility` 等来源值映射后展示，不承担招聘业务状态 |
| 发明人署名 | 发明人、顺序、能够取得的稳定身份       | 原始发明人字符串始终保留                                                                             |
| 权利信息   | 申请人或权利人                         | 作为成果事实，不自动建立公司关系                                                                     |
| 成果身份   | 申请号、公开号、授权号和数据源身份     | 稳定编号优先查重，冲突时禁止自动合并                                                                 |
| 时间       | 申请日、授权日                         | 法律状态只作带来源时间的附带信息                                                                     |
| 人物关联   | 人物线索或正式候选人、关联依据和状态   | 只有姓名一致不建立正式关联                                                                           |
| 来源与文件 | 数据来源、导入时间、原始专利文件及附件 | 导入反馈规则与论文一致                                                                               |

**详情形态**：与论文同层级的连续详情页，展示申请信息、摘要、发明人、人物关系、人才版图、文件和来源。

## 十二、必要支撑对象

### 12.1 人物线索

| 字段组     | 内容                                                           | 规则                                      |
| ---------- | -------------------------------------------------------------- | ----------------------------------------- |
| 原始身份   | 原始姓名、来源中的角色或机构表述                               | 不因只有姓名就创建候选人                  |
| 消歧信息   | 机构、职位、外部身份、论文专利署名、其他可识别信息             | 只保存实际取得的信息，不由 Agent 猜测补齐 |
| 来源上下文 | 论文、专利、人才版图、公开网页、用户输入、业务主线或任务       | 单纯导入成果不批量创建全部作者人物线索    |
| 身份判断   | 可能关联的候选人、判断依据、明确同一或可能同一或不同或证据不足 | 只有通过正式候选人门槛才允许转换          |
| 处理结果   | 待探索、待身份确认、已转候选人、已排除或已失效                 | 不进入正式候选人列表和统计                |

### 12.2 组织单元

| 字段组   | 内容                                         | 规则                                               |
| -------- | -------------------------------------------- | -------------------------------------------------- |
| 身份     | 正式公司、标准名称、已确认名称变体           | 只复用组织单元身份，不维护公司全局组织树           |
| 来源     | 原始组织文本、来源和确认记录                 | 原始文本继续保留在产生它的经历、联系人关系或版图中 |
| 版图关系 | 上下级、方向、角色、人物、适用时间和可信状态 | 归属于具体人才版图，可以在不同版图中不同           |

### 12.3 真实沟通

| 字段组   | 内容                                                          | 规则                                             |
| -------- | ------------------------------------------------------------- | ------------------------------------------------ |
| 参与方   | 发送方、接收方、对应联系人或候选人                            | 同一消息只保存一次                               |
| 消息     | 方向、邮件发送身份、主题、正文、附件、发生时间                | 阶段一系统沟通渠道只设计邮件；其他结果由人工补录 |
| 外部状态 | 发送状态、失败原因、外部消息 ID、会话和回复关系、最近同步时间 | 草稿不是已发生沟通                               |
| 业务关联 | 公司、招聘机会、岗位、业务主线和任务                          | 无法判断时关联待确认，不能复制消息               |

## 十三、来源、证据、文件和变更的共用结构

### 13.1 来源

| 时间     | 观察时间、适用时间和最近核实时间                           |
| 可信状态 | 已验证、用户确认、平台可见、系统推断、待验证、冲突、已失效 |

## 十四、统一关系矩阵

| 关系                  | 基数                           | 正式写入条件                                       | 删除一端后的处理                                                     |
| --------------------- | ------------------------------ | -------------------------------------------------- | -------------------------------------------------------------------- |
| 公司—联系人           | 多对多                         | 公司关系已确认                                     | 解除正式关系，另一端保留                                             |
| 公司—招聘机会         | 一对多                         | 机会必须关联明确公司                               | 公司回收期保留关系；物理清理后机会显示“关联公司已删除”和必要历史名称 |
| 公司—岗位             | 一对多，可空                   | 原始公司文本必有；正式公司关联可后补               | 岗位保留原始公司文本                                                 |
| 公司—候选人工作经历   | 一对多，可空                   | 必须确认某段经历确属该公司                         | 候选人经历原始公司文本保留                                           |
| 联系人—候选人身份     | 一对零或一                     | 强身份或用户确认，不能仅凭姓名                     | 解除身份入口，两份档案独立保留                                       |
| 招聘机会—岗位         | 一对多；岗位最多有一个来源机会 | 拆分新岗位或把尚无来源机会的已有岗位关联到当前机会 | 任一端删除不级联另一端                                               |
| 候选人—岗位推进       | 多对多，中间关系唯一           | 用户操作或通过授权的正式入池命令                   | 删除任一资产时关系随资产进入回收上下文                               |
| 候选人—岗位匹配       | 多对多，多版本结果             | 匹配任务通过输出门禁                               | 旧结果按业务历史保留或随资产清理策略处理                             |
| 论文—人物线索或候选人 | 多对多                         | 稳定身份或多证据确认；只有姓名只能召回             | 成果与人物独立保留，关系解除或显示已删除引用                         |
| 专利—人物线索或候选人 | 多对多                         | 稳定身份或多证据确认；只有姓名只能召回             | 同论文                                                               |
| 人才版图—正式资产     | 多对多                         | 版图范围内明确引用                                 | 删除版图不删除共享资产；资产删除显示已删除引用                       |
| 业务主线—正式资产     | 多对多                         | 作为输入、结果或复用对象                           | 主线历史保留必要摘要，不复制资产详情                                 |

## 十五、身份识别、重复与合并策略

| 对象     | 优先身份依据                                                                         | 证据不足时                                             | 明确重复后的处理                                                               |
| -------- | ------------------------------------------------------------------------------------ | ------------------------------------------------------ | ------------------------------------------------------------------------------ |
| 公司     | 已确认公司名称、官网或邮箱域名、平台公司身份、名称变体和来源上下文                   | 提示可能重复，允许继续核实；不能只凭字符串包含自动合并 | 展示名称、关键资料、关系和影响范围后合并；原始外部名称继续保留在各来源对象中   |
| 联系人   | 手机、邮箱、公司关系、职位角色和来源身份                                             | 保留联系人线索或进入身份待确认；不能只凭姓名合并       | 合并联系人资料和公司关系；若与候选人同人，建立身份关系而不是把两种档案合成一种 |
| 招聘机会 | 同一公司、相近需求方向、确认依据、来源和时间                                         | 新建或编辑时提示可能重复，允许用户判断                 | 阶段一优先关联或补充已有机会；不自动把两个机会合并                             |
| 岗位     | 正式公司或公司原文、岗位名称、JD 和招聘要求                                          | 提示同公司存在相似岗位，但允许继续创建                 | 阶段一不自动合并岗位；同名岗位可能属于不同团队或招聘周期                       |
| 候选人   | 稳定外部身份、手机、邮箱、平台身份、公开资料、工作教育轨迹、论文专利身份             | 保留人物线索或待确认资料，不冒险创建重复正式候选人     | 确定保留档案，审核新增、更新和冲突后合并全部有效资料与业务关系，并提供撤销     |
| 人才版图 | 名称、摸排目标、目标范围和使用目的                                                   | 新建时提示相似版图，允许使用已有版图或仍然新建         | 阶段一不提供版图合并和复制                                                     |
| 论文     | DOI、OpenAlex Work ID、arXiv ID、OpenReview ID；缺失时综合标题、作者、年份和发表场所 | 进入待确认，不能只凭标题合并                           | 不创建第二条记录，补充缺失信息；冲突字段等待确认                               |
| 专利     | 申请号、公开号、授权号；缺失时综合标题、申请日、发明人和权利人                       | 进入待确认，不能只凭标题合并                           | 不创建第二条记录，补充缺失信息；冲突字段等待确认                               |

所有输入路径都必须返回可见处理结果。明确命中已有对象但没有新信息时显示“已匹配现有资产，本次没有可更新内容”，不能让用户误以为上传或任务失败。

## 十六、资料版本与结果过期

| 对象或结果     | 版本规则                                         | 何时提示过期                                                         | 用户可以做什么                               |
| -------------- | ------------------------------------------------ | -------------------------------------------------------------------- | -------------------------------------------- |
| 候选人资料     | 每次正式变化形成资料版本和变化摘要               | 简历、当前角色、经历或技能等相关内容变化后，旧摘要和匹配结果可能过期 | 查看变化、更新摘要、重做受影响匹配           |
| 岗位资料       | 当前 JD 显式版本；招聘要求和岗位分析保留变化记录 | 当前 JD 或匹配相关要求变化后，旧岗位分析和匹配结果可能过期           | 查看版本差异、重新解析或重做匹配             |
| 公司资料       | 正式字段变化形成精简历史                         | 关键资料来源过期或出现冲突时                                         | 审核更新建议、保留现有值或采用新值           |
| 人岗匹配结果   | 关联候选人资料版本、岗位资料版本和策略版本       | 任一相关版本改变                                                     | 保留历史结果，创建新结果；不自动移出已有推进 |
| 人才版图       | 以范围版本和变更批次追溯                         | 来源失效、关系冲突或引用资产变化影响当前判断时                       | 审核增量变化、撤销批次或接受缺口             |
| 论文和专利指标 | 指标值附更新时间；成果身份和原文独立保存         | 被引数、来源状态等时效数据陈旧时                                     | 按需刷新，不覆盖原始成果信息                 |
