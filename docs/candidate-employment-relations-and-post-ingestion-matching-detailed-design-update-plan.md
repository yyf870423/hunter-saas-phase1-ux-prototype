## 一、已确认产品结论

1. 候选人的同公司、同部门关系由已确认任职经历派生，不新增需要用户维护的正式资产字段。
2. 候选人详情中的任职关系、学术成果和合作人共用一个“人物与成果关系”区域，通过二级 Tab 切换，避免三个长表格纵向堆叠。
3. 候选人简历上传、候选人批量导入、岗位手动创建、岗位批量导入和任务内资产写入使用同一条“正式写入后再启动匹配”的规则。
4. 立即匹配默认关闭。候选人可以匹配全部招聘中岗位或指定岗位；岗位匹配系统内可用候选人。
5. 身份查重、字段审核和正式写入先完成，匹配随后异步启动。匹配失败不能回滚已经成功的资产写入。
6. Agent 在任务中准备写入候选人或岗位时，通过纵向选项询问是否立即匹配，同时保留自然语言输入；不新增单独配置表单。
7. 新建岗位的 AI 解析入口支持完整 JD、长段自然语言、链接和文件，提交后进入统一任务对话。已有岗位重新解析继续使用资产 AI，并保留既有补充说明规则。
8. 人物身份审核页是上传或 Agent 入库发现已有候选人、疑似重复或身份冲突后的条件页面，不是常驻导航入口。

## 三、逐篇更新要求

### 3.1 `02 任务`

1. 在动态结果交互中增加候选人或岗位正式写入前的纵向选择。
2. 明确用户可以选择立即匹配、仅写入或输入其他要求。
3. 匹配范围和选择必须显示在对话中，不能作为不可追溯的隐藏参数。
4. 增加候选人入库和岗位创建两个关键状态入口。

### 3.2 `03 运行与恢复`

1. 正式资产写入成功后，立即匹配创建独立的资产 AI 运行或批量后续运行。
2. 匹配失败不改变写入成功状态；失败项可以重试，不能重复创建或合并资产。
3. 批量场景需要分别统计写入成功、匹配启动、匹配跳过和匹配失败。

### 3.3 `04 资产公共规则`

1. 增加“写入后立即处理”规则，定义默认关闭、执行顺序、幂等复用和失败边界。
2. 手动创建、文件上传、统一导入和任务写入使用相同业务口径，但沿用各自已有交互外壳。
3. 指定范围为空、没有可匹配对象、部分写入失败和匹配失败都要有可理解结果。

### 3.4 `05 候选人资产`

1. 增加同公司与同部门候选人的来源、可信边界、字段和自动刷新规则。
2. “任职关系、学术成果、合作人”使用二级 Tab 切换；大数据量继续使用搜索、筛选和分页表格。
3. 上传简历可以选择写入后匹配全部招聘中岗位或指定岗位；身份和合并完成后才启动。
4. 人物身份审核只在重复或冲突条件满足时出现。
5. 补充正常流程、异常流程、验收标准、原型入口和关键状态截图。

### 3.5 `06 岗位与招聘推进`

1. 手动创建岗位可以选择创建后立即人岗匹配。
2. AI 解析入口接收完整 JD、长文本、链接或文件，之后进入统一任务对话；不再使用预置示例代替用户输入。
3. Agent 准备创建岗位时询问是否立即匹配，匹配只读取正式写入的岗位版本。
4. 补充匹配失败不回滚岗位、无候选人时跳过以及关键状态入口。

### 3.6 `10 统一数据操作`

1. 候选人批量导入支持全部招聘中岗位或指定岗位。
2. 岗位批量导入支持对成功写入岗位立即匹配系统候选人。
3. 导入结果分别显示写入和匹配统计，失败重试不能重复匹配已经具有相同输入版本的组合。

## 四、在线更新顺序

1. 先更新 `02、03、04` 的任务、运行和公共规则。
2. 再更新 `05、06` 的候选人和岗位专题。
3. 最后更新 `10` 的批量导入规则。
4. 每篇文档更新后立即重新读取，检查标题、表格、图片、链接和用户可能进行的在线修改。
5. 新截图只放在对应关键状态说明附近；使用已经通过验收并与提交 `594e870` 一致的截图。

## 五、交叉 Review 门禁

1. “立即匹配”始终发生在正式写入之后，不会绕过身份、查重、字段审核和写入门禁。
2. 候选人和岗位的手动、导入、任务入口使用相同执行顺序和失败边界。
3. 匹配失败不回滚资产；重试不重复创建资产或重复计算同一输入版本。
4. 任职关系不复制成用户手工维护字段；部门证据不足时只显示同公司关系或待确认。
5. 人物身份审核页不会被描述为候选人常驻详情入口。
6. 新建岗位 AI 解析和已有岗位重新解析的输入规则不会混为同一页面。
7. 详细设计链接、截图和在线原型均指向已经推送的当前版本。
8. 不修改概要设计，不改动无关详细设计，不自动更新文档版本表。
