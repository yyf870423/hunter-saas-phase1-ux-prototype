## 二、隐私与数据边界

1. 原型数据不包含候选人姓名、岗位名称、简历正文、文件名、对话、提示词、任务输入或 Agent 输出正文。
2. 任务详情只显示任务编号、工作空间、任务类型、阶段、检查点、错误码、状态码、服务耗时、资源和用量。
3. 工作空间详情只聚合运营健康、风险和脱敏任务摘要，订阅与支持通过对应模块继续处理。
4. 诊断包必须由用户主动提交；运营端只展示脱敏环境、错误和调用链摘要。

## 三、角色与操作边界

1. 运营人员可以处理试用、权益、支持和系统明确判定安全的恢复。
2. 系统管理员额外管理能力配置和安全事件。
3. 权限不足使用统一受限状态，不伪装成系统错误。
4. 安全恢复包含从检查点继续、重新入队、终止异常资源、重新分配资源和退还重复额度。
5. 原型不提供修改任务输入或输出、绕过门禁、代替用户审核、启动业务任务或对外联系的入口。

## 四、关键交互与状态

1. 搜索、筛选和单项清空会真实改变列表，不是静态装饰。
2. 试用申请覆盖批准、暂缓、拒绝和可选标准结果说明。
3. 例外权益调整和安全恢复均有必填原因、执行边界、禁用态和完成反馈。
4. 模型配置覆盖多资源池、多密钥、负载均衡、任务路由、并发预算、配置版本、验证中、验证失败和验证成功。
5. 能力降级可关联既有安全事件或创建新事件。
6. normal、loading、empty、error、permission-limited 以及局部失败、不可安全恢复、诊断包异常均有直接验收入口。

## 五、视觉与响应式 Review

1. 已检查运营概况、工作空间列表、任务详情和系统能力的桌面、iPad 与 iPhone 截图。
2. 已检查试用审批、安全恢复、模型配置、模型后端 Modal、工作空间健康抽屉、支持处理抽屉、配置验证失败、局部错误、空状态和权限受限截图。
3. 三种视口没有页面级横向溢出；桌面表格在移动端转换为字段分组记录。
4. Button、Modal、Drawer、Toast、SelectMenu、DatePicker、TextInput、TextArea 和 FormField 均复用产品级组件，没有可见的浏览器默认控件。
