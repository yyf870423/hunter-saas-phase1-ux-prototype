# 招聘机会闭环与对话确认

更新日期：2026-09-08。本轮由用户授权推送原型和同步详细设计；这是浏览器交互原型，不代表正式后端或真实 Agent 已上线。

## 业务闭环

1. 招聘机会保留为持续跟进的需求资产。有效公司、机会名称、需求摘要和发现依据为基本准入；联系人、完整 JD 可暂缺，事实、推断和待确认项分开表达。
2. 支持手工新建、公司内新建、任务资料形成，以及洞察进入新任务或已有任务。取消机会批量导入；历史导入只读保留，不影响其他资产导入。
3. 客户开发先展示潜在机会并确认是否记录，再处理联系人和对外联系。记录机会不等于客户已确认需求或合作；后续资料更新同一机会，不重复创建。
4. 跟进记录保存实际时间和内容；未来安排保存事项和提醒时间。每个机会一个当前安排，可完成、改期或取消，保存记录不默认完成安排。任务自有安排仍归原任务。
5. 到期通知只生成一次，通知已读不等于事项完成。机会自身提醒不生成用户任务或洞察；机会完成、关闭、删除仅取消自身安排，恢复不重放旧提醒。
6. 方向支持新增、编辑、拆分、放弃、重新打开。每个方向至多一个当前岗位关系；已有关系时不能删除或拆分后复制该关系。
7. 形成岗位支持手工创建、AI 整理后对话确认、关联同公司已有岗位。必须有实质 JD，不从职位名或历史样例补造；未知薪资、学历和地点不填假值。
8. 新岗位使用真实独立 ID、资料版本和空候选人流程；创建岗位不自动开始找人。找人另行发起，引用实际岗位 ID 与版本，候选人批量审核继续使用既有组件。
9. 机会完成表示本轮需求交接，不表示候选人入职。至少一个有效岗位、其余方向已明确处置后由用户确认完成；岗位和任务独立推进。
10. 删除、恢复、引用校验、幂等和版本冲突共用领域命令。解除当前岗位关系不删除岗位，也不改写历史创建来源。

## 对话与公共组件

- 单个资产入库及修改通过 Markdown 展示草稿、发现依据、缺口和旧新值，直接询问“是 / 否 / 建议”，不提供专用审核页。建议只改草稿并重新确认；拒绝保留草稿；含修改或歧义的回答不直接写入。
- 自动执行不跳过上述确认；仅分析不写入。确认命令不混入业务证据，写入前再次检查权限、引用、版本、字段及去重。Markdown 链接仅导航，不执行副作用。
- 岗位找人、批量候选人审核、身份冲突、邮件发送、跟进安排及资产手工表单保持专用交互。其余状态提示的改善建议未在本轮自动实施。
- `SingleAssetTaskSummary`、`OpportunityWriteResult` 复用 `HunterReply`、`HunterMarkdown`、`Composer`；资料/方向/跟进复用 `OpportunityComponents`、`OpportunityDirections` 和 `asset-ui` 公共控件。
- `WorkHistory` 类型文字使用 13px、650 字重和已有强调色，支持多类型换行。全局新建仅提供“新建任务”“手动新建资产”；周期性目标从统一任务入口表达。
- 删除确认正文复用 `.s1-modal-copy`。订阅页 Agent 用量、图形与用户菜单共用 `agentUsage.usedPercent`，不显示任务次数或公开网络搜索配额；数据处理用量保留。
