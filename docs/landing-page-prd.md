# Hunter 首页 PRD

> 状态：已批准进入实现。视觉基准为 `.impeccable/mocks/decision/evidence-choreography-spine-theatre-v3-login.png`。

## 1. 页面目标

让中国独立猎头和资深顾问在首屏内理解：Hunter 不是给出一轮名单的通用 AI，也不是只管理已入库简历的 ATS；它围绕岗位跨渠道找人，统一身份、去重补证和匹配，把可核验的候选池交给猎头判断。

## 2. 转化路径

1. 主转化：拿一个岗位来演示。
2. 次转化：查看真实寻访，进入 `#/workstreams/position-vla`。
3. 已有用户：从首页“登录”进入 `#/login`，完成手机号验证码或微信扫码登录后进入 `#/home`。

申请演示在原型内使用完整前端表单模拟，不调用真实后端。提交成功后显示明确确认状态；不得暗示已经向销售系统写入真实数据。

## 3. 内容结构

1. 顶部导航：怎么找人、找人渠道、真实寻访、人机边界、登录、预约演示。
2. Hero：核心价值主张、主 / 次 CTA、光学证据轨道和人工判断刹停点。
3. 产品机制：一个岗位如何被拆成目标定义、多路召回、身份与证据合并、候选池审核。
4. 真实寻访：以“具身智能 VLA 算法负责人”为演示数据，展示跨渠道召回、候选人证据、猎头判断和岗位储备。
5. 人工控制边界：系统负责什么、人负责什么，以及异常或证据不足时如何停下。
6. 找人渠道：已有候选人、人才版图、公开与学术来源、认证人才平台结果回传。
7. 最终 CTA 与页脚。

## 4. 核心交互

- 导航滚动到对应区块；移动端提供可关闭菜单。
- Hero 证据轨道自动推进，也允许用户通过证据片切换当前阶段。
- 桌面端五张 Hero 证据片必须完整入框；移动端一次展示一张完整活动证据片，不允许内容卡被左右裁断。
- 主要区块进入视口时完成一次轻量对齐动效。
- `prefers-reduced-motion` 下停用自动位移与速度残影。
- “查看真实寻访”进入现有岗位招聘主线。
- “登录”进入独立用户认证页；认证页支持手机号验证码登录、微信扫码登录与手机号注册。
- 用户认证仅做前端原型模拟；成功后进入现有 `#/home`，不扩建 Console。
- 运营登录为独立 `#/ops/login` 页面，仅支持用户名与密码；首页和用户认证页均不提供该入口。成功后进入现有 `#/ops/overview`，不扩建运营后台。
- “拿一个岗位来演示”打开 Modal；支持必填校验、联系方式格式校验、提交中和成功状态。
- 真实寻访区支持切换多路召回、候选人判断、人工判断与下一步，内容同步变化。

## 5. 内容与证明约束

- 不使用客户 Logo、客户证言、商业指标、价格、认证或真实人物照片。
- 所有对外展示的工作流明确标记为“演示数据”。
- 不承诺未在现有原型中出现的自动化、数据源或外部联系能力。
- 页面文案使用中文；第三方技术名词和产品名保留原文。
- 文案从独立猎头熟悉的找人处境出发：目标范围模糊、渠道分散、人物重名、证据不足、候选人关系依赖顾问把握。避免把猎头描述成只需要“提效”的执行角色。
- 统一使用“岗位要求、多路召回、统一身份、候选池、等你筛人”等业务语言；不使用“AI 赋能、智能匹配、颠覆招聘”等泛化表述。
- CTA 使用“拿一个岗位来演示”，强调带真实岗位约束来看，而不是泛泛“了解产品”。

## 6. 必要状态

- normal：默认页面和默认演示阶段。
- loading：仅用于演示表单提交等真实等待；工作流演示数据已在本地，Tab 切换直接更新，不显示虚假 loading。
- empty：表单未填写；不作为错误，点击提交后才提示。
- error：必填缺失、联系方式无效；字段旁给出修复方式。
- disabled：提交中禁用重复提交。
- permission-limited：对外动作在演示中只展示说明，不伪造真实发送。
- success：演示申请已在本地确认，不声称已经进入真实后台。
- auth：登录 / 注册包含输入、校验、验证码倒计时、扫码演示、提交中与失败提示；不得暗示已经接入真实短信、微信或账号服务。

## 7. 响应式与无障碍

- 桌面目标：1440 × 1000 与常见 1280–1600px 宽度。
- 移动目标：375–430px 宽度，无横向滚动。
- 键盘可操作；焦点可见；Modal 支持 Escape 和遮罩关闭。
- 颜色不是唯一状态信号；关键状态同时有文字与图形。
- 动画不阻塞阅读，并尊重系统减少动态偏好。
- Hero 固定两条语义标题行；区块标题使用作者声明的 2–3 条语义行，不出现不足三个汉字（含标点）的孤行。

## 8. 验收条件

- 首屏与获批 comp 在构图、颜色、尺度和核心动势上保持一致。
- 完整页面内容有清晰节奏，不退化为功能卡片墙。
- 用户登录 / 注册、独立运营登录、查看工作流、导航和演示申请路径可操作。
- 首页和用户认证页中不存在进入运营登录页的链接。
- 桌面与移动截图通过设计 QA；构建和相关测试通过。
