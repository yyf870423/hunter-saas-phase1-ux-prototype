# 原型阶段一公共设计系统

> 状态：阶段一已通过人类审批并冻结。该文件只记录阶段一已经实际使用的 Token 和组件；后续阶段只能扩展，不能在业务页面中另起一套样式。

## 一、设计原则

1. 采用 WorkBuddy 的持续工作区层级和 Vercel Geist 的清晰视觉语言，不复制任何单一产品页面。
2. 页面背景、内容表面和浮层形成三层深度；侧栏在浅色模式使用低对比冷白灰形成安静边界，在深色模式使用冷炭黑形成稳定识别区，两种主题使用不同明度但保持相同信息层级；亮蓝色只强调当前导航、主操作和需要注意的系统状态，不使用装饰性卡片墙和大面积渐变。
3. 业务优先级通过尺寸、位置、留白和边界表达，不依靠堆叠说明文字。
4. 默认亮色，深色模式保持相同信息层级；警告与风险允许使用黄色、橙色和红色。
5. 所有控件都有 normal、hover、focus-visible、active、disabled 和 loading 状态。

## 二、基础规格

| 类别     | 规格                                                          |
| -------- | ------------------------------------------------------------- |
| 正文     | 14px / 1.55                                                   |
| 辅助文字 | 12px 或 13px，不低于 12px                                     |
| 页面标题 | 24px，字重 650                                                |
| 区域标题 | 16px 或 18px，字重 650                                        |
| 紧凑状态 | 12px，状态点与文字不可拆分换行                                |
| 控件高度 | 32px、36px、40px 三档                                         |
| 控件圆角 | 输入、按钮和菜单项 6px                                        |
| 表面圆角 | 普通面板、卡片和浮层 8px                                      |
| Modal    | 10px；小 440px、中 640px、大 880px；移动端全屏                |
| 导航     | 收起 64px、展开 224px                                         |
| 阴影     | 控件、普通浮层、Modal 和 Tooltip 四级；页面区块默认不使用阴影 |

## 三、产品级组件

1. `AppShell`：桌面导航、顶栏、移动顶栏和底部导航。
2. `SidebarNav`：核心工作导航、收起/展开和底部固定区；浅色主题使用冷白灰表面、深色文字与淡蓝选中态，深色主题使用冷炭黑表面、高对比浅色文字与蓝灰选中态；两种主题必须有明显明度差异，当前项和普通项均满足可读性要求。收起后使用固定 SVG 与无障碍名称，不显示系统原生 Tooltip。
3. `AssetNavigationPanel`：桌面侧向资产导航，按招聘、人才和研究分组直接进入八类正式资产。
4. `Topbar`：搜索、创建、主题和通知。
5. `Button` / `IconButton`：主、次、幽灵、危险和加载状态。
6. `StatusBadge`：运行、等待、异常、完成、观察和普通状态。
7. `SearchDialog`：搜索输入、最近访问、分组结果、无结果和键盘关闭。
8. `NotificationDrawer`：全部/未读、已读操作和空状态。
9. `Modal` / `Drawer`：统一尺寸、遮罩、焦点和关闭逻辑。
10. `Toast`：成功、信息、警告和错误。
11. `UsageRing`：紧凑用量入口和详情。
12. `MainlineFocus`：工作台唯一主焦点和紧凑主线切换。
13. `TaskSummaryList`：少量需要关注的独立支线摘要。
14. `SignalFeed`：少量高优先级信号摘要。
15. `ActionQueue`：默认收起的人工行动摘要。
16. `Skeleton` / `EmptyState` / `ErrorState` / `PermissionState`：全局状态组件。
17. `UserMenu`：显示当前用户和工作空间，并承载设置、切换工作空间和退出登录；支持外部点击与 `Escape` 关闭。
18. `AppTabs`：列表分类、详情分区和审核视图共用 WorkBuddy × Vercel 内容导航式 Tab；整行使用轻底边区分内容层级，选中项通过强调文字、字重和底部色条表达，计数使用弱底色徽标；业务页面不得另起一套按钮块或分段框 Tab。
19. `OverflowTooltip`：只服务于确实被截断的文本和 `+N` 隐藏标签；采用 WorkBuddy × Vercel 的中性高层浮层，亮色模式使用白色表面、细灰边界和短距离阴影，深色模式使用深灰表面，不使用箭头、左侧色带、彩色边框、毛玻璃、`title` 或 SVG `title`。鼠标悬停延迟约 `150ms`，键盘聚焦立即显示，移开、失焦或按 `Escape` 关闭；富信息改用 Context Card、Drawer 或详情页。
20. `TagList`：技能、行业、人物类别、论文主题和专利主题等同组标签统一使用 `8px` 横向间距和 `6px` 换行间距；隐藏项使用同行 `+N`，业务页面不得自行压缩标签间距。
21. `DatePicker`：日期、日期时间、出生年份、多年份筛选和月份区间共用同一个公共组件。每个字段只显示一个触发框；日期区间在同一浮层内依次选择开始与结束时间，开始与结束选择区始终左右排列，不上下堆叠。组件采用 WorkBuddy × Vercel 的中性表面、细边框、轻阴影和蓝色选中态，不显示浏览器原生日期、月份或时间控件。浮层打开时按 `Escape` 只关闭当前时间浮层，不连带关闭外层 Modal。
22. `AcademicPeopleList`：论文作者和专利发明人共用的紧凑人物名单。默认最多显示 5 位，论文作者必须直接显示论文署名机构；其余人物通过可滚动浮层查看，不在详情页继续堆叠大卡片。已关联姓名进入对应候选人，未关联姓名只打开该人物的单人身份审核 Modal；详情页不提供一次审核全部人物的入口。
23. `PersonIdentityReview`：单个人物的作者或发明人身份审核 Modal。系统每次只给出置信度最高的一位疑似候选人，不允许在审核 Modal 内搜索或更换候选人。短字段摘要只用于识别两侧人物，详细判断按联系方式、工作经历、教育经历、项目与研究经历分组；每组使用左右档案对照和一致性状态，不使用 Markdown 表格承载多条经历。两侧分别显示记录数量，数量不同时不按视觉行位强行配对；多出的记录保留在所属一侧，并以“来源未发现”“候选人补充”“来源未披露”等状态说明关系。桌面端左右对照，移动端在同一分组中按来源人物、疑似候选人的顺序纵向显示。关联候选人、保留人物线索和暂不关联使用三个独立按钮，点击即保存并更新当前人物状态，不再使用 Radio 后二次保存。
24. `SourceList`：资料来源和原始文件的统一列表。可访问的外部原文必须使用语义化链接并在新 Tab 打开；产品内详情使用按钮或路由跳转。所有可交互项都必须显示可点击指针和 hover 反馈。
25. `RelationshipCanvas`：人才版图和摸排批次共用的关系投影。固定提供视图切换、缩放、重置、节点选择和详情区；节点与关系的证据必须逐项打开当前任务快照，已关联业务资产可以进入对应详情。切换批次或投影时必须同步当前选中对象，不能保留上一视图的失效选择。
26. `MappingTargetList`：人才版图目标的公共清单。目标包含类别、优先级、完成标准、当前缺口、证据判断、下一步和状态；支持新增、查看、分区编辑、标记完成和重新打开。未知市场总人数不用于计算完成度，目标完成必须基于可理解、可行动和结果可预期的完成标准。
27. `SelectMenu` 图标型单选项：当选项本身对应固定 SVG 语义时，触发器和下拉选项统一显示“图标 + 文本”，图标位于文本左侧；图标只能辅助识别，文本仍是完整的可访问名称。知识图谱的节点类型使用该模式，节点图标由节点类型唯一决定，不提供独立图标配置。

## 四、复用约束

1. 页面只组合公共组件和数据配置，不复制按钮、浮层、状态、列表行和导航实现。
2. 所有图标来自统一 SVG 映射；未知图标不能静默回退成无关图形。
3. 后续阶段发现组件不足时，先更新本文件和组件实现，再进入业务页面。
4. 组件的视觉状态和业务状态分离；同一个业务状态在工作台、详情和列表中使用相同颜色语义。
