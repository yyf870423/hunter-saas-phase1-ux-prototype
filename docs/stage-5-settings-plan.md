# 阶段五：设置中心 UX 原型方案

## 1. 目标

设置中心服务阶段一个人用户，集中管理个人账户、通知、自动化授权、云端连接、订阅用量和数据隐私。设置不是主要业务入口，继续放在用户菜单中；用户完成设置后应返回原业务页面，不改变业务主线、支线任务和业务资产的信息架构。

本阶段只完成设置中心的高保真交互原型、公共组件补充和验收状态，不编写设置中心详细设计，也不进入 Hunter 产品代码开发。

## 2. 产品边界

### 2.1 本阶段包含

1. 个人资料、个人工作空间和登录安全。
2. 站内通知与页面外邮件通知偏好。
3. 四类业务主线的默认自动化授权。
4. 发件邮箱连接和寻访 App 设备连接管理。
5. 订阅、用量、额度、支付宝或微信支付及自动续订信息。
6. 数据导出、诊断包、回收站和工作空间删除。
7. 桌面 Web 与移动 Web 的完整交互、加载、空、错误和权限受限状态。

### 2.2 本阶段不包含

1. LLM 供应商、模型、API Key、搜索源、OpenAlex、GitHub 等技术配置。上述能力由 Hunter 托管。
2. 人才平台账号、验证码、登录态和风控处理。上述能力只在寻访 App 中处理。
3. 团队成员、角色、复杂权限和团队审批。阶段一只有个人工作空间。
4. 运营人员远程查看业务内容。阶段一运营端只能读取脱敏诊断信息。
5. 正式推荐、面试确认、薪资承诺、Offer 沟通和录取决定的自动授权。
6. 寻访 App 本身的详细设置和平台操作页面。

## 3. 信息架构

设置入口位于左侧导航底部的用户菜单。桌面端设置页使用“窄设置导航 + 宽内容区”；移动端使用账户卡片下的设置目录，不把“设置”作为底部主导航标签。

| 设置项     | 页面目标                       | 主要内容                                                           |
| ---------- | ------------------------------ | ------------------------------------------------------------------ |
| 个人资料   | 管理个人身份与工作空间         | 头像、姓名、登录邮箱、工作空间名称、语言、时区、登录安全和活跃会话 |
| 通知       | 决定什么事项通过何种方式提醒   | 站内、邮件、强制通知、低优先级摘要和通知邮箱状态                   |
| 自动化授权 | 管理尚未开始工作的默认执行边界 | 四类业务主线的仅分析、执行前确认和自动执行                         |
| 连接       | 管理云端可识别的外部连接       | 个人发件邮箱、邮箱协议、寻访 App 设备、版本、最近同步和授权撤销    |
| 订阅与用量 | 查看产品权益和成本边界         | 当前套餐、续订、支付方式、用量环、分类用量、额度预警和订单记录     |
| 数据与隐私 | 管理数据带出、恢复和危险操作   | 全量导出、诊断包、回收站、数据保留和删除工作空间                   |

## 4. 页面布局与交互

### 4.1 设置公共外壳

1. 页面标题为“设置”，副标题只说明当前页作用，不展示产品功能宣传。
2. 桌面端设置导航宽度固定，内容区最大宽度约 880px；页面分区使用无卡片白底区块和分隔线，不把页面做成卡片套卡片。
3. 移动端显示用户账户卡片和当前设置项选择器，设置项切换后保留页面滚动位置。
4. 设置保存使用局部按钮和 Toast；存在未保存修改时离开页面，显示标准确认 Modal。
5. 所有开关、复选框、单选、下拉、日期和确认输入使用公共组件，不使用浏览器原生可见样式。

### 4.2 个人资料

#### 页面区域

1. 个人资料：头像、姓名、登录邮箱。更换头像进入独立 Modal，支持选图、格式与大小检查、圆形裁剪、缩放、保存中和失败反馈；邮箱已验证状态只读显示，修改邮箱进入独立 Modal 并要求重新验证。
2. 个人工作空间：工作空间名称、界面语言、时区。阶段一不出现成员和角色。
3. 登录与安全：修改密码、当前登录会话、其他会话、退出其他会话。

#### 关键交互

1. 每个区域独立编辑、保存和取消。
2. 名称为空、邮箱格式错误、密码强度不足时即时显示字段级错误。
3. 退出其他会话必须二次确认，成功后当前会话保留。
4. 登录会话加载失败只影响该区块，不阻塞个人资料编辑。

### 4.3 通知

#### 页面区域

1. 通知渠道：站内通知、邮件通知；邮件沿用账号邮箱并显示验证状态。
2. 通知矩阵：任务状态、需要用户处理、外部回复、高优先级信号、寻访 App、额度和订阅。
3. 通知摘要：低优先级事项可选择即时、每日摘要或仅站内。

#### 关键交互

1. 安全、订阅到期、额度耗尽和强制门禁失败属于必须通知项，控件禁用并说明原因。
2. 邮箱未验证时，邮件列不可选，页面提供“验证邮箱”操作。
3. 保存失败保留用户当前选择并显示局部错误，不回滚到旧值。

### 4.4 自动化授权

#### 页面区域

1. 四类业务主线：客户开发、岗位招聘、人才摸排、候选人求职。
2. 每类显示当前默认授权、影响范围和最近修改时间。
3. 页面不展示内部数据检查、系统安全规则和研发实现细节。

#### 关键交互

1. 点击业务主线进入编辑 Modal，选择“仅分析”“执行前确认”“自动执行”。
2. 选择自动执行时先显示影响说明，确认后只影响新创建且未单独指定授权的工作。
3. 任务运行中仍可在任务页修改授权；本页只管理默认值。
4. 邮件发送不继承自动执行，每封邮件仍需确认收件人、标题、正文和附件。

### 4.5 连接

#### 页面区域

1. 发件邮箱：个人邮箱地址、连接状态、自动识别的协议、最近使用、重新连接和断开连接。
2. 寻访 App 设备：设备名称、操作系统、版本、最近同步、连接状态和撤销授权。
3. 页面不显示人才平台账号和登录状态。

#### 关键交互

1. 用户填写个人邮箱地址以及邮箱密码或客户端授权码。发送邮件固定使用 SMTP，读取回复优先使用 IMAP。
2. Hunter 先根据已知服务商配置、邮箱域名和可用服务器自动探测协议，再分别验证 SMTP 和收件连接。
3. 自动探测失败时保留邮箱凭据，并允许用户手动填写 SMTP 服务器、端口、加密方式，同时在 IMAP 和 POP3 中选择收件协议。IMAP 为推荐项，POP3 只作为服务商不支持 IMAP 时的兼容方案。
4. 邮箱连接失败允许在当前 Modal 重试并保留已经填写的内容。
5. 添加寻访 App 设备生成一次性连接码和二维码；连接成功后局部刷新设备列表。
6. 设备撤销授权必须说明未提交结果的影响并二次确认。
7. 无设备时显示空状态；版本不兼容时显示升级操作，但平台登录和风控仍由 App 自己处理。

### 4.6 订阅与用量

#### 页面区域

1. 当前套餐：名称、续订日期、自动续订和首次支付时授权的自动付费方式；当前套餐区不显示价格。
2. 用量：总用量环、Agent 任务、公开网络搜索和数据处理分类用量。
3. 额度预警：达到 70%、90% 和耗尽时的通知状态。
4. 订单记录：日期、金额和支付状态，不提供订单文件下载。

#### 关键交互

1. 左侧导航用量环和用户菜单均可进入本页。
2. 首次订阅和更换套餐使用标准 Modal。中国大陆阶段一支持支付宝、微信支付，默认开启自动续订；首笔支付完成后不提供更换自动付费方式的入口。
3. 到期说明明确：Agent 和付费功能受限，数据查看和导出继续可用。
4. 用量明细加载失败不隐藏套餐和支付信息。
5. 从未订阅时单独说明可浏览、可导出的能力边界，并提供首次选择套餐入口，不显示用量和续订信息。

### 4.7 数据与隐私

#### 页面区域

1. 数据带出：全量导出跳转数据管理导出页；诊断包只包含脱敏运行信息。
2. 数据恢复：进入回收站，说明统一保留和清理规则。
3. 危险操作：删除工作空间。页面不单列内部隐私边界，也不提供注销 Hunter 账号。

#### 关键交互

1. 删除工作空间需要输入工作空间名称并确认影响，错误输入即时提示。
2. 删除操作存在运行中的导出或数据处理任务时，显示阻塞原因和下一步。
3. 导出和诊断包创建后进入异步任务，不要求用户停留等待。
4. 权限受限状态明确哪些数据仍可查看和导出。

## 5. 状态覆盖

每个设置页覆盖 `normal`、`loading`、`error`、`disabled`、`permission-limited`；适用页面补充 `empty`、`unsaved`、`connecting` 和 `success`。

1. 页面级加载只用于首次读取；局部保存和连接使用局部 loading。
2. 页面级错误提供重试，已经成功读取的区块不被灰色骨架覆盖。
3. 权限受限不是团队权限，而是订阅到期、邮箱未验证或连接失效导致的功能限制。
4. 自动刷新不关闭 Modal、不清空输入、不改变滚动位置。

## 6. 响应式规则

1. 桌面端采用设置侧栏与内容区；iPad 竖屏仍保留紧凑侧栏。
2. iPhone 使用设置项选择器和单列内容；表格改为列表，不出现横向滚动。
3. Modal 在移动端转换为底部或全屏浮层，底部操作保持可见。
4. 通知矩阵在移动端按通知类型展开，每种渠道作为行内开关，不压缩文字。
5. 订阅与用量在移动端先显示套餐和用量，再显示订单。

## 7. 原型验收入口

1. `/settings/profile`
2. `/settings/notifications`
3. `/settings/automation`
4. `/settings/connections`
5. `/settings/subscription`
6. `/settings/data-privacy`
7. `/review/settings`：汇总页面、关键状态和交互入口。
