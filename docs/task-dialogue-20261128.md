# 任务对话交互调整（GitHub 原型，待审核）

## 已确认范围

- 移除任务对话中的执行计划、步骤计数和展开入口；不改变内部任务业务规则。
- 当前工作在对话末尾用等宽字体呈现，只描述用户可理解的操作，不展示模型思维过程。
- 每轮完成后，在自然语言回复之前显示该轮用时；继续处理时重复这一节奏。
- 保留操作确认框。另提供单选、多选和文字输入的澄清询问；回答问题不等于授权保存、合并、联系或发送。
- 覆盖新建任务、岗位寻访、客户开发、组织梳理、求职匹配、身份核验、摘要、推荐报告、单资产任务、周期任务和候选人调研。
- 只改原型仓库；不改 AROS、后端和正式官网。2026-11-28 用户明确授权“推送到原型让我审核”，本轮仅发布 GitHub Pages 供审核，不代表 1420 实现或后端接入获批。
- 补充确认：用户希望保留计划执行的可感知性，移除的原因是固定面板太占空间。内部计划保留，运行步骤在对话末尾依次显示；状态经过即消失，不固定、不展开、不回查。完成后只留下处理用时和自然语言结果。
- 补充确认：正常任务不弹出右下角黑色 Toast。重复的“已收到/已保留/已完成”反馈移除；仍有必要的反馈在当前对话内就地呈现。错误不静默丢弃，非任务页面的原有提示不受影响。

## 实现与验收约定

1. 共用对话容器负责当前工作、计时、停止和任务切换清理。新交互使用本地模拟，用时为实际模拟经过时间；历史示例用时明确标记为示例。
2. 共用询问组件复用现有单选、多选、输入框和按钮，校验必填项。支持提交、暂不回答、补充文字和回答回显；防止重复提交与过期回调。
3. 自然语言输入始终保留。选择框用于明确意图，结果区只读，实际操作仍遵守授权模式和本版确认。
4. 运行中可停止；停止后不执行尚未执行的本地回调。失败显示可理解的提示，保留用户输入；切换任务不串入旧回复。
5. 不改变任务列表、分栏拖动、详情入口、已有内容和手机底栏。
