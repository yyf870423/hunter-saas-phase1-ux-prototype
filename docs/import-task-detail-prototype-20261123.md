## 审批状态

## 目标与边界

- 用户要求先做本地原型，补足数据管理中“哪些正在导入、哪些成功、哪些失败及原因”。未经验收不推送，不同步 AROS，不改后端、真实数据或公网。
- 基于原型 main `87816b0`。已对照 `DataManagementPages.jsx`、AROS `DataImportsPage.tsx` 和 `ResumeImportJobPanel.tsx`：现有全局详情主要是汇总及三步日志；简历接口已有逐文件结果，但不能据此声称所有资产都有逐项进度接口。
- 沿用现有任务列表与详情 Modal；不重做新建导入步骤、导出或回收站。新建确认页仅将原来固定的 28 条虚构结果改为所选文件摘要，避免与新建任务计数冲突；未解析时不预报成功。

## 交互设计

1. “查看详情”打开同页弹窗，顶部显示文件、资产类型、任务状态、计数单位、更新时间和处理进度。完成进度不等于成功率，失败、跳过、待确认分别列出。
2. 默认查看全部条目，可按处理中（含排队）、成功、失败、待确认、已跳过筛选；支持名称、文件名、原因搜索及分页。
3. 每项展示名称、源文件/表格工作表与行号、状态、当前步骤或结果；展开后查看具体原因、下一步和处理过程。成功结果的资产链接在新标签页打开。
4. 可重试的临时错误生成新的重试任务；原记录保留且不重复重试。缺字段/加密文件要求修正后重传，写入结果不确定需先核实，均不盲目重试。
5. 整文件校验失败时，显示真实失败范围与位置，不伪造逐行进度或“已完成 100%”。关闭详情不影响本地任务状态，再打开仍保留。
6. 用本地虚构数据覆盖混合结果、运行中、失败、读取失败、加载中、无权限、无匹配、任务不存在和手机布局；“刷新状态”只模拟一批变化，无上传、模型调用或业务写入。

## 公共组件

- `ImportTaskDetail`：公共导入明细组合，复用 `Modal`、`Tabs`、`SearchField`、`Pagination`、`StatusBadge`、`ProgressBar`、`StateBanner`、`Button` 和既有图标。
- `import-task-details.js`：样例与纯逻辑；统一派生计数、筛选、进度、重试及 CSV，不在页面另算一套。
- `import-task-detail.css`：仅布局与响应式，沿用现有 `--s1-*` token，不改变全局组件默认样式。

## 后端对接注意（非本次实现）

- 通用任务需提供稳定的 task/item ID、单位、总数是否已知、源文件/行号、逐项状态、处理步骤、时间、可读原因、下一步、可否重试及资产引用。
- 处理中逐项快照/增量及失败报告需要真实接口；不能仅凭汇总数字生成假明细，不用姓名或行号跨任务猜关联。
- 重试应具备幂等性、明确 eligible item 集合、新旧任务关联和原结果保留；写入状态未知先对账。
- 暂不改历史招聘机会导入专用详情；该业务已取消，保留原件与历史审核入口。
