# 任务原型统一交互复核

## 范围与标准

仅修改 GitHub 原型，不修改 AROS 1420、后端、数据库或正式官网。场景全集沿用 `src/stage2/task-design-scenarios.js` 的 62 个入口；本轮增加流式输出的动态检查，不把静态页面加载当作交互验收。

1. 当前操作使用等宽小字，说明读取、检索或工具用途与对象，每项演示约6秒；不显示模型内部推理、固定计划、历史调用列表或闪烁光标。
2. 新产生的自然语言回复按顺序流式输出；阶段结论保留，经过的操作提示消失。历史记录即时阅读，不重新打字。
3. 复用 Markdown/GFM 解析结果渐进展示，不能出现因截断源码造成的未闭合格式；完整输出后与原稿一致。
4. 表单、附件和只读成果沿用既有结构，不逐字生成。写入与发送确认必须等本版回复输出完；选择回答不是写入授权，邮件仍逐封确认。
5. 流式输出可以停止，已显示部分保留，剩余内容不迟到；切换任务清理旧队列。新一轮可继续提出要求。
6. 输出期间暂停下一阶段，避免一边打字一边跳过下一项工具操作。累计耗时包含实际处理和本轮流式输出，结束后定稿；历史快照不虚构耗时。
7. 默认跟随新内容；用户向上阅读时不强行拉回底部。正常任务无右下角黑色提示。

## 本轮处理的问题

- 原来的 `streaming` 只改变组件状态，正文仍整段出现：新增公共渐进输出和顺序队列。
- 一批出现多条回复时会同时展示：逐条输出，后一条等待前一条完成。
- 回复未结束时下一阶段仍可能推进：业务阶段等待输出结束，具体操作仍保留完整演示时间。
- 新建任务停止会重置内容，单资产整理停止后可能继续：保留已显示内容，并暂停后续整理与自动跳转。
- 确认和澄清控件可能早于本版正文完成：输出期间阻止执行，停止后旧确认不再直接使用。
- 推荐报告误用人选匹配的工作提示：增加报告资料读取和报告整理提示。
- 周期轮次摘要在状态变化时不应重新打字：历史摘要单独标记，新产生的补充回复仍流式。
- 不能简单切 Markdown 源码：使用同一套解析器的语法树渐进展示；流式期间不开放未完成链接。
- 流式延长了真实等待：累计计时持续更新，最终值含输出时间；独立调研的显式耗时也计入本次输出。
- 内容增长时需要保持阅读位置：仅在用户处于底部时跟随，不强迫回到底部。
