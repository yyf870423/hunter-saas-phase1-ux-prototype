# 阶段五：设置中心方案交叉 Review

## 1. 与概要设计的对应关系

| 概要设计要求                         | 原型方案对应                               | 结论                         |
| ------------------------------------ | ------------------------------------------ | ---------------------------- |
| 设置不作为主要导航                   | 入口位于用户菜单，移动端归入账户区域       | 一致                         |
| 账户与订阅管理个人工作空间和产品权益 | 六个设置项完整覆盖                         | 一致                         |
| 用户不配置模型、供应商和 API Key     | 设置中心不出现技术配置                     | 一致                         |
| 平台登录和风控只在寻访 App           | 云端只管理设备连接、版本和授权             | 一致                         |
| 至少一种页面外通知                   | 原型采用账号邮箱作为页面外通知渠道         | 一致；具体服务商留给技术方案 |
| 自动授权不能绕过强制门禁             | 强制门禁锁定，自动执行只改变业务确认默认值 | 一致                         |
| 邮件逐封确认                         | 自动化授权页明确邮件不继承自动执行         | 一致                         |
| 移动 Web 功能完整                    | 六页均提供移动布局和操作                   | 一致                         |
| 到期后数据仍可查看和导出             | 订阅和隐私页面明确保留数据访问             | 一致                         |
| 阶段一运营不可查看业务内容           | 隐私说明与诊断包脱敏边界明确               | 一致                         |

## 2. 与当前 Hunter 实现的关系

1. 复用当前系统已经验证的公共 Modal、Toast、Tabs、输入、状态、列表和加载反馈原则。
2. 不复用桌面版设置的信息架构。桌面版以本机技术配置为中心，SaaS 版以个人账户和产品权益为中心，两者目标不同。
3. 数据管理和回收站保留已有独立页面，设置中心只提供明确入口，不复制业务页面。
4. 用量环继续位于导航底部，但点击后应进入“订阅与用量”设置页；快速 Modal 可以保留摘要和“查看详情”入口。

## 3. 已消除的矛盾

1. “设置在用户菜单”与“移动端更多菜单显示设置”冲突：移动端改为账户区域入口，不把设置作为独立主导航功能。
2. “自动执行”与“邮件逐封确认”冲突：邮件明确排除在自动执行授权之外。
3. “寻访 App 设备管理”与“云端不能处理人才平台账号”冲突：云端只展示设备，不展示平台账号、登录态和风控。
4. “设置里支持导出”与“已有数据管理”重复：设置只作为入口，实际导出继续由数据管理承载。
5. “阶段一个人版”与“工作空间管理”混淆：只允许修改个人工作空间信息，不出现成员、角色和团队审批。

## 4. 进入原型实现的门禁

- [x] 页面范围与阶段一边界一致。
- [x] 每个页面的正常和异常路径明确。
- [x] 桌面和移动布局规则明确。
- [x] 公共组件复用边界明确。
- [x] 不新增未经确认的技术设置或团队设置。
- [x] 与概要设计、现有原型外壳和数据管理入口不存在阻塞矛盾。

结论：可以进入设置中心高保真交互原型实现。
