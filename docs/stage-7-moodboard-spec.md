# 阶段七：首页与认证 Moodboard 规格

> 状态：实现中。该文档用于限定 Moodboard 的视觉与交互边界，不代表最终首页信息架构已经审批。

## 一、交付目标

本轮只比较三种对外品牌表达，不设计完整营销站。每套 Moodboard 必须包含：

1. 桌面与移动首屏。
2. 一段能够说明 Hunter 如何工作的业务流程。
3. 用户登录、注册与必要反馈状态。
4. 运营端登录与二次验证状态。
5. 真实可运行的 3D 或空间动效，以及关闭动效后的降级表现。

## 二、共同边界

1. 登录后的 Hunter 产品继续使用已审批的 `WorkBuddy × Vercel AI` 设计语言。
2. 对外页面使用独立公共组件，不复制业务端页面实现，也不覆盖既有 Token。
3. 图标全部使用项目 SVG 组件；不使用字符图标、图标字体或浏览器原生控件外观。
4. 3D 由 Three.js 实现，场景必须对应业务含义。移动端降低粒子数量和镜头移动，`prefers-reduced-motion` 下停止自动动画。
5. 三套方案可以共享认证校验、无障碍和响应式基础能力，但不能共享同一套首屏排版和动效后只换颜色。

## 三、三套方案

### A. AI 招聘编排中枢

| 项目     | 规格                                                                         |
| -------- | ---------------------------------------------------------------------------- |
| 气质     | 克制、精确、可信，强调 Agent 是可监督的执行系统                              |
| 基础颜色 | 深海军蓝 `#050b18`、电光蓝 `#4c8dff`、青色 `#67e8f9`、中性白                 |
| 字体     | Geist 系统栈；标题高对比但不使用夸张超大字号                                 |
| 首屏布局 | 文案覆盖在全屏编排场景上，底部露出流程区首行                                 |
| 3D 场景  | 中央 Hunter 编排核心连接目标、调研、匹配、审核和业务资产；任务脉冲沿连线运动 |
| 动效     | 节点按任务顺序点亮；滚动进入流程区后，对应节点切换为活动状态                 |
| 认证页   | 深色空间背景收敛为亮色认证面板，延续蓝色编排连线                             |

### B. 人才智能图谱

| 项目     | 规格                                                                       |
| -------- | -------------------------------------------------------------------------- |
| 气质     | 清晰、探索、关系驱动，强调信息不是孤立记录                                 |
| 基础颜色 | 冷白 `#f4f7fb`、墨黑 `#121826`、紫蓝 `#695cff`、冷青 `#1fb6aa`             |
| 字体     | Geist 系统栈；更强调编辑式留白和数据标注                                   |
| 首屏布局 | 中央关系网络为主视觉，标题与输入意图悬浮在场景上方和下方，不做左右卡片拼接 |
| 3D 场景  | 公司、岗位、候选人、论文和专利形成分层关系网络；选中节点后邻接关系聚焦     |
| 动效     | 关系逐层展开、证据附着、重复身份合并、结果聚焦                             |
| 认证页   | 冷白背景与可交互关系缩略图，表单更像建立个人工作空间                       |

### C. AI 人才观测站

| 项目     | 规格                                                                 |
| -------- | -------------------------------------------------------------------- |
| 气质     | 主动、敏锐、持续运行，强调发现机会和变化信号                         |
| 基础颜色 | 石墨黑 `#07090d`、冰蓝 `#8bd5ff`、蓝紫 `#7788ff`、警示琥珀 `#ffbf69` |
| 字体     | Geist 系统栈；数据标注更紧凑，标题仍保持业务可读性                   |
| 首屏布局 | 全屏观测场景承载文字，底部使用横向信号摘要，不使用仪表盘卡片墙       |
| 3D 场景  | 时间轨道、扫描扇区和信号柱表示招聘信号、人才变化和待处理机会         |
| 动效     | 扫描、信号出现、优先级分层和任务触发；警示色只用于需要关注的信号     |
| 认证页   | 深色、克制，不模拟安全监控终端；运营端与用户端通过标题和权限说明区分 |

## 四、公共组件边界

1. `PublicBrand`：Hunter 品牌标识和方案副标题。
2. `PublicButton` / `PublicIconButton`：三套主题通过 Token 和 Variant 呈现，不允许原生按钮外观。
3. `PublicNav`：首页导航、登录、申请体验和移动菜单。
4. `SceneCanvas`：Three.js 生命周期、响应式尺寸、降级和无障碍说明；具体几何场景由三个独立构建函数提供。
5. `ProcessExplainer`：流程选择与说明；每套布局独立，业务数据共用同一事实口径。
6. `AuthField` / `AuthSelect` / `AuthCheckbox`：认证表单、错误、禁用和加载状态。
7. `AuthShell`：仅复用认证状态机；三套方案保留各自背景与空间布局。
8. `PublicToast`：认证成功、错误和提示反馈。

## 五、验收尺寸

1. 桌面宽屏：`1440 × 900`。
2. iPad 竖屏：`820 × 1180`。
3. iPhone：`390 × 844`。
4. 低动效：浏览器开启 `prefers-reduced-motion: reduce`。

每个尺寸检查首屏非空、品牌首屏可见、下一段内容有提示、文字不遮挡、按钮可用、Canvas 有有效像素、认证表单不溢出。
