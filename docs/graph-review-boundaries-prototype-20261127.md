## 已确定规则

1. 默认只展示本项变化和必要上下文；按需展开更多内容，不默认复制整图。
2. 单画布叠加原有内容和拟新增/拟修改/拟移除，配合文字状态；关系名称仍仅悬停显示。右侧对照当前值、建议值、证据和影响范围。
3. 可以平移、缩放、自适应、全屏及拖动审核节点。拖动只改临时位置，不能重叠改层级、改接连线或编辑正式内容。
4. 审核项切换只作用于审核区；正式图页的当前图页、节点和相机不随之切换。主动“查看原图”才定位正式对象。
5. 每个审核项在当前图谱内保留自己的临时位置和视角；离开图谱或刷新后复原。建议及处理记录与临时视图分开保存。
6. 修改建议先预览，明确采纳才应用当前项的完整变化；拒绝不改原图。保留已处理记录，不顺带采纳其他项或更改候选人等原始资产。
7. 采纳保留原节点正式位置；新增节点在正式图页另行安排邻近空位，不带入审核预览坐标或重排整图。
8. 无关字段/布局变化不阻塞；相关字段变化必须重新核对；建议已实现则记录为无需重复处理。对象删除、非法结构、重复边、循环层级和缺失依赖不能直接应用。
9. 执行中防重复，失败保留建议并可重试；成功后再更新内容、计数和记录。既有可信来源自动同步规则不变。

### 建议的连续验收路径

1. 人才地图打开“VLA算法组拟调整至机器人学习组”，查看拟移除/拟新增连线及右侧当前/建议内容。
2. 拖开某节点，平移、缩放；切换其他审核项再回来，视角保留。切回图谱内容，正式位置及原有关系不变。
3. 进入“修改建议”，输入新内容，取消后可选择继续编辑或放弃；更新建议预览不改变正式内容。
4. 点击具体确认按钮；处理后查看正式图页，验证完整变化已应用而临时位置未被写入。
5. 返回审核区的“已处理”，可查看记录；刷新后仍能回读已采纳内容与记录。
6. 对另一建议点击“拒绝建议”，确认原图不变，计数下降且记录可查。

### 受控异常入口

以下参数只生成本地、明确标记的验收场景，不注入产品后端；不覆盖普通原型的持久化图谱。路径前缀同上，使用人才地图审核页并追加：

- `&reviewCase=conflict`：本项正式内容已变化，采纳禁用；核对当前差异并点击“已核对最新内容”后，仍需再次明确采纳。
- `&reviewCase=missing`：目标被移除，不能通过直接重新核对绕过，可拒绝旧建议。
- `&reviewCase=already`：建议已实现，只有“记录为无需重复处理”，不重复创建或写入内容。
- `&reviewCase=unrelated`：无关节点位置变动，本项仍可采纳。
- `&reviewCase=fail`：第一次模拟保存失败，保留内容和待审项，重试成功。
- `&state=limited`：只能查看，修改、采纳和拒绝禁用。

## 组件与状态设计

| 文件 | 职责 |
| --- | --- |
| `src/stage4/GraphReviewWorkspace.jsx` | 三栏组合、已处理记录、建议编辑、证据预览、临时视图和失败反馈；复用既有表单、Modal、Tabs、状态与画布组件 |
| `src/stage4/graph-review-model.js` | 明确的逐项变更、字段白名单、当前/建议值、局部投影、重核与完整应用；无API请求 |
| `src/components/TopicGraphCanvas.jsx` | 可选`previewNodeDrag`只开放只读预览的坐标拖动；`initialView/onViewChange`保留同一图谱内的相机，未解除正式编辑限制 |
| `src/stage4/topic-graph-store.js` | 本机一次提交保存变更结果及审核记录；失败先于内存发布，正式版本快照与预览视图分离 |
| `src/stage4/graph-review.css` | 在既有三栏、节点、连线、表单样式上添加差异标识和必要布局，不创建另一套组件视觉 |

三类状态分离：正式图页的节点/关系、审核项的变化及处理记录、当前图谱内的临时预览位置/相机。预览只保留坐标，不保存节点或关系副本来覆盖后续正式事实。应用前再次检查当前字段和必要依赖，不按整图版本号把无关改动误判为冲突。

新增和删除通过完整结果校验后一起发布，已有节点位置不进入变更字段白名单。关系调整的父级与连线端点同步校验；反向关系、悬空节点和循环不能进入采纳结果。标记身份待核实不等于自动确认身份。
