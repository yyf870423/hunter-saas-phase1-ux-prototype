## 阶段边界

以下内容未被本清单标记为缺口，它们按已审批阶段划分进入后续原型：

1. 四类业务主线完整业务剧本、全部等待与分支进入阶段三。
2. 八类正式业务资产的新建、管理、合并和业务闭环进入阶段四、阶段五。
3. 全局设置、通知历史、回收站和运营端进入阶段六、阶段七。

## 第二轮验收专项门禁

1. 业务主线和支线任务的执行计划都位于输入框正上方，不进入对话历史；自动化测试校验计划栏与输入框的实际位置关系。
2. 计划步骤显示“对应要求”；计划变化显示用户补充原文、实际受影响的步骤和保持不变的边界。
3. 信号中心左侧明确标记为“信号列表”，右侧明确标记为“所选信号”；自动化测试实际点击第二条信号并校验右侧标题变化。
4. 桌面端信号详情宽度必须显著大于列表宽度；移动端继续采用列表进入详情并可返回的交互。

## 第三轮验收专项门禁

1. 主线和支线对话的普通回复使用 Markdown 标题、段落、列表、引用、表格和链接，不要求 Agent 生成视觉组件。
2. 执行计划取消左右分栏；展开后先显示单列步骤，计划依据与相关任务均按需展开。
3. 大型候选人审核由 Hunter 受控组件承载；底部明确区分当前查看对象和已勾选批量对象，并说明不会自动联系候选人。
4. 桌面侧栏不再单列设置；设置进入用户菜单，菜单支持点击外部和 `Escape` 关闭。

## 第四轮验收专项门禁

1. 候选人审核不使用“处理方式切换 + 确认”组合。勾选候选人后，三个明确业务按钮直接执行对应批量动作，并共同复用同一确认和反馈逻辑。
2. 主线和支线任务的执行计划统一使用“计划步骤 / 计划依据”标签切换。同一时间只显示一类内容，不使用上下箭头，不把依据追加在步骤下方。
3. 每轮验收必须给出全部页面和可直接访问状态的完整 URL，覆盖 normal、loading、empty、error、disabled、permission-limited、流式中断和恢复状态。
4. 不能通过 URL 单独进入的交互状态，必须给出入口 URL 和逐步操作方法，包括候选人审核、计划切换、相关任务和用户菜单。

## 第五轮验收专项门禁

1. 候选人审核只保留“加入岗位储备”。未勾选候选人继续留在本轮结果中，不提供“本轮排除”或“加入联系名单”。
2. 执行计划不提供“计划依据”视图或二级切换；展开后直接显示调整摘要和单列步骤。
3. 主线和支线任务的计划箭头统一为收起时向上、展开时向下，并由自动化测试校验 SVG 路径。
4. 结构化审核和自然语言筛选都只建立岗位储备关系；审核完成后，主线再接收需要联系哪些候选人的后续指令。
5. 主线、支线和新建页共用自动高度 `Composer`；测试覆盖初始高度、多行增高、最大高度、内部滚动、清空恢复和 `resize: none`。
