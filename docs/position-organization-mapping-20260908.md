# 岗位人才梳理与公司组织梳理

日期：2026-09-08。状态：已按用户最新决定更新，交付用户检查。仅为可交互 SaaS 原型，不修改正式 Hunter 产品。

## 业务边界

- 岗位人才摸排：沿用岗位招聘找人流程。审核入储备与岗位人才梳理原子同步，按稳定候选人 ID 去重；保留匹配依据、风险、来源与当前阶段。不自动联系、不把已推进人选退回储备。
- 公司组织梳理：针对一个或多个明确公司，梳理公司、部门、团队、关键岗位和任职人；按公司分别保存人才地图。任职人未知不等于岗位空缺，身份冲突不自动合并，未核实关系不伪装为组织隶属。
- 人才地图仍是知识图谱类型；不默认附送公司关系图、候选人关系图或联系路径，不自动加入岗位储备。保留缺口可交付已核实部分，“暂不保存”不能显示完成。
- 本轮用已知四家公司及候选人样本模拟语义判断，不接入真实搜索、LLM 或服务器。其他公司需提供明确范围和资料，不能用默认公司冒充结果。

## 公共组件

岗位复用审核工作区、FieldGroup、HierarchyTable、RelationshipCanvas、Modal、状态标签、筛选及公共提示；新 PositionTalentMap 在既有和新建岗位间共用。表格只保留实际公司/人选两层，关系图是同一审核结果的投影，业务人选与匹配依据不能在图上独立增删，避免与岗位流程脱节；布局仍可拖动。

公司组织梳理复用统一任务外壳、ContextReviewPanel、ReviewHeader、关系画布及知识图谱多图页组件。组织样本和转换在 organization-mapping-data.js 统一维护；任务标题、审核、完成态和资产图页引用同一数据。

## 交互覆盖

| 操作           | 入口                                       | 正常与异常验证                                                                     |
| -------------- | ------------------------------------------ | ---------------------------------------------------------------------------------- |
| 岗位人选审核   | `#/tasks/position-vla?state=review`        | 选择入储备、自然语言筛选提交；未选人不入库，非法 ID、过期版本、仅分析/受限模式拦截 |
| 查看人才梳理   | `#/positions/position-vla?tab=talent-map`  | 表格/关系图、来源任务、匹配与风险详情、搜索、无匹配、空态；刷新保留数据            |
| 岗位数据联动   | 审核提交与流程推进                         | 重复提交幂等、状态不退回储备；本地存储失败不部分写入，可重试                       |
| 公司范围       | `#/new` 输入公司组织梳理目标               | 单公司与多公司范围；按公司隔离，不扩成其他公司                                     |
| 组织批次审核   | `#/tasks/mapping-embodied?state=gaps`      | 三组审核、公司切换、证据、冲突决定；未知位置继续保留                               |
| 保存人才地图   | 完成审核后选择更新                         | 保存成功才显示完成；失败可重试、重复打开不覆盖；不同批次保留其他图页及人工修改     |
| 完成与回看     | `#/tasks/mapping-embodied?state=completed` | 完成对话、缺口、查看地图、继续补充；刷新可恢复                                     |
| 客户旧确认显示 | `#/tasks/client-xinglan`                   | 仅首次草稿“是”兼容显示“确认”，底层决定原文与后续答复保留                           |
