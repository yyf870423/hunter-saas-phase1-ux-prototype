# 工作台首页展示迭代

日期：2026-09-08。用户已授权直接推送并更新详细设计。本轮只调整独立 SaaS 原型工作台的展示形式及公司组织梳理任务标签，不修改正式 Hunter 产品。旧的纯表格展示约定由本节替代，原信息、优先级和数量规则不变。

## 已确认需求与现状

- 保留任务类型、名称、进度、状态，以及洞察和资产变化的全部信息，改为更适合首页的展示形式。
- 任务、洞察、资产变化分别最多 10 条，默认分别 5、8、10 条。
- 按待你处理、待你验收、正在推进、等待外部排序，同组稳定，先排序再限量；置顶和完成比例不覆盖顺序。
- 进度沿用计划完成步数及当前步骤，不使用业务对象数量或虚假时间、工作量百分比。
- 全局空、局部空、加载、错误、禁用、来源受限及原有新任务和行动队列行为均保留。
- `mapping-embodied` 任务类型摘要改为“公司组织梳理 · 人才地图”，不全局重命名知识图谱资产。

已阅读当前 `Dashboard.jsx`、`DashboardWidgets.jsx`、任务步骤与业务数据、公共组件清单，以及先前焦点式工作台实现。当前信息准确，但三个区域均为连续列表；本轮恢复重点展示，不恢复早期只有少数条目的数据量。

## 布局与交互

1. 保留产品框架、明暗主题、问候语与紧凑自然语言新任务入口。
2. 上方全宽任务区内，左侧约 56% 展示当前任务，右侧约 44% 展示可切换任务。焦点包含类型、状态、名称、对象、摘要、完成步数、当前步骤、实际计划节点和进入任务入口。
3. 默认聚焦排序后的第一项。右侧保留四项原信息，点击只切换预览，独立箭头直接进入详情；方向键、Home、End 可切换。窄屏点击后滚动回当前预览，避免更新发生在屏幕外。焦点和切换项使用同一数据，不建立第二份审核状态。
4. 下方洞察与资产变化双栏顶部对齐。洞察为单项卡片，资产为图标节点与细线串联的时间线；名称先于类型、时间及状态说明。
5. 洞察默认两列，内容区不足 1050px 时一列；内容区不足 760px 时任务焦点与切换区、洞察与资产区均纵向排列，平板洞察可用两列，手机单列。只使用全页滚动，不自动轮播、不填充空白行。
6. 三个分区使用无外框标题、语义图标和实际展示数量，标题 18px；任务区上下细边界，内部竖线区分焦点与切换区。分区和动态双栏间距 32px，手机 28px；标题区桌面最小 48px、手机 44px。页面分区不包成浮动卡片，不添加阴影。
7. 任务切换项最小 88px，长文本自然增长；名称 14px、辅助文字不小于 12px。焦点标题桌面 22px、手机 20px，计划节点桌面三列、手机两列。洞察单项卡片圆角 8px，资产时间线不使用卡片。不新增装饰图、统计大卡或不真实的进度条。
8. 洞察仍包含来源数、时间、真实处理状态和下一步，不把已处理或忽略条目误称待办；点击整卡进入原洞察。资产保留名称、类型、时间和变化说明，进入原资产，联系人回所属公司的子资产。
9. 行动队列保留在页末且默认收起。无任务时不显示示例待办，但真实机会跟进事项不能因此隐藏。自然语言输入保留空白禁用、输入法确认、Shift+Enter 换行、Enter 提交及保存失败保留草稿。

## 公共组件与数据边界

- `DashboardSection`：无外框分区标题、图标、实际数量、可选全量入口及内容容器。
- `TaskFocusBoard` / `TaskPlanMilestones` / `TaskProgressSummary`：复用公共 `Button`、`IconButton`、`StatusBadge`、`TooltipText`；计划节点按已完成、当前、后续区分，没有计划的动态任务保留原摘要，不生成虚假节点。
- `DashboardInsightCards` / `DashboardAssetTimeline`：共用 `DashboardFeed` 数据渲染，使用不同业务表现；只给单条洞察加卡片边框，不嵌套卡片。
- `DashboardListSkeleton`：任务使用焦点与切换区骨架，其他区域保留对应摘要骨架。公共 `EmptyState` 的 compact 规格承载空态。
- `DashboardTaskStarter` / `ActionQueue`：复用原交互和领域来源，无第二份完成状态。
- `Dashboard.jsx` 为页面组合层，`dashboard.css` 为共享布局，`dashboard-data.js` 提供示例、计划快照、排序和限量；组件预览页复用同一组件。

计划来源为岗位 `planSteps`、业务 `businessScenarios.plan` 和人物核验 `identityReviewPlan`，完成 ID 是原型快照；只统计有效且去重的已完成步骤。当前示例为岗位 4/5、客户 1/6、公司组织梳理 3/5、求职 3/5、核验 2/3。无计划显示待生成，全完成不再标记当前步骤。动态机会任务继续使用本地领域状态及既有摘要，不伪装为已有完整计划。本轮不增加正式后端同步，不修改任务详情布局。

## 状态与验收入口

| 状态     | 路由                              | 验收重点                                                   |
| -------- | --------------------------------- | ---------------------------------------------------------- |
| 正常     | `#/home`                          | 5/8/10、任务预览与直接打开、计划节点、洞察卡片、资产时间线 |
| 全局空   | `#/home?state=empty`              | 三个零数量区域、新建及导入，不显示示例行动队列             |
| 任务为空 | `#/home?empty=tasks`              | 新建任务入口，其他两区不清空                               |
| 洞察为空 | `#/home?empty=insights`           | 轻量空态，不制造待处理数量                                 |
| 资产为空 | `#/home?empty=assets`             | 保留导入入口，不影响其他区域                               |
| 加载     | `#/home?state=loading`            | 三区骨架、禁用输入、无错误零数量                           |
| 局部错误 | `#/home?state=error`              | 洞察可重试，任务和资产可用                                 |
| 来源受限 | `#/home?state=limited`            | 已有内容可读，可进入连接设置                               |
| 容量     | `#/components?dashboard=capacity` | 每类传入 12 条，先排序后最多呈现 10 条                     |

交互覆盖包含所有 5 个任务预览和详情、8 条洞察、10 条资产、新任务成功与存储失败、行动队列、键盘导航、全局与局部空、容量、桌面/平板/手机、明暗主题。实现用例见 `tests/stage1/dashboard.spec.js`，公司组织梳理标签在 `tests/docs/position-organization-mapping.spec.js` 覆盖。
