# 工作台摘要布局迭代

日期：2026-09-07。状态：首轮及后续分区、计划步骤进度迭代已完成，待用户验收。本轮仅修改独立 SaaS 原型，不修改 Hunter 正式实现或在线文档，尚未提交或推送。

## 已确认需求

- 任务不再突出单个焦点，统一显示任务类型、名称、进度、状态；统一行规格不等于没有业务优先级。
- 任务、洞察、资产变化分别最多展示 10 条；默认原型分别展示 5、8、10 条。
- 同时设计整个工作台为空和某一区域单独为空的状态。
- 全列表形式可以保留，但信息密度不能导致无从下手；至少任务、洞察和资产变化要有明显区域划分。
- 最新进度反馈明确针对工作台：显示计划共多少步、已完成多少步，以“已完成 X / Y 步”及当前步骤表达；不要求重新设计任务详情。
- 最新优先级反馈：需要用户处理的在前，其次需要用户验收，最后正在推进。

## 现状与布局决策

已阅读实际 `Dashboard.jsx`、阶段一 Token、公共 `DataTable` / `EmptyState` 和任务、洞察、资产真实原型数据。旧工作台将 1 条任务放大，另外 3 条用于切换，洞察与资产变化均只有 3 条并纵向堆叠；空状态隐藏其余区域。这些结构无法承载本轮信息密度。

1. 保留既有视觉体系和自然语言新建入口，缩短头部及新建区域的占用。
2. 上方全宽任务表格，使四项信息可以逐行横向比较；不再保留选中焦点、摘要大卡或“继续任务”的二次操作。
3. 下方洞察与资产变化双栏，顶部对齐，各自自然增长；窄内容区改为单列。全页统一滚动，不添加区内滚动、不凑空白行或自动轮播。
4. 区域标题显示实际展示数量。两类内容都是混合状态的最近摘要，洞察不再称为“需要处理的洞察”，避免将已处理/忽略条目误标为待办。
5. 任务进度按最新反馈改为“已完成 X / Y 步”，次行显示当前步骤。分母是当前计划的步骤数，不是未知市场覆盖率或候选人数，不显示时间或工作量百分比；未生成计划时显示“计划待生成”，不能伪造 0/0。
6. 列表项直接进入现有任务、洞察和资产详情；原有行动队列保留在页末，默认收起，任务为空时不显示示例待办。
7. 后续分区反馈覆盖首轮弱标题边界：三个区域统一使用 56px 中性标题带、语义图标与上下细边界，标题为 18px；任务到动态区留白 40px，动态双栏间距 48px 并设中间分隔线。窄内容区改为单列、24px 分区间距，手机标题带 48px。不使用浮动卡片、阴影或装饰性色带。
8. 任务行高为 68px；动态条目先读 14px 名称，再读 12px 类型、时间及状态说明，桌面上下留白 20px、手机 16px。保留完整字段、原有条数和全页滚动，不靠隐藏信息降低密度。正常、空态、错误与加载态共享分区边界。
9. 工作台任务按待你处理、待你验收、正在推进排序，等待外部保留独立标签并置末；处理指补充信息、授权、决定或异常恢复，验收指已有结果等待审核。状态列使用相同公共标签，不另加优先级列、Tab 或焦点卡。同优先级稳定排序，先排序再截取最多 10 条，置顶和计划完成比例不覆盖该顺序。

## 公共组件

- `DashboardSection`：中性分区标题带、可选语义图标、实际数量、可选全量入口及内容容器；无卡片外框或阴影。
- `DashboardTaskStarter`：复用现有自然语言输入样式与公共按钮，保留空白禁用、输入法确认、换行、提交和失败草稿；任务为空时仍可使用。
- `TaskSummaryTable` / `TaskProgressSummary`：组合公共 `DataTable`、`StatusBadge`、`TooltipText`；桌面四列，手机重排为类型与状态、名称、进度。进度的主行是完成数/总步数，次行是当前步骤；尚未生成计划和所有步骤完成有明确文案。不发明新的表单或状态标签样式。
- 工作台关注状态配置与 `orderDashboardTasks`：统一分类、标签、颜色和排序，`getDashboardData` 与公共任务表格均先排序后限量。未知分类显示原执行状态并置末，不将其自动归为待处理。
- `DashboardFeed`：洞察与资产共用的连续摘要行，名称优先，类型、时间、状态及下一步/变化摘要作为辅助层；没有卡片套卡片。
- `DashboardListSkeleton`、公共 `EmptyState` 的 compact 规格：匹配摘要区域的加载和空状态，不使用巨大插画、虚假进度或占位记录。
- 页面壳 `Dashboard.jsx` 仅组合公共业务组件；布局放在 `dashboard.css`，示例和最多 10 条的限制放在 `dashboard-data.js`。

## 状态与验收入口

| 状态         | 路由                    | 表现                                                   |
| ------------ | ----------------------- | ------------------------------------------------------ |
| 正常         | `#/home`                | 任务 5 条、洞察 8 条、资产变化 10 条                   |
| 全局空       | `#/home?state=empty`    | 保留新建入口与三个零数量区域，不显示示例数据和行动队列 |
| 任务为空     | `#/home?empty=tasks`    | 任务区显示新建任务，洞察和资产保留                     |
| 洞察为空     | `#/home?empty=insights` | 轻量“暂无洞察”，不制造待处理计数                       |
| 资产变化为空 | `#/home?empty=assets`   | 轻量“暂无资产变化”，保留导入入口                       |
| 加载         | `#/home?state=loading`  | 三个区域骨架，新建按钮禁用，不展示错误的零计数         |
| 局部错误     | `#/home?state=error`    | 只有洞察报错，可重试，其他区域保留                     |
| 来源受限     | `#/home?state=limited`  | 保留已有结果，局部说明受限来源                         |

正常条目导航、自然语言开始任务、空态新建与导入、错误重试、行动队列、最大容量、长文本、桌面/平板/手机及明暗主题均需验证。组件库保留摘要组件的 normal、capacity、empty 示例；容量用例是明确的组件示例，不添加到正式工作台数据。

## 数据边界

任务与洞察使用当前任务和洞察模块的示例数据，资产变化指向真实存在的原型对象。步骤复用岗位 `planSteps`、三类业务 `businessScenarios.plan` 和人物核验 `identityReviewPlan`，完成 ID 为工作台示例快照；计算函数从步骤定义求总数，只统计已完成 ID，不把重复、未知 ID 或等待中的步骤算作完成。对应示例为岗位 4/5、客户 2/5、摸排 3/5、求职 3/5、核验 2/3。页面不另建审核状态，原型快照不代表真实用户记录或跨页面实时同步；本轮不增加正式后端状态同步，也不改变任务详情布局。

后续优先级示例使用显式 `attention`：客户开发和人物核验待处理；岗位已交付候选人结果，待验收；人才摸排正在推进；求职任务等待外部。工作台展示为关注状态摘要，保留原始执行状态字段，不改写详情状态，也不根据完成步数自动推断是否验收。
