## 三、基线边界

1. 该提交代表统一资产内 AI 协作工作区改造前的现有原型代码。
2. 记录基线时，新的统一协作工作区尚未写入原型代码。
3. 当前本地存在未跟踪的产品讨论、影响分析和交接文档，它们不属于该 Git 提交，但必须保留。
4. 后续原型改造应形成边界清晰的独立提交，便于只撤销相关变化。
5. 回滚不能使用会覆盖未提交文件的破坏性命令。应优先撤销后续独立提交，或按基线提交恢复明确列出的原型文件。

## 四、原型验证门禁

统一交互至少需要验证以下场景：

1. 专题图谱生成、增量更新、变更预览和双向定位。
2. 候选人信息补全、字段变化、证据和资料版本。
3. 岗位 AI 解析、JD 变化和岗位解析建议。
4. 公司调研、资料草稿、来源证据和字段审核。
5. 论文、专利解析与人物身份处理。
6. 推荐报告等文件生成、在线预览、继续修改和历史产物查看。
7. 运行中、等待用户、失败、重试、取消、恢复和授权切换。

只有这些场景的原型交互均可理解、可操作且没有明显空间问题后，才更新正式详细设计并替换当前资产 AI 交互。
