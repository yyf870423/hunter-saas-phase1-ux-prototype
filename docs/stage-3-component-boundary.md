# 原型阶段三组件边界

> 状态：组件边界已按阶段三实现并完成回归，等待阶段三人类审批。
>
> 本文件约束阶段三如何复用阶段二组件并新增业务组件，防止四条主线变成四份重复页面或单一页面换文案。

## 一、公共外壳

以下结构只能有一套实现：

1. 业务主线历史、收起与展开、新建工作入口。
2. 主线头部、状态、暂停、继续、终止和删除菜单。
3. 对话滚动区、用户消息、Hunter Markdown 回复和流式状态。
4. 执行计划、计划调整、相关内部任务和任务详情检查。
5. 对话输入、附件、授权模式、发送、停止生成和输入框自动高度。
6. 加载、流式中断、权限受限、局部失败和等待外部状态。

公共外壳通过稳定接口接收主线身份、计划、任务、对话事件和业务审核入口；不能在外壳中硬编码某一种主线的字段。

## 二、主线剧本配置

四条主线分别维护独立剧本配置，至少包括：

1. 主线身份、来源对象、目标和默认授权。
2. 渐进阶段、每阶段可见对话和推进条件。
3. 计划步骤、内部任务、调整规则和结束条件。
4. 专用结果类型、审核入口、等待对象和恢复动作。
5. 通用状态和专用分支状态。

剧本配置不能只提供标题和文案；必须提供不同的过程对象、业务命令、结果结构和分支处理。

| 组件         | 使用主线                       | 必须显示                                                 | 不负责                           |

| 联系人审核   | 客户开发                       | 姓名、角色、公司关系、联系方式、来源、可信度、是否可联系 | 自动发送消息、完整联系人资产管理 |
| 招聘机会摘要 | 客户开发                       | 公司、需求、确认依据、联系人、方向、缺口、岗位形成状态   | 伪造正式岗位、复制完整 JD        |
| 候选人审核   | 岗位招聘                       | 完整候选人资料、得分、理由、风险、证据、建议动作         | 联系候选人、改变推进阶段         |
| 人才版图批次 | 人才摸排                       | 公司、组织、方向、人物、关系、来源、冲突、行动缺口       | 猜测未知关系、显示虚假百分比     |

## 四、数据与组件映射

1. Agent 普通输出统一映射为 Markdown，不允许直接注入 HTML。
2. 受控组件只接收代码校验后的结构化数据；未知只读结构降级为 Markdown 文档。
3. 涉及正式写入、外部操作或业务审核的未知结构必须停止，不能降级放行。
4. 自然语言决定与受控审核操作映射到同一业务命令和对象集合。
5. Mock 数据中的人数、状态、对象名称和关联去向必须在主线历史、执行计划、对话、审核和结果摘要中一致。

## 五、响应式映射

1. 桌面中量详情使用右侧检查区；移动端使用全屏覆盖层。
2. 桌面大型审核占用主要工作区；移动端使用完整页面式审核。
3. 桌面表格在移动端转换为字段分组列表，不使用横向滚动。
4. 主线历史在桌面可收起，在 iPad 和 iPhone 作为可关闭导航面板。
5. 组件 normal、loading、empty、error、disabled、permission-limited 和 waiting 状态使用同一 token 与反馈规则。
