## 二、本轮必须统一的产品口径

### 2.1 用户侧对象

1. 用户只创建和管理“任务”，不再理解“工作”“业务主线”“支线任务”或“独立工作”。
2. 任务可以一步交付，也可以形成持续更新的执行计划；用户不选择任务类型。
3. 任务没有“完成后不可继续”的终态。一次交付结束后显示“可继续”，用户仍可以继续对话和补充资料。
4. 用户侧正式入口统一为 `#/tasks` 和 `#/tasks/:taskId`，不兼容尚未开发的 `#/works/*` 与 `#/workstreams/*`。

### 2.2 资产 AI 与运行

1. 从资产详情发起的岗位 AI 解析、候选人信息补全、已有公司调研、人岗匹配、推荐报告生成和图谱内 AI 整理属于“资产 AI”，不创建任务，也不进入任务列表。
2. 用户从全局新建入口提出同一目标时，才按照任务执行。
3. 内部运行统一分为任务运行、任务步骤运行、资产 AI 运行和系统运行。
4. 用户只在所属任务或资产中查看必要的运行状态；运营端从“运行与故障”查看脱敏记录。

### 2.3 云端合规边界

1. Hunter 云端不登录、操作或控制需要认证的人才平台。
2. Hunter 云端不与本地 App 或浏览器插件交换任务、运行状态和结果。
3. 外部简历只由用户主动上传；上传必须在对话或资产中显示为用户输入，并经过文件门禁、身份判断、查重、合并和匹配。
4. 设置中心不再包含配套设备、连接码、设备授权和版本状态。

### 2.4 知识图谱与关系视图

1. “人才摸排”是任务或业务过程；“知识图谱”是正式业务资产，两者不能混用。
2. 一份知识图谱包含一个或多个图页。每个图页保存节点实例、层级、关系、布局、备注和资产关联。
3. 同一图页可以在画布和层级表格之间切换，两种视图展示同一份内容。
4. 图谱本地内容、共享关系、来源业务关联及其派生关系必须区分所有者，不能复制成多份相互冲突的数据。
5. 正式资产或来源关系发生变化时，已存在的知识图谱和资产关系视图自动更新；证据不足或关系冲突时显示待确认标记，并进入通知或行动事项。
6. 候选人联系路径、岗位重点人才、公司关系与人才流动是对应资产中的关系视图，不是自动创建的知识图谱，也不要求存在知识图谱后才能生成。
7. 这些资产关系视图默认不存在。用户从资产详情用自然语言发起创建或更新；创建后才显示图、表格或关系标签。

## 三、文档结构决策

### 3.1 文档数量和编号

保持 `00—13` 共 14 篇，不增加文档，不调整编号。原因如下：

1. 现有文档职责边界仍然成立。
2. 知识图谱继续由 `08` 单独负责，不需要新增“关系数据库”文档。
3. 任务、资产 AI 和运行分别由 `01—04` 共同定义，不需要再拆一篇技术对象文档。
4. 候选人、岗位、公司和学术关系仍应回到对应资产文档说明，避免把所有关系交互堆入 `08`。

建议调整以下在线标题：

| 编号 | 当前标题             | 调整后标题           |
| ---- | -------------------- | -------------------- |
| 01   | 工作、执行与资产关系 | 任务、运行与资产关系 |
| 02   | 工作                 | 任务                 |
| 03   | 工作执行与恢复       | 运行与恢复           |
| 08   | 人才版图             | 知识图谱             |

其他在线文档标题保持不变。

### 3.2 版本表处理

本轮不在方案阶段自动修改任何在线文档版本号。正式更新时应先由产品负责人确认是否形成新的文档版本；确认后再统一追加版本记录，不能由脚本按更新时间自动生成。

### 3.3 概要设计边界

本轮不修改已经审批的产品概要设计。详细设计更新完成并审批后，只整理一份“概要设计最小影响清单”，再由产品负责人决定是否更新概要设计。不得在详细设计更新过程中顺带改写上位文档。

## 四、逐篇修改方案

2. 将 `08 人才版图` 改为 `08 知识图谱`，职责摘要改为“多图页、节点与关系、资产关联、导入、Agent 更新、版本和实时同步”。
3. 补充资产 AI 的阅读路径：先读 `01` 和 `04`，再读对应资产文档。
4. 说明候选人联系路径、岗位重点人才、公司关系与人才流动由 `05—07` 负责，`08` 只定义知识图谱资产。
5. 更新本批次边界：独立外部简历工具不属于 Hunter 云端产品，不再表述为待设计的“配套寻访 App”。
6. 更新文档关系图和职责表；现有全局状态截图无产品变化时保留。

### 4.2 `01 工作、执行与资产关系`：大改

1. 标题改为“任务、运行与资产关系”。
2. 核心对象从三类改为五类：任务、资产 AI、运行、信号和正式资产。
3. 删除“工作执行 / 相关任务执行 / 系统后台任务”定义，改为任务运行、任务步骤运行、资产 AI 运行和系统运行。
4. 重写对象演进图：用户输入或信号形成任务；资产详情操作形成资产 AI；二者产生运行和过程成果；确认后更新正式资产；资产变化继续影响匹配、知识图谱和资产关系视图。
5. 增加关系所有权总则：
   - 知识图谱本地节点、连线、备注和布局由知识图谱维护。
   - 人岗匹配、岗位流程、论文作者等由来源资产维护。
   - 前同事、共同作者、共同发明人和人才流动由来源记录派生或由独立证据补充。
   - 资产关系视图只引用和展示，不复制来源事实。
6. 删除本机任务包、等待本机结果和跨端合并冲突流程，改为用户上传文件后的身份、字段和关系冲突。
7. 将完整示例改为当前岗位招聘任务：系统候选人、知识图谱、公开资料、论文专利和用户上传简历共同形成候选结果；人岗匹配和推荐报告在资产内处理。
8. 替换对象关系画板和任务详情截图。

### 4.3 `02 工作`：大改

1. 标题改为“任务”，所有用户可见对象统一使用“任务”。
2. 新建流程改为一个自然语言入口：目标歧义时纵向给出选项并保留自由输入；简单目标可以不生成计划；复杂目标生成并持续更新计划。
3. 删除“系统判断工作或相关执行”的用户文案。内部拆分只影响运行，不形成第二套用户对象。
4. 删除“完成”终态，改为“可继续”；保留运行中的等待、暂停、失败和恢复状态。
5. 任务列表以客户开发、岗位招聘、人才摸排、候选人求职和其他任务为业务场景 Tab，状态使用快速筛选。
6. 四类业务任务保留业务差异，不把场景变成创建前表单。
7. 用户补充文字、链接、截图和文件必须作为对话输入出现；上传简历后只重新处理受影响范围。
8. 人才摸排任务在用户完成结果审查后，才在对话中询问是否保存到已有知识图谱或更新已有图页；不能静默创建顶层知识图谱。
9. 删除所有 `#/works/*` 和本机协作状态，替换为当前 `#/tasks/*` 路由和用户上传简历状态。
10. 更新新建任务、任务列表、任务详情、任务等待、流式中断、上传批次和冲突截图。

### 4.4 `03 工作执行与恢复`：大改

1. 标题改为“运行与恢复”。
2. 运行范围统一为任务运行、任务步骤运行、资产 AI 运行和系统运行。
3. 明确运行可以成功、失败、暂停、取消和恢复；任务本身在一次交付后仍可继续。
4. 定义所属对象：任务运行和任务步骤运行归属任务；资产 AI 运行归属资产及处理记录；系统运行可以没有用户任务归属。
5. 增加知识图谱实时同步、关系派生、岗位重点人才增量重算等系统运行的幂等、重试和失败恢复要求。
6. 恢复不能重复写入资产、重复创建图页或重复发送外部动作；无法证明安全时不提供恢复操作。
7. 用户侧不提供运行列表；运营端只查看脱敏元数据和所属对象。
8. 更新运行类型图、生命周期图、恢复状态和运营定位截图。

### 4.5 `04 资产公共规则`：中等修改

1. 正式资产中的“人才版图”改为“知识图谱”。
2. 增加知识图谱、图页、节点实例、关系、正式资产关联和历史版本的公共边界，但具体画布操作由 `08` 负责。
3. 增加“图谱本地内容 / 共享关系 / 来源业务关联 / 来源派生关系”的所有权规则。
4. 增加资产关系视图公共生命周期：未创建、生成中、可查看、更新中、失败；创建后允许自然语言更新和人工编辑。
5. 明确从资产详情发起的确定性 AI 操作属于资产 AI，不创建任务；审核、版本、失败和处理记录仍使用资产公共规则。
6. 增加实时传播规则：来源资产变化自动更新引用视图，不覆盖用户本地文字和布局；证据不足时进入待确认。
7. 文件可以关联知识图谱和图页；知识图谱导入的专属结构由 `08` 定义。
8. 删除和恢复需要区分删除节点实例、删除图页、删除知识图谱、删除共享关系和删除正式资产。
9. 更新资产公共关系图和资产 AI 审核截图；现有列表、合并、回收站截图可保留。

### 4.6 `05 候选人资产`：中等修改

1. 将“人才版图人物节点”改为“知识图谱节点”，并说明同一候选人可以被多个节点实例引用。
2. 候选人信息补全改为资产 AI：从候选人详情发起，不新增任务；支持启动、运行、审核、失败和处理记录。
3. 在详情中补充学术关系与联系路径：
   - 学术成果和合作人分别使用分页表格，适应 50—100 条关系。
   - 合作人表显示人物、合作类型以及论文或专利名称。
   - 联系路径使用独立关系图 Tab，不与学术表格挤在同一块区域。
4. 联系路径默认不存在，由用户用自然语言创建或更新；即使已有手机或邮箱也允许生成。手机号表示可直接联系，邮箱不等同于高成功率的直接关系。
5. 联系路径图使用与知识图谱一致的画布交互：拖动、滚轮缩放、平移、搜索、全屏、节点和连线详情、双击编辑、新增节点和删除确认。
6. 候选人资料、公司经历、论文专利和身份变化自动刷新已经生成的关系视图；不自动创建尚不存在的联系路径。
7. 补充关联知识图谱入口，但不在候选人详情复制图谱正文。
8. 替换补全处理、学术关系、联系路径空状态、生成中、正常图和异常状态截图。

### 4.7 `06 岗位与招聘推进`：中等修改

1. 明确“开始找人”和“人岗匹配”的差异，并在对应入口使用产品 Tooltip：
   - 开始找人创建任务，从已有资产、知识图谱、公开资料、论文专利和用户上传简历持续寻找候选人。
   - 人岗匹配属于资产 AI，只计算系统已有候选人与当前岗位的适配程度。
2. 岗位 AI 解析、人岗匹配和推荐报告改为资产 AI，不进入任务列表；岗位详情保留处理记录。
3. 推荐报告保留完整对话和文件预览，支持持续修改；匹配结果显示最新文件，历史版本留在处理对话中。
4. 增加“重点人才”关系结果：
   - 不依赖已有知识图谱才能生成；有相关知识图谱时作为重要输入。
   - 默认不存在，用户用自然语言创建或更新。
   - 创建后可以在关系图和层级表格之间切换，两种视图展示同一份结果。
   - 表格提供身份和状态筛选，可打开系统候选人详情。

5. 重点人才图使用统一关系画布交互，且不显示“关联知识图谱”占位区。
6. 更新岗位 AI、匹配运行、推荐报告、重点人才未创建、生成中、表格和关系图截图。

1. 已有公司调研改为资产 AI；新建公司时的公开调研仍属于资产创建流程。
2. 公司详情增加“公司关系与人才流动”：
   - 默认不存在，用户用自然语言一次创建两类关系数据。
