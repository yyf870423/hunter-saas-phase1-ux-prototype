# 原型阶段六：运营端实施计划

> 状态：高保真原型已完成，等待产品负责人审批。
>
> 日期：2026-08-24。

## 一、目标

运营端用于判断产品运营是否符合预期、处理用户与商业事项、恢复系统问题，并管理 Hunter 托管的外部能力。它与用户产品使用独立页面壳、独立导航和独立角色边界。

运营端不能查看候选人、岗位、公司、联系人、人才版图、论文、专利、对话、提示词、任务输入或 Agent 输出正文。排障只使用工作空间、任务、错误码、脱敏调用链、服务状态、用量、资源状态和用户主动提交的诊断包。

## 二、模块

1. 运营概况：运营趋势、系统风险、任务处理和用户商业事项。
2. 用户与工作空间：工作空间、用户账号和试用申请。
3. 订阅与额度：订阅工作空间、支付订单和权益调整。
4. 任务与故障：任务运行、错误聚合、脱敏详情和安全恢复。
5. 系统能力：能力健康、降级状态、供应商路由和配置验证。
6. 支持与审计：最小支持记录、诊断包、操作审计和安全事件。

## 三、角色

阶段一只保留运营人员和系统管理员两个固定角色。

- 运营人员可以处理试用、订阅、额度、支持，以及系统明确判定安全的技术恢复。
- 系统管理员额外管理供应商、模型路由、密钥、降级策略和安全事件。
- 两个角色都不能查看用户业务内容、绕过业务门禁、代替用户审核或启动新的业务任务。

## 四、交付门禁

1. 六个模块、页面内 Tab、列表、详情、筛选和分页均可交互。
2. 试用审批、权益调整、安全恢复、配置验证、支持处理和安全事件覆盖正常与失败路径。
3. normal、loading、empty、error、permission-limited 及业务异常状态有明确入口。
4. 桌面、iPad 和 iPhone 无页面级横向溢出。
5. Mock 数据在工作空间、订阅、任务、诊断包、支持和审计间保持一致。
6. 产品负责人审批前不编写运营端正式详细设计。
