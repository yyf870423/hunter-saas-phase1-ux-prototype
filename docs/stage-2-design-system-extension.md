## 三、布局与显示规则

1. 用户输入采用右侧有边界容器；Hunter 回复使用无头像、无气泡的全宽 Markdown。
2. 计划和内部任务常驻输入框正上方并默认收起，不能混入对话历史或长期挤占对话主区域；展开内容设置最大高度和独立滚动。
3. 少量结果在对话内显示，中量结果打开同页检查区，大量审核临时占据主工作区。
4. 桌面端候选人审核和信号使用列表/详情并列。信号左侧使用次级背景、列表标题和选中指向，右侧使用“所选信号”标题及主画布背景；详情宽度显著大于列表。移动端详情覆盖当前工作区并提供明确返回。
5. 等待状态不使用持续动画；只有实际运行或流式生成时显示动态反馈。
6. 错误优先在失败组件附近显示，保留已有内容并提供恢复动作，不使用阻断全页的全局 Banner。
7. 所有辅助文字不低于 `12px`；状态标签、工具栏按钮和候选人关键决策信息禁止拆分换行。
8. Agent 和支线任务正文只生成 Markdown 语义内容，不生成带视觉样式的业务组件；Markdown 表格、引用和链接由统一渲染器负责显示。
9. 执行计划展开后直接显示单列步骤和必要的计划调整提示，不设置“计划依据”或其他二级切换。2026-11-18 用户要求调整原型：点击“当前进度”的某一步，在该步骤下展开所属相关处理；一次只展开一个步骤，不再在底部集中堆放全部相关处理。再点处理行打开该记录的右侧详情，关闭详情保留步骤展开。没有独立记录时明确显示空态。处理通过显式`stepId`归属，不按名称或排列顺序猜测。此项当前仅为待验收原型，AROS实现与后端暂不修改。
10. 执行计划的折叠箭头按本产品约定显示：收起状态箭头向上，展开状态箭头向下；主线和支线任务保持一致。
11. 候选人审核底部使用全宽批量处理区。候选人勾选后只提供“加入岗位储备”：审核负责建立候选人与岗位的关系，未勾选即表示本轮不处理。联系候选人属于审核完成后的主线动作，不作为并列审核结果。
12. `Composer` 不显示浏览器原生缩放柄。文本框随输入内容自动增高，最小高度为 `54px`、最大高度为 `150px`；达到上限后内部滚动，清空或发送后自动恢复紧凑高度，发送按钮位置不能被缩放柄或文本覆盖。

## 四、复用边界

2026-09-08：`WorkHistory` 的任务类型统一为 13px、650 字重和 `--s1-accent-hover` 强调色，多类型允许换行；全局新建不单列周期任务。`SingleAssetTaskSummary` 与 `OpportunityWriteResult` 复用公共 Markdown 回复与输入框，单个资产入库/修改直接询问是/否/建议，不使用专用审核页，业务命令继续校验和防重复。完整边界见 `opportunity-lifecycle-prototype.md`。

1. 阶段三四类业务主线必须组合这些组件，不为每类主线重新创建对话、计划、任务和授权控件。
2. 业务专属结果可以新增 Renderer，但必须进入公共结果协议，并提供未知只读结果的安全降级。
3. 正式业务资产页面不能直接复用内部任务状态作为资产状态；两者只通过结果去向和来源引用关联。
