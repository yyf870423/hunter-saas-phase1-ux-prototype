# 原型阶段四：业务资产原型实施计划

> 状态：六批原型均已完成，专项和全量自动化验证通过，等待人类审批。
>
> 日期：2026-08-21。

## 一、阶段目标

阶段四完成公司、联系人、招聘机会、岗位、候选人、人才版图、论文和专利八类正式资产的完整管理原型，以及身份合并、字段变更、文件预览、来源证据、导入任务、导出和统一回收站等共用能力。

阶段四继续使用阶段一至阶段三已经审批的导航、设计 Token、公共组件、Markdown-first 对话和受控审核协议，不重新设计业务主线和支线任务。

## 二、原型分批顺序

阶段四按以下六批完成设计与实现，以控制模型和交互复杂度。由于本轮由用户明确要求一次性交付四阶段全部原型，六批在内部逐批完成文档核对、组件扩展、状态覆盖、响应式验证和自动化测试后，统一提交人类审批。

### 2.1 第一批：候选人与统一身份合并

页面范围：

1. 候选人列表。
2. 候选人详情六个 Tab。
3. 候选人新建与导入工作区。
4. 候选人身份合并审核。
5. 简历与普通文件预览。
6. 字段变更审核和来源证据详情。

选择候选人作为首批的原因：候选人字段最丰富，并同时覆盖表格、搜索筛选、列配置、复杂详情、文件、版本、来源、身份合并、时间线和跨资产关联。完成后可以验证大部分共用资产组件。

### 2.2 第二批：岗位、匹配与招聘推进

页面范围：

1. 岗位列表。
2. 岗位详情四个 Tab。
3. 岗位新建与岗位 Agent 工作区。
4. JD 版本、已确认要求和岗位分析。
5. 人岗匹配结果、过期状态与历史版本。
6. 候选人推进列表与泳道、岗位级阶段配置和相关文件。

本批重点验证岗位状态与任务门禁、岗位资料版本、匹配结果版本和候选人 × 岗位唯一推进关系。

### 2.3 第三批：公司、联系人和招聘机会

页面范围：

1. 三类资产列表与详情。
2. 公司手动、文件和 Agent 新建工作区。
3. 联系人宽 Modal 新建与编辑。
4. 招聘机会新建、编辑、方向拆分和岗位转换。
5. 公司名称识别、联系人多公司关系和联系人—候选人身份建议。

本批重点验证原始文本与稳定公司关联并存、跨业务身份和招聘机会到岗位的渐进转换。

### 2.4 第四批：人才版图

页面范围：

1. 人才版图卡片列表。
2. 详情六个 Tab。
3. 自然语言、文件、链接和手工新建工作区。
4. 目标清单、公司生态、组织结构、方向角色、人物关系和联系路径。
5. 增量变化、关系冲突、身份待确认和变更批次审核。

本批重点验证同一关系数据在多种图形和列表投影中的一致性，以及 Agent 后续探索所需的可解释关系结构。

### 2.5 第五批：论文与专利

页面范围：

1. 论文和专利单列卡片列表。
2. 两类连续详情页。
3. 文件、条件检索结果和 Agent 结果导入工作区。
4. 成果重复合并与作者或发明人身份审核。
5. 与人物、人才版图和来源证据的关联。

本批重点验证大量结果浏览、稳定标识优先查重、退化查重和人物关联门槛。

### 2.6 第六批：统一数据管理与全量关系 Review

页面范围：

1. 统一回收站。
2. 数据导入任务。
3. 数据导出任务与下载记录。
4. 跨资产搜索与反向关系入口。
5. 所有资产的 loading、empty、error、disabled、permission-limited、重复、冲突、过期和删除状态。

本批完成八类资产与已审批业务主线、支线任务、信号和工作台的端到端交叉 Review。

## 三、每批固定实施步骤

1. 对照业务资产模型、字段字典、当前 Hunter 真实页面和已审批信息架构，生成本批页面与状态清单。
2. 先扩展产品级组件库，再创建薄页面和 Mock 数据；不得在业务页面临时发明控件。
3. Mock 数据必须跨页面一致，例如候选人、岗位、公司、匹配、推进和主线中的对象名称、数量和状态互相对应。
4. 完成桌面、iPad 和 iPhone 的完整可操作路径。
5. 覆盖正常、加载、空、错误、禁用、权限受限和该资产专用异常状态。
6. 运行格式、构建和 Playwright；按审批原型要求完成截图检查。
7. 更新交互覆盖清单，标明每个操作的入口、正常路径、异常路径和状态。
8. 记录本批 Review 结论；六批全部收敛后统一提交人类审批。未通过时只调整对应批次和必要公共组件。

## 四、公共组件预期扩展

阶段四已新增或扩展以下产品级组件，并统一沉淀在 `src/stage4/asset-ui.jsx` 和 `src/stage4/stage4.css`：

2. 资产详情头部、全局统一的 `AppTabs`、资料分组、关系摘要和相关工作入口。
3. 宽 Modal、独立新建工作区、文件上传、解析进度和导入结果。
4. 联系方式编辑、经历编辑、标签编辑、公司关系选择和公开链接识别。
5. 身份合并审核、字段变化对比、关系确认、证据详情和批量审核。
6. JD 版本、匹配结果、招聘推进泳道和阶段配置。
7. 关系图、组织树、目标清单、变化批次和关系冲突。
8. 文件预览、回收站恢复、删除影响摘要、异步导入与导出任务。

## 五、阶段四完成门禁

1. 八类正式资产的列表、详情、新建、编辑、删除、恢复、搜索、筛选和关联操作全部可用。
2. 候选人、公司、论文和专利的身份或重复处理均有可解释结果，不存在静默跳过。
3. 原始文本、正式关系、过程状态、Agent 建议和正式资产没有混用。
4. 业务主线中的资产结果与资产页面使用同一核心字段和业务命令。
5. 文件、来源、证据和变更记录在不同资产中使用同一公共结构。
6. 表格优先在可读列宽下避免页面级横向滚动；候选人等字段较多的业务表格允许表格内部横向滚动，并固定关键首列与操作末列；列配置、分页和返回上下文均可操作。
7. 所有页面在桌面、iPad 和 iPhone 覆盖正常与异常状态，没有原生默认控件、文字溢出、遮挡或不可达操作。
8. 每个批次通过人类审批；全量关系与交互覆盖 Review 收敛后，阶段四才可以冻结。
