# Hunter 首页文案策略

## 目标

让中国独立猎头和资深顾问在数秒内感到：Hunter 理解难岗位真正卡人的地方——人散在不同渠道、人物身份难合并、结果缺依据；产品先把可核验的候选池整理出来，再把联系和正式推荐交回猎头。

## 已确认的产品依据

本轮于 2026-08-26 使用飞书产品目录索引与搜索结果，定位并读取了阶段一产品计划、产品概要，以及目录中 00—13 的业务主线、支线、资产规则、候选人、岗位与推进、公司与联系人、人才版图、论文专利人物身份、工作台、公开首页与账号认证、设置和运营端详细设计。由此锁定：

1. 阶段一首要用户是独立猎头，不先讲团队管理或企业 HR。
2. 岗位招聘目标是从内部候选人、人才版图、公开网络、论文、专利、开源项目与用户主动上传的简历中尽可能找到合适候选人。
3. 不同来源的人物必须先统一身份、查重、补全和保留证据，再经过岗位硬门槛与加权条件匹配。
4. 只有姓名的结果是人物线索，不包装成正式候选人；未知项明确写成未知。
5. Hunter 不自动操作需要登录的人才平台，也不与外部简历摘取工具通信；用户主动上传的简历统一进入去重、合并、审核和匹配流程。
6. 匹配不等于正式推荐；联系、正式推荐、面试确认和承诺类动作由猎头决定。

飞书文件夹原生枚举受应用后台缺少 `space:document:retrieve` / `drive:drive:readonly` 权限限制，因此通过目录文档与文档搜索定位并读取 00—12 全套设计；这一限制不影响上述首页核心定位的证据闭环。

## 首要顾虑

1. **“这会不会又是一个只能生成一轮名单的 AI？”**  
   首屏直接承诺围绕岗位持续找人，机制展示多渠道召回、身份合并、去重补证和候选池审核。
2. **“搜到的人到底是不是同一个人，为什么适合？”**  
   真实寻访区持续展示来源、已核验事实、风险和未知项，不把姓名或模型推断包装成结论。
3. **“系统不懂关系、温度和联系时机。”**  
   人机边界明确：系统做到候选池，联系、推荐、时机与口径由猎头掌控。

## 核心表达

- 首屏标题：给我一个难岗位，把该找的人找出来。
- 产品角色：吃透岗位，跨渠道找人，统一身份、查重、补证和匹配。
- 猎头角色：决定谁进入岗位储备、何时联系、是否正式推荐以及用什么口径。
- 转化动作：拿一个正在卡住的岗位来演示。

## 语言原则

- 使用猎头熟悉的对象：岗位要求、目标公司、人才版图、内部候选人、公开履历、论文、专利、开源项目、岗位储备、联系时机和推荐口径。
- 用“你”尊重专业判断，不教育猎头怎样经营关系，也不暗示系统比猎头更懂候选人温度。
- 先说找人的具体难处，再说产品动作；避免“赋能、提效、智能化、颠覆”等泛化词。
- 不虚构客户、指标、自动外联、已接入数据源或真实销售接入。
- “演示数据”持续可见；未知信息明确写成未知，人物身份没有证据时只称线索。

## 术语表

- 多路召回：围绕岗位同时从内部资产、人才版图、公开与学术来源及用户上传简历中找人。
- 统一成池：统一人物身份、查重、补全、保留来源，再按岗位条件匹配。
- 候选池：已经过基础身份和证据门禁、等待猎头审核的人选集合；不等于正式推荐。
- 等你筛人：系统停止自动推进，由猎头决定储备、补证、联系、推荐或暂停。
