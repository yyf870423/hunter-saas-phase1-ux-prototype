# 岗位面试资料原型决策记录

## 一、已确认边界

1. 岗位详情增加“面试资料”，用于持续积累该岗位历次沟通和面试信息，并整理可提供给后续候选人的面试指南。
2. 页面只保留“沟通记录”和“面试指南”，不增加“待收录建议”这一层中间状态。
3. 沟通记录可以由猎头手动补充，也可以引用候选人推进记录中的已确认事实；记录保留来源，避免同一事实形成两份无法追溯的内容。
4. 用户发起整理后，Hunter 直接生成并保存最新面试指南，不再要求二次审核；此前版本全部保留，可查看和下载。
5. 面试指南属于岗位资产上的 AI 处理结果，不创建独立任务，也不自动对候选人发送。

## 二、原型信息结构

岗位详情增加一级 Tab“面试资料”，包含两个二级视图：

1. **沟通记录**：搜索、筛选、查看和手动新增面试相关信息，支持把过时记录标记为失效。
2. **面试指南**：查看当前版本、AI 整理过程和全部历史版本。

经验记录的最小输入包括记录内容；面试轮次、关联候选人、获知时间和附件均为可选信息。内部记录可以保留来源候选人用于追溯，但候选人版指南必须排除其他候选人的姓名、联系方式、薪资、内部评价和客户保密信息。

## 三、关键交互

1. 用户可以从岗位面试资料中手动新增文字、链接和文件记录，并通过面试轮次、有效状态进行筛选。
2. 用户用自然语言说明整理要求后启动资产 AI；AI 只读取仍然有效的沟通记录。
3. AI 运行时保留当前指南可用；完成后直接生成最新版本，不显示“等待审核”或“确认更新”。
4. 当前指南支持在线查看、复制文案和下载；历史版本只读，不覆盖或删除现有版本。
5. 候选人版指南必须排除其他候选人的姓名、联系方式、薪资、内部评价和客户保密信息；不确定内容按不确定事实表达。

## 四、原型入口

- 沟通记录：`#/positions/position-vla?tab=interview`
- 面试指南：`#/positions/position-vla?tab=interview&section=guide`
