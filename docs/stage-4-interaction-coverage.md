## 一、覆盖原则

1. 八类正式资产共用导航、搜索筛选、列表或卡片、详情头部、Tab、Modal、Toast、文件、来源、审核和回收站组件。
2. 页面展示的公司、联系人、岗位、候选人、招聘机会、版图、论文和专利使用同一组 Mock 身份，跨页面名称、数量和关系保持一致。
3. 反向关系只读同一事实来源；编辑从事实所有者入口完成，不在公司或版图页面创建第二份补丁数据。
4. Agent 建议、任务状态、推进阶段和正式资产状态分别展示，不混写为同一种状态。
5. 所有输入路径必须反馈新建、补充、无变化、待确认或失败，不允许静默跳过。
6. 表格与卡片中的同组标签统一保留 `8px` 横向间距和 `6px` 换行间距，并按容器宽度显示；超过约定数量后统一在同一行显示 `+N`，悬停或键盘聚焦后通过产品自定义 Tooltip 查看隐藏标签。卡片描述最多显示三行，超出后截断并通过同款 Tooltip 查看完整内容。只有实际截断文本和 `+N` 可以触发 Tooltip，其他文字、普通标签、图标和按钮均不显示 Tooltip，也不使用浏览器原生提示样式。
7. Select、多选、行业级联、收藏夹和列设置统一使用视口级浮层，根据可用空间向上或向下展开，不受表格、Modal 和卡片的 `overflow` 裁切。
8. 列表分类、资产详情、审核视图和关系视图统一使用产品级 `AppTabs`；整行以底边界承载内容导航，选中项同时使用强调文字、字重、底部色条和计数徽标表达，不做设置控件式的外框分段按钮。
9. 出生年份、发生时间、预计时间、论文年份筛选和经历起止时间统一使用产品级 `DatePicker`。单个时间与时间区间都只有一个外部触发框，区间在同一浮层中完成选择；不使用原生日期输入框或把开始、结束拆成两个并列下拉框。
10. 论文与专利详情共用紧凑人物名单。论文默认显示前 5 位作者，每位作者直接显示论文署名机构；更多作者在可滚动浮层中继续查看。身份审核以单个人物为单位，点击谁只处理谁，Modal 不加载同一成果的全部人物；系统只给出一位疑似候选人，并按联系方式、工作经历、教育经历、项目与研究经历分别对照来源人物和候选人资料。多条经历使用档案记录而非 Markdown 表格，缺失信息需要明确显示；两侧数量不同时独立排列并显示各自数量，多出的记录标注为来源未发现或候选人补充，不能通过空白占位制造错误的一一对应。三个处理按钮点击后直接保存，不使用候选人下拉框、Radio 或二次确认。原始论文链接使用新 Tab 打开，不占用当前资产详情页。
